## 题目

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k`、`j != k`，且 `nums[i] + nums[j] + nums[k] == 0`。返回所有**和为 0 且不重复**的三元组。

```
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
```

注意 `[-1,0,1]` 和 `[0,1,-1]` 算同一个解，只保留一次。

## 思路：固定一个，退化成两数之和

三数之和 = 枚举 `nums[i]` + 在 `i` 右侧找两个数使其和为 `-nums[i]`。右侧那部分就是"两数之和 II"，用对撞指针 O(n) 解决，所以整体 O(n²)。

**先排序**是前提，它同时提供了两样东西：对撞指针需要的单调性，以及让相同元素相邻、便于去重。

遍历 `i` 作为第一个数，`left = i + 1`、`right = n - 1`：

- 三数之和等于 0 → 收集答案
- 小于 0 → `left++`（需要更大的数）
- 大于 0 → `right--`

## 三处去重，缺一不可

这是本题真正的考点：

1. **`i` 层去重**：`i > 0 && nums[i] === nums[i-1]` 时跳过。因为同一个值作为第一个数，能凑出的后续组合完全一样，会产生重复解。
2. **找到答案后 `left` 去重**：`[-1, -1, -1, 0, 1, 1]` 这类输入里，命中一次后 `left` 继续右移可能还是相同值，必须跳过。
3. **找到答案后 `right` 去重**：同上，对称处理。

```
nums = [-4,-1,-1,0,1,2]  （已排序）

i=0 (-4): left=1,right=5 → -4-1+2=-3<0 逐步推进，无解
i=1 (-1): left=2,right=5 → -1-1+2=0 ✓ 收集 [-1,-1,2]
          left 跳过重复的 -1 → left=3(0), right 跳过重复的 2 → right=4(1)
          left=3,right=4 → -1+0+1=0 ✓ 收集 [-1,0,1]
i=2 (-1): 与 nums[1] 相同 → 跳过（第 1 处去重）
```

还有一个可选剪枝：`nums[i] > 0` 时直接 `break`——数组已排序，第一个数都大于 0 了，后面两个数更大，三数之和不可能回到 0。

## 代码

```ts
function threeSum(nums: number[]): number[][] {
	const result: number[][] = [];
	const arr = [...nums].sort((a, b) => a - b);

	for (let i = 0; i < arr.length - 2; i++) {
		// 去重 1：同一个值作为第一个数只处理一次
		if (i > 0 && arr[i] === arr[i - 1]) continue;
		// 剪枝：最小的数都大于 0，三数之和不可能为 0
		if (arr[i] > 0) break;

		let left = i + 1;
		let right = arr.length - 1;

		while (left < right) {
			const sum = arr[i] + arr[left] + arr[right];

			if (sum === 0) {
				result.push([arr[i], arr[left], arr[right]]);
				// 去重 2 & 3：跳过左右两侧的重复值
				while (left < right && arr[left] === arr[left + 1]) left++;
				while (left < right && arr[right] === arr[right - 1]) right--;
				left++;
				right--;
			} else if (sum < 0) {
				left++;
			} else {
				right--;
			}
		}
	}

	return result;
}
```

两个容易写错的地方：

- `sort((a, b) => a - b)` 是必须的。JS 默认的 `sort()` 按字符串比较，`[10, 9, 2]` 会排成 `[10, 2, 9]`，结果全错。
- 找到答案后**两侧都要移动**，只动一边会死循环或者漏解。

## 复杂度

- 时间 **O(n²)**：外层 O(n)，内层对撞 O(n)；排序 O(n log n) 被覆盖
- 空间 **O(log n) ~ O(n)**：排序的栈空间；`[...nums]` 复制了一份，若允许修改入参可以省掉

## 复盘

三数之和是"中等题"里性价比最高的一道：它把排序、双指针、去重、剪枝四件事压在一道题里，几乎覆盖了数组类题目的全部基本功。

我建议的练习方式是**不要背代码，而是默写三处去重的理由**。能说清"为什么 `i` 层要跟 `i-1` 比而不是 `i+1`"、"为什么命中后必须两边都跳"，这道题才算真的会了。第 18 题「四数之和」是它的直接扩展（多套一层循环 + 多加一处去重），按这个理解去写会很顺。

另外提醒一句：`[...nums].sort(...)` 这个复制是有意的。LeetCode 不在乎你改不改入参，但业务代码里直接 sort 调用方传进来的数组，是个非常隐蔽的 bug 源——我见过线上因为某个工具函数内部 sort 了共享数组，导致另一个模块的渲染顺序莫名其妙变了。
