## 题目

给你两个按 **非递减顺序** 排列的整数数组 `nums1` 和 `nums2`，另有整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 中的元素数目。

请你 **原地** 合并 `nums2` 到 `nums1` 中，使合并后的数组同样按非递减排列。注意 `nums1` 的初始长度为 `m + n`，其中后 `n` 个元素为 0，仅作为占位。

```
输入：nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3
输出：[1,2,2,3,5,6]
```

## 思路：把对撞指针倒过来用

直觉上会想"从前往后，取两者较小的写进 nums1"，但这条路走不通——`nums1` 的前面正是你还没读的数据，一写就**覆盖掉了尚未处理的元素**。要么开一个新数组（空间 O(m+n)，不符合原地要求），要么换个方向。

**从后往前填**就没有这个问题：`nums1` 尾部那 n 个 0 是纯占位空间，写进去不会破坏任何待处理数据。于是用三个指针：

- `p1 = m - 1`：`nums1` 有效部分的末尾
- `p2 = n - 1`：`nums2` 的末尾
- `p = m + n - 1`：写入位置（从最后一位开始）

每次取 `nums1[p1]` 和 `nums2[p2]` 中**较大**的写到 `p`（因为是从大到小填），对应指针左移。

```
nums1 = [1,2,3,_,_,_], nums2 = [2,5,6]

p1=2(3), p2=2(6): 6 大 → nums1[5]=6, p2=1, p=4
p1=2(3), p2=1(5): 5 大 → nums1[4]=5, p2=0, p=3
p1=2(3), p2=0(2): 3 大 → nums1[3]=3, p1=1, p=2
结果 [1,2,2,3,5,6]
```

## 代码

```ts
function merge(nums1: number[], m: number, nums2: number[], n: number): void {
	let p1 = m - 1;
	let p2 = n - 1;
	let p = m + n - 1;

	while (p1 >= 0 && p2 >= 0) {
		if (nums1[p1] > nums2[p2]) {
			nums1[p] = nums1[p1];
			p1--;
		} else {
			nums1[p] = nums2[p2];
			p2--;
		}
		p--;
	}

	// nums2 有剩余才需要补；nums1 有剩余不用动，它们本来就在正确位置
	while (p2 >= 0) {
		nums1[p] = nums2[p2];
		p2--;
		p--;
	}
}
```

最后那个 `while` 是很多人漏掉的地方，但反过来想：**`nums1` 剩下的不用处理**（它们已经在自己该在的位置），只有 `nums2` 剩下了才需要继续搬。

## 复杂度

- 时间 **O(m + n)**：每个元素被读写一次
- 空间 **O(1)**：原地完成

## 复盘

这道题的价值在于它教你一个更普适的动作：**当"从前往后"会破坏输入时，先问一句"从后往前行不行"**。

原地算法里有一类问题专门靠这个技巧破：数组尾部有空闲空间、或者从后往前处理不影响已计算的结果。除了本题，第 844 题「比较含退格的字符串」用栈是 O(n) 空间，改成从后往前双指针就是 O(1)——同一招换个战场。

另外注意签名返回 `void`：LeetCode 的合并类题目改的是传入数组本身。在真实工程里我更倾向返回一个新数组而不是原地修改参数，副作用可控性比省那点内存重要得多；这道题按题目要求写原地即可，但别把这种写法带进业务代码。
