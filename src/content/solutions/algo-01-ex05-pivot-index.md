## 题目

给你一个整数数组 `nums`，请计算数组的 **中心下标**。中心下标是数组的一个下标，其左侧所有元素相加的和等于右侧所有元素相加的和。如果中心下标位于数组最左端，那么左侧数之和视为 0；不存在则返回 -1。如果有多个中心下标，返回**最靠左**的那个。

```
输入：nums = [1,7,3,6,5,6]
输出：3
解释：左侧 1+7+3 = 11，右侧 5+6 = 11
```

## 思路：右侧和不需要真的算

暴力写法对每个下标都左右各扫一遍求和，是 O(n²)。

优化的关键观察是：**右侧和 = 总和 - 左侧和 - 当前元素**。既然如此，只要先 O(n) 求出 `total`，再从左到右边走边累加 `leftSum`，每一步都能用 O(1) 算出右侧和：

```
total   = 1 + 7 + 3 + 6 + 5 + 6 = 28

i=0: leftSum=0, right=28-0-1  =27 ≠ 0   → leftSum=1
i=1: leftSum=1, right=28-1-7  =20 ≠ 1   → leftSum=8
i=2: leftSum=8, right=28-8-3  =17 ≠ 8   → leftSum=11
i=3: leftSum=11, right=28-11-6=11 = 11 ✓ → 返回 3
```

因为是从左往右第一个满足的就返回，天然满足"返回最靠左的"。

## 代码

```ts
function pivotIndex(nums: number[]): number {
	const total = nums.reduce((sum, n) => sum + n, 0);
	let leftSum = 0;

	for (let i = 0; i < nums.length; i++) {
		if (leftSum === total - leftSum - nums[i]) {
			return i;
		}
		leftSum += nums[i];
	}

	return -1;
}
```

## 复杂度

- 时间 **O(n)**：求和一趟 + 扫描一趟
- 空间 **O(1)**：只有两个累加变量

## 复盘

有意思的地方在于：这道题**属于前缀和家族，但最优解不需要开前缀和数组**。

标准前缀和套路是先建一个 `pre[i]` 数组，于是"区间和"可以 O(1) 查询——但那是为**多次查询**准备的。这题每个位置只查一次，边走边累加就够了，开数组纯属浪费。

所以判断要不要上完整前缀和，看的是查询次数：

- 查询 O(n) 次以上，且区间不连续 → 前缀和数组（第 303 题「区域和检索」）
- 只扫一遍、区间有规律滑动 → 滚动变量（本题、第 53 题「最大子数组和」）

顺带说个工程细节：`reduce` 写起来漂亮，但它在超大数组上比 `for` 循环慢一截（函数调用开销），我在处理几十万条数据的导出功能时实测过，差了大约 3 倍。算法题里无所谓，业务里数据量上来了记得换回 `for`。
