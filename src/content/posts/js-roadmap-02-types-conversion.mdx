## 七个原始类型 + 一个对象

```js
// 原始类型（值语义，不可变）
string, number, boolean, null, undefined, symbol, bigint

// 引用类型
object（含数组、函数、Date、Map…）
```

关键差别：**原始类型赋值是复制值，对象赋值是复制引用**。

```js
let a = { n: 1 };
const b = a;
b.n = 2;
console.log(a.n);   // 2 —— 同一个对象
```

## `typeof` 的四个坑

```js
typeof undefined      // "undefined"  ✅
typeof null           // "object"     ❌ 历史遗留 bug（32 位时代类型标记）
typeof []             // "object"     ❌ 数组识别不了
typeof function(){}   // "function"   ✅（唯一能区分函数的）
typeof NaN            // "number"     ❌ NaN 也是 number
typeof 1n             // "bigint"
```

正确的判断方式：

```js
Array.isArray([]);                 // 判数组
x === null;                        // 判 null（只能用 ===）
Number.isNaN(x);                   // 判 NaN（别用全局 isNaN，它会先转数字）
```

`isNaN('abc')` 返回 `true`（因为先 `Number('abc')` → NaN），`Number.isNaN('abc')` 返回 `false`（不转换）。**线上判断数字一定要用后者。**

## `==` 的转换规则：记住三条就够

`==` 在类型不同时会转换，规则可以压缩成三条：

1. **`null == undefined` 为 `true`，且它们不等于任何其它值**；
2. **数字与字符串比较 → 字符串转数字**；
3. **布尔值先转数字**（`true → 1`，`false → 0`），再回到第 1/2 条；
4. 对象与原始值比较 → 对象走 `ToPrimitive`。

```js
null == undefined        // true
null == 0                // false ← 反直觉，但很有用
'' == 0                  // true
'0' == false             // true
[] == false              // true  （[] → '' → 0）
[] == ![]                // true  （右边 ![] 是 false → 0；左边 [] → '' → 0）
({}) == '[object Object]' // true
```

这张表不是为了背，而是为了**知道哪里会出事**：

| 场景 | 风险 | 建议 |
| --- | --- | --- |
| 表单值比较 | `'0' == false` 为 true | 统一转数字后比较 |
| 接口字段判空 | `0 == ''` 为 true | 用 `===` 或显式判 `null/undefined` |
| 数组/对象比较 | 触发 `ToPrimitive` | 别用 `==` 比对象 |

**唯一推荐的 `==` 用法**：`x == null` 同时判 `null` 和 `undefined`（这是社区共识，ESLint 也允许 `eqeqeq` 的 null 例外）。

## `+` 是加还是拼？看有没有字符串

```js
1 + 2            // 3
1 + '2'          // '12'
'1' + 2          // '12'
1 + 2 + '3'      // '33'  ← 先算 1+2=3，再拼
'1' + 2 + 3      // '123'
[] + {}          // '[object Object]'
```

规则：**只要有一边是字符串（或能被转成字符串的对象），就拼接**。其它算术运算符（`- * /`）只会做数字转换：

```js
'6' - 1     // 5
'6' * '2'   // 12
'6' + 1     // '61' ← 只有 + 有拼接歧义
```

真实事故：求和时把 `reduce` 的初始值写成 `''` 而不是 `0`，结果得到 `"0123456789"`。

## `ToPrimitive`：对象怎么变成原始值

对象参与比较/运算时，会按顺序尝试：

1. `Symbol.toPrimitive`（如果有）
2. `valueOf()`
3. `toString()`

```js
const obj = {
  valueOf() { return 42; },
  toString() { return 'obj'; },
};
obj + 1;        // 43  ← valueOf 先
`${obj}`;       // 'obj' ← 字符串上下文优先 toString
```

这个机制能解释很多"诡异"：

```js
[1, 2, 3].map(parseInt);
// → [1, NaN, NaN]
```

原因：`map` 传三个参数 `(value, index, array)`，而 `parseInt(value, radix)` 的第二个参数是**进制**。所以实际调用是 `parseInt(1, 0)`、`parseInt(2, 1)`、`parseInt(3, 2)`——radix 为 1 和 2 时非法/无法表示，返回 NaN。

修法：`[1,2,3].map((v) => parseInt(v, 10))` 或 `map(Number)`。

## `Object.is` 与 `===`

```js
NaN === NaN          // false
Object.is(NaN, NaN)  // true

+0 === -0            // true
Object.is(+0, -0)    // false
```

`Object.is` 只在这两种边界上不同。React 的依赖比较用的就是 `Object.is`——**这就是为什么 `NaN` 作为依赖不会导致重复执行，而 `-0`/`+0` 会被视为不同**。

## 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| `typeof null` 是 object | 历史 bug | 用 `x === null` |
| `isNaN('abc')` 为 true | 全局 isNaN 先转数字 | 用 `Number.isNaN` |
| 求和得到字符串 | 初始值是 `''` 或有一边是字符串 | 初始值给 `0`，显式 `Number()` |
| `'0' == false` 为 true | 布尔先转数字 | 用 `===` |
| 对象比较永远 false | 比的是引用 | 深比较或比关键字段 |
| `[1,2,3].map(parseInt)` 出 NaN | 第二个参数是 radix | 用箭头函数包装 |
