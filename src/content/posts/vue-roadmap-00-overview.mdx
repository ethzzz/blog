## 1. 五条「做到什么算过」的尺子

不是"看完了 19 篇"，而是能做到这五个动作。

| # | 验收动作 | 判定标准 | 对应章节 |
|---|---|---|---|
| 1 | 能解释一个值为什么"改了不更新" | 说出 Proxy / ref 拆包 / 解构丢响应式三条路径，并给出各自修法 | 01、04 |
| 2 | 能把一段模板预编译成它的大致产物 | 说清 patchFlag、动态 props 与提升分别解决什么 | 02 |
| 3 | 能设计一个别人不会用错的 composable | 返回值类型、参数 `MaybeRef`、清理责任三处都有明确约定 | 07、08 |
| 4 | 能给一个 3 万行 Vue 项目定分层与规范并落地 | 目录、组件三分类、组件库透传规则能写成文档并被 CI 拦住 | 14、15 |
| 5 | 线上白屏时 30 分钟内定位到根因 | 能说清这次是哪一个：错误边界、路由 chunk 404、还是 SSR 水合失败 | 16 |

## 2. 三层能力地图

| 层 | 目标 | 章节 | 判断你在这层的标志 | 做到什么算过 |
|---|---|---|---|---|
| **L1 会写** | 组件、模板、表单能独立交付需求 | 01–06 | 不再靠"玄学刷新"绕过响应式问题 | 能解释模板里每一个响应式断点在哪断的 |
| **L2 会设计** | 状态、通信、路由、数据层能提前避开三年后的坑 | 07–12 | composable 与 store 有明确边界，不互相偷渡 | 能给同事讲清"这个状态为什么放 store 而不是 props" |
| **L3 会上规模** | 性能、架构、质量、可运维形成机制 | 13–16 | 优化有数字，事故有复盘 | 一次真实首屏/交互优化能给出前后指标 |
| **毕业项目** | 把上面全部串起来 | 17 | 一个能演示、能讲清设计的后台 | 毕业篇 22 条验收清单全勾 |
| **扩展** | Vue 3.5+ 与跨端差异 | 18 | 能判断哪些新语法值得现在上 | 说清 Nuxt / uni-app 各自改了什么 |

## 4. 四类起点的读法

**A. 从 React 转过来（最常见）**
01 → 02 → 04 → 07 → 13 优先。这五章回答的都是"为什么 Vue 不用写 useMemo、什么时候又必须写"。
03/06 里 `defineProps` 的默认值语义、`v-model` 的双向约定是最容易写错的两处，别跳。

**B. 只会 Vue 2，要升 3**
01（Object.defineProperty → Proxy 到底解决了什么）、03（`.sync` → `defineModel`）、08（`beforeDestroy` 改名、`created` 消失）、
10（Vuex → Pinia 的模块拆分）、14（Options API 与 Composition API 混用的工程代价）。

**C. 带团队 / 做架构**
07（composable 的 API 设计就是团队契约）、09（跨层通信的边界）、14、15、16。
特别是 16：错误边界在 Vue 里靠 `onErrorCaptured` + 组件层级，位置和 React 的 class 组件写法完全不同，
线上能不能兜住白屏就看这章。

**D. 只在救火（卡顿、白屏、内存涨）**
13 性能 → 12 竞态与缓存 → 16 错误 → 01 响应式。先止血，再补认知。

## 5. 症状速查表

| 现象 | 先查哪一章 | 一句话原因 |
|---|---|---|
| 改了数据视图不动 | 01 | 解构了 `reactive` 对象 / 数组用了非响应式来源 / 直接替换了整个对象引用 |
| 输入框打字卡顿 | 13、05 | 大列表整表 diff；把 `shallowRef` 用成了 `ref` |
| watch 里请求被后到的旧响应覆盖 | 04、12 | 没清理上一次副作用，也没丢弃过期请求 |
| 页面切回来数据是旧的 | 08、12 | `keep-alive` 下 mounted 不再执行，要用 `onActivated` |
| 刷新后 404 / 白屏，控制台报 loading chunk failed | 16、11 | 部署后旧 chunk 文件被删，动态路由要捕获重试 |
| 生产包比开发环境还慢 | 13 | 组件里手写 `key`、`v-memo` 用错对象，或依赖了 dev-only 行为 |
| 二次封装的组件传属性全丢 | 14 | `inheritAttrs` 与 `v-bind="$attrs"` 的落点，slot 透传没加 `v-for` |
| store 解构后 getters 失效 | 10 | 必须 `storeToRefs`，actions 可以直接解构 |

## 6. 每章的固定结构

为了能让你反复复习，每章都按同一套骨架写：

1. **一句话本质**——先给结论，再展开。
2. **原理拆解**——配可运行的最小代码片段，标 Vue 版本要求。
3. **React 对照表**——同一个需求在两个栈里的写法差异（没有差异的也会写"无差异"，省得你怀疑自己）。
4. **翻车现场**——我在真实项目里踩过的，含症状 → 根因 → 修法。
5. **复习卡片**——3–6 张，背面只有一句话。
6. **练习 + 面试一句话**——练习能在本地 30 分钟内做完；面试一句话就是这一章的 senior 考点。

> 版本口径：主线按 **Vue 3.5** 写——`defineModel` 是 3.4 起稳定（3.3 属实验、需显式打开）、
> `onWatcherCleanup` / `useId` / `useTemplateRef` / 响应式 props 解构都在 **3.5**（props 解构 3.5 起默认开启），
> `toValue`、`defineSlots`、元组式 `defineEmits`、跨文件 `import type` 在 3.3。各章引用具体 API 时都带版本下限。
> 工程链路统一 Vite 5 + Pinia 2 + Vue Router 4 + Vitest 2。

## 小结

- 这条路线的定位是**体系层**：`interview-guide` 那篇 Vue 问答负责"被问到时怎么答"，这里负责"为什么会这样"。
- 五个验收动作比读完更重要，读完直接去勾毕业项目的 22 条清单。
- 与 React 路线互为对照，遇到"这玩意儿 React 怎么做"就回 [React 路线](/blog/posts/react-roadmap-00-overview/) 的对应章节，两边都有的通用机制不重复讲。
- L2（07–12）是这条路线的增值中心：L1 的资料遍地都是，L2 的"边界在哪、谁负责清理"才是面试和工作真正拉开差距的地方。

## 练习

1. 打开你手上任意一个 Vue 项目，按第 1 节的五条尺子逐条判定：哪几条现在就能过？把过不了的那条对应章节记为本周必读。
2. 在第 5 节症状速查表里，找出你**曾经遇到过但没搞明白**的一行——那就是你该跳读的位置。
3. 写下你项目里一个"说不清该放 props、store 还是 composable"的状态，带着它读 07 和 10，读完给团队一条书面约定。
