React 的教程从来不少，但绝大多数人卡在同一个地方：**能照着文档写出页面，遇到"为什么状态改了 UI 没变""为什么这个 effect 跑了两次""为什么列表一删除就串了"就完全没方向。**

原因不复杂——React 有一层自己的运行时（协调器），它和 DOM 不是一一对应的。你心里那套"我改了变量页面就该变"的直觉，在 React 这里是错位的。**这套路线只做一件事：把运行时的规则讲清楚，让每个"为什么"都能推出来，而不是背结论。**

## 先定「做到什么算过」

不看知识清单，看你能不能在真实工作里做出这些动作。五条都能做到，就是能独立写 React 应用的水平：

1. 拿到一个需求，**先画状态树**（哪些状态、谁持有、谁是派生值），再写组件——而不是边写边加 `useState`。
2. 遇到"UI 没更新"，能判断是**状态没变（同一个引用）**、**读到了旧闭包**、还是**组件根本没重渲染**，并直接定位到那一行。
3. 写 `useEffect` 之前能说出**它同步的是什么外部系统**；说不出就说明不该用 effect。
4. 说出某段代码"为什么不加 `memo`"——**性能优化必须有 Profiler 的数字**，没有数字就不加。
5. 能把一个列表页做成**URL 即状态**（刷新、分享、后退都不丢筛选和分页），且增删改后列表自动一致。

第 4 条最容易被忽略：面试和代码评审里，"我加了 memo 所以更快"和"我测了 Profiler，加 memo 省了 0 次渲染所以没加"是两个水平。

## 四类起点的读法

**A. 完全没写过 React**（会 JS，但没碰过 React）
从 01 顺读到 09，跳过 13–15，然后做毕业项目。**01–03 必读**——它们是后面所有"为什么"的地基，跳过就会在 05 的 effect 上卡死。06 的 `useMemo`/`useCallback` 第一遍可以只读不练。

**B. 会写但说不清为什么**（能写页面，遇到诡异 bug 只能靠试）
直接从 **03 渲染与协调**开始，然后 05、07、12。这三篇解决 80% 的"玄学"：为什么状态没更新、为什么 effect 依赖写不对、为什么重渲染失控。

**C. 带团队 / 做架构**
08（状态管理的边界）、09（数据层）、11（路由与 URL）、16（工程与坑）是重点。特别是 08，它讲的不是"选哪个库"，而是**服务端状态和客户端状态必须分开**——这一条决定了项目三年后还能不能维护。

**D. 只在救火**（线上白屏、卡顿、内存涨）
14 错误边界 → 12 性能 → 16 工程坑。先止血，再补认知。

## 版本基线

本路线以 **React 19 + TypeScript 5 + Vite** 为基线，同时标注与 18 的差异（主要是 `use`、Actions、`useOptimistic`、`ref` 作为普通 prop）。React 18 的项目照样能跑，只是少几个新 API——**遇到 `forwardRef` 的旧写法不要慌，它在新版本里已经不需要了**。

## 四个必须先破的误解

1. **"setState 之后 state 立刻变了"** —— 不会。同一次事件里的多次 `set` 是批处理的，`state` 是本次渲染的快照。这是 02、05 的核心。
2. **"组件函数每次渲染都重新执行，所以变量会重置"** —— 对，但 `useState` 的值不会（它存在 fiber 上，不在函数作用域里）。这是 05 的核心。
3. **"key 只是个 id，用 index 也行"** —— 列表增删排序时 index 会让 React 认错节点，导致输入框串值、动画错乱。这是 03 的核心。
4. **"useEffect 是生命周期"** —— 它是"把某个外部系统和当前 state 同步"，不是 `componentDidMount` 的替代品。想不清同步什么，就别写。这是 05、07 的核心。

## 怎么判断自己读完了

不是"看完了 17 篇"，而是：

- [ ] 能对着一段 50 行的组件，指出**每次渲染会重新创建哪些东西**、**哪些被 `useMemo` 缓存了**
- [ ] 能在不看文档的情况下写出一个正确的 `useDebouncedValue`，并解释为什么清理函数必须清 timer
- [ ] 能解释为什么 `useEffect(() => { fetchData() }, [])` 在 StrictMode 下会请求两次，以及生产环境为什么不
- [ ] 能说出你项目里**哪三个地方故意没加 `memo`**，理由是什么
- [ ] 能画出毕业项目的状态树：哪些是服务端状态、哪些是 UI 状态、哪些是 URL 状态

第 5 条是分水岭：**把状态按"归属"分类**，是初级和中级最明显的分界线。

准备好了就从 01 开始。如果只想先止血，直接跳 03 和 05。
