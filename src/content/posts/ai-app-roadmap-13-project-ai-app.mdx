五轮实战完成后，花一次演示的时间从用户视角串起全部能力。只有做过早期专题示例时，可以从第 1 章开始，将代码累加到第 5 章。 [开始搭建](/blog/posts/ai-app-workshop-01-chat/)

## 演示前准备

在练习目录运行 `node setup.mjs 5` 补齐源码，启动第 1 章配置的 MySQL。用开发库演示，或在重新配置 `DB_NAME` 后使用新建并授权的演示库。运行 `node --env-file=.env server.mjs 5`。打开两个独立浏览器窗口，分别用 `alice-local` 与 `bob-local` 进入工作台。准备一份脱敏的发布手册、一张截图和一段 WAV。

另开终端运行 `node --env-file=.env smoke.mjs 5`。预期有五条 PASS。评估请按第 5 章用独立的 `kb_workshop_eval` 库运行 `node evaluate.mjs`，以免演示文档干扰样本召回。

## 端到端验收

| 演示动作 | 验收证据 |
| --- | --- |
| Alice 新建聊天、发送长问题、停止，再刷新 | Network 中有增量输出，停止后服务保存部分文本和中断状态 |
| Alice 导入发布手册，先问「发布流程」再问「今日食堂菜单」 | 第一题引用可打开原文，第二题证据不足。Bob 用同一问题查询不到 Alice 的手册 |
| Alice 用 Agent 拟待办，点击确认两次，用 MCP 查询 | 确认前正式列表为空，重复确认仍只有一条，MCP 只暴露读取工具 |
| 上传截图和 WAV，检查结果后填回消息输入框 | 两种输入都能拿到文本，用户可编辑再发送，超限文件或类型不符时返回错误 |
| 跑评测、给回答反馈、消耗完临时额度 | 看到逐条结果和失败退出码，反馈可回读，请求 ID 能对应日志，额度耗尽后返回 429 |
| 从测试域名访问并重启服务 | HTTPS 下流式增量正常，会话和文档可恢复，备份可启动验证 |

## 真机质量与交付记录

1. 用合成数据，对照 mock 与真机报告。真机至少演示一次多轮流式、一个同义改写的知识库问题、读工具与写草案、图片和音频。记录分别用了哪个模型、失败输入以及大致耗时。
2. 用两套身份再复查会话、原文、待办和反馈。记录 401、404、413、415、429 和上游错误的复现方法。浏览器和服务端日志里都检查有没有意外回传密钥。
3. 交付启动命令、无密钥配置模板、评测结果和一份回滚记录。描述哪些场景在 mock 下已通过，哪些做过真实模型和反代验证。

## 毕业自测

- 调高召回阈值后，拒答准确率和引用命中率可能怎样变化？怎么用样本判断改动值不值得？
- 浏览器按停止后，哪一个信号传给模型？连接断在最后一个增量和完成标记之间时应显示什么？
- 模型返回「创建待办」时，谁决定执行用户身份？重发确认请求为何没有两条数据？
- 单日请求数和真实模型账单差在哪里？取消的一轮已经消耗的 token 从哪里查？
- 更换 Embedding 模型或部署版本时，哪些数据可直接沿用，哪些需要重新生成或迁移？
