## 做到什么算过

1. 能从零起一个 NestJS 项目，说清 `Module / Controller / Provider` 各自负责什么。
2. 用 Prisma 建表并跑迁移，能解释"为什么改 schema 要 `migrate` 而不是手动改库"。
3. DTO 校验失败时，返回**统一格式**的错误体，且前端能按字段定位问题。
4. 实现 JWT access token + httpOnly 刷新令牌，并解释"为什么 refresh token 不能放 localStorage"。
5. 日志里每次请求都能按 `requestId` 串起来（含耗时、状态码、用户）。
6. 能写两类测试：service 单测（不碰数据库）、e2e（真起服务，走 HTTP）。
7. 能把这个服务部署上线，并用 `curl` 逐条验收契约，最后被前端成功调用。

## 契约先行（先定接口，再写代码）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| GET | `/tasks` | `_page`、`_limit`、`status`、`q` | `{ items: Task[], total: number, hasNext: boolean }` |
| GET | `/tasks/:id` | — | `Task`，不存在 → 404 |
| POST | `/tasks` | `title/status/priority/assignee/desc` | 201 + 新建的 `Task` |
| PATCH | `/tasks/:id` | 上述字段的部分 | 200 + 更新后的 `Task` |
| DELETE | `/tasks/:id` | — | 204 |
| POST | `/auth/login` | `username/password` | `{ accessToken }` + `Set-Cookie: refresh_token` |
| POST | `/auth/refresh` | Cookie | 新的 `accessToken` |
| GET | `/health` | — | `{ status: "ok", db: "up" }` |

错误体统一为：

```json
{ "statusCode": 422, "message": "提交的数据不合法", "errors": { "title": ["标题不能为空"] }, "requestId": "..." }
```

```ts
import { Type } from "class-transformer";
import { IsIn, IsInt, IsOptional, IsString, Max, Min } from "class-validator";

export class QueryTaskDto {
	@IsOptional()
	@Type(() => Number)
	@IsInt()
	@Min(1)
	page: number = 1;

	@IsOptional()
	@Type(() => Number)
	@IsInt()
	@Min(1)
	@Max(100)
	limit: number = 5;

	@IsOptional()
	@IsIn(["all", "todo", "doing", "done"])
	status: "all" | "todo" | "doing" | "done" = "all";

	@IsOptional()
	@IsString()
	q?: string;
}
```

> `_page`/`_limit`（前端契约）与 `page`/`limit`（代码里更好写）之间做一次映射，写在一个 `@Transform` 或 controller 里都行——**但只在一处做**，别散落。

### 4. service：查询、软删、返回契约

```ts
// src/tasks/tasks.service.ts
import { Injectable, NotFoundException } from "@nestjs/common";
import { PrismaService } from "../prisma/prisma.service";
import { CreateTaskDto } from "./dto/create-task.dto";
import { QueryTaskDto } from "./dto/query-task.dto";
import { UpdateTaskDto } from "./dto/update-task.dto";

@Injectable()
export class TasksService {
	constructor(private readonly prisma: PrismaService) {}

	async list(query: QueryTaskDto) {
		const where = {
			deletedAt: null,
			...(query.status !== "all" ? { status: query.status } : {}),
			...(query.q ? { title: { contains: query.q } } : {}),
		};
		const skip = (query.page - 1) * query.limit;

		// 一次事务拿两样东西：当前页 + 总数，保证 total 与 items 对得上
		const [items, total] = await this.prisma.$transaction([
			this.prisma.task.findMany({
				where,
				skip,
				take: query.limit,
				orderBy: { createdAt: "desc" },
			}),
			this.prisma.task.count({ where }),
		]);

		return { items, total, hasNext: skip + items.length < total };
	}

	async findOne(id: string) {
		const task = await this.prisma.task.findFirst({ where: { id, deletedAt: null } });
		if (!task) throw new NotFoundException("任务不存在（可能已被删除）");
		return task;
	}

	create(dto: CreateTaskDto, createdBy: string) {
		return this.prisma.task.create({ data: { ...dto, createdBy } });
	}

	async update(id: string, dto: UpdateTaskDto) {
		await this.findOne(id); // 先确认存在，再更新：避免 update 静默返回 null
		return this.prisma.task.update({ where: { id }, data: dto });
	}

	async remove(id: string) {
		await this.findOne(id);
		await this.prisma.task.update({ where: { id }, data: { deletedAt: new Date() } });
	}
}
```

### 5. controller：只做协议转换，不写业务

```ts
// src/tasks/tasks.controller.ts
import { Body, Controller, Delete, Get, Param, Patch, Post, Query, UseGuards } from "@nestjs/common";
import { JwtGuard } from "../auth/jwt.guard";
import { CurrentUser } from "../auth/current-user.decorator";
import { TasksService } from "./tasks.service";
import { CreateTaskDto } from "./dto/create-task.dto";
import { UpdateTaskDto } from "./dto/update-task.dto";
import { QueryTaskDto } from "./dto/query-task.dto";

@UseGuards(JwtGuard)
@Controller("tasks")
export class TasksController {
	constructor(private readonly tasks: TasksService) {}

	@Get()
	list(@Query() query: QueryTaskDto) {
		return this.tasks.list(query);
	}

	@Get(":id")
	findOne(@Param("id") id: string) {
		return this.tasks.findOne(id);
	}

	@Post()
	create(@Body() dto: CreateTaskDto, @CurrentUser() user: { username: string }) {
		return this.tasks.create(dto, user.username);
	}

	@Patch(":id")
	update(@Param("id") id: string, @Body() dto: UpdateTaskDto) {
		return this.tasks.update(id, dto);
	}

	@Delete(":id")
	async remove(@Param("id") id: string) {
		await this.tasks.remove(id);
	}
}
```

### 6. 统一错误体（前端能按字段定位）

先把"校验错误"整理成字段结构——**在管道里做，不要在过滤器里解析字符串**：

```ts
// src/common/validation.ts
import { UnprocessableEntityException, type ValidationError } from "@nestjs/common";

function flatten(errors: ValidationError[], prefix = ""): Record<string, string[]> {
	const out: Record<string, string[]> = {};
	for (const err of errors) {
		const path = prefix ? `${prefix}.${err.property}` : err.property;
		const messages = Object.values(err.constraints ?? {});
		if (messages.length) out[path] = messages;
		if (err.children?.length) Object.assign(out, flatten(err.children, path));
	}
	return out;
}

/** ValidationPipe 的异常工厂：把字段错误整理成 { 字段: [提示] } */
export function validationExceptionFactory(errors: ValidationError[]) {
	return new UnprocessableEntityException({
		message: "提交的数据不合法",
		errors: flatten(errors),
	});
}
```

```ts
// src/common/filters/all-exceptions.filter.ts
import { ArgumentsHost, Catch, ExceptionFilter, HttpException, HttpStatus, Logger } from "@nestjs/common";
import type { Request, Response } from "express";

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
	private readonly logger = new Logger("Exception");

	catch(exception: unknown, host: ArgumentsHost) {
		const ctx = host.switchToHttp();
		const res = ctx.getResponse<Response>();
		const req = ctx.getRequest<Request & { requestId?: string }>();

		const status =
			exception instanceof HttpException ? exception.getStatus() : HttpStatus.INTERNAL_SERVER_ERROR;

		let message = "服务端出错了";
		let errors: Record<string, string[]> | undefined;

		if (exception instanceof HttpException) {
			const body = exception.getResponse();
			if (typeof body === "string") {
				message = body;
			} else if (body && typeof body === "object") {
				const b = body as { message?: string | string[]; errors?: Record<string, string[]> };
				message = Array.isArray(b.message) ? (b.message[0] ?? "请求不合法") : (b.message ?? exception.message);
				errors = b.errors;
			}
		} else {
			// 未知异常：源码细节只进日志，响应体里不外泄
			this.logger.error({ err: exception, requestId: req.requestId }, "unhandled exception");
		}

		res.status(status).json({ statusCode: status, message, errors, requestId: req.requestId });
	}
}
```

> 这块是"最容易写成一坨"的地方。原则：**管道负责把校验错误结构化，过滤器只负责翻译成 HTTP 响应**，两边都不做业务判断。

## 阶段 2：鉴权 + 日志 + 限流（能被真实前端调用的门槛）

### 1. JWT：access 短、refresh 放 httpOnly Cookie

```ts
// src/auth/auth.service.ts
import { Injectable, UnauthorizedException } from "@nestjs/common";
import { JwtService } from "@nestjs/jwt";
import { compare } from "bcrypt";
import { PrismaService } from "../prisma/prisma.service";

@Injectable()
export class AuthService {
	constructor(
		private readonly prisma: PrismaService,
		private readonly jwt: JwtService,
	) {}

	async validate(username: string, password: string) {
		const user = await this.prisma.user.findUnique({ where: { username } });
		// 用户不存在也走一次 compare，避免"响应时间差"暴露账号是否存在
		const ok = user ? await compare(password, user.passwordHash) : false;
		if (!user || !ok) throw new UnauthorizedException("用户名或密码错误");
		return user;
	}

	signAccess(user: { id: string; username: string; role: string }) {
		return this.jwt.sign(
			{ sub: user.id, username: user.username, role: user.role },
			{ secret: process.env.JWT_ACCESS_SECRET, expiresIn: "15m" },
		);
	}

	signRefresh(user: { id: string }) {
		return this.jwt.sign({ sub: user.id }, { secret: process.env.JWT_REFRESH_SECRET, expiresIn: "7d" });
	}
}
```

```ts
// src/auth/auth.controller.ts
import { Body, Controller, Post, Res } from "@nestjs/common";
import type { Response } from "express";
import { AuthService } from "./auth.service";
import { LoginDto } from "./dto/login.dto";
import { Public } from "./public.decorator";

@Controller("auth")
export class AuthController {
	constructor(private readonly auth: AuthService) {}

	@Public()
	@Post("login")
	async login(@Body() dto: LoginDto, @Res({ passthrough: true }) res: Response) {
		const user = await this.auth.validate(dto.username, dto.password);
		res.cookie("refresh_token", this.auth.signRefresh(user), {
			httpOnly: true, // JS 读不到 → XSS 偷不走
			sameSite: "lax",
			secure: process.env.NODE_ENV === "production",
			path: "/auth/refresh", // 只在刷新接口上带，减少暴露面
			maxAge: 7 * 24 * 3600 * 1000,
		});
		return { accessToken: this.auth.signAccess(user), user: { username: user.username, role: user.role } };
	}
}
```

Guard 的最小实现（生产可以换 `@nestjs/passport`，原理不变）：

```ts
// src/auth/jwt.guard.ts
import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from "@nestjs/common";
import { JwtService } from "@nestjs/jwt";
import { Reflector } from "@nestjs/core";
import { IS_PUBLIC_KEY } from "./public.decorator";

@Injectable()
export class JwtGuard implements CanActivate {
	constructor(
		private readonly jwt: JwtService,
		private readonly reflector: Reflector,
	) {}

	async canActivate(ctx: ExecutionContext) {
		const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
			ctx.getHandler(),
			ctx.getClass(),
		]);
		if (isPublic) return true;

		const req = ctx.switchToHttp().getRequest();
		const token = (req.headers.authorization ?? "").replace(/^Bearer /, "");
		if (!token) throw new UnauthorizedException("缺少登录凭证");
		try {
			req.user = await this.jwt.verifyAsync(token, { secret: process.env.JWT_ACCESS_SECRET });
			return true;
		} catch {
			throw new UnauthorizedException("登录已过期，请重新登录");
		}
	}
}
```

### 2. 日志：一条日志能串起一次请求

```ts
// src/main.ts（关键片段）
import { Logger } from "nestjs-pino";
import { randomUUID } from "node:crypto";

app.use((req, _res, next) => {

	next();

```

```ts
// app.module.ts 里的 pino 配置
LoggerModule.forRoot({
	pinoHttp: {
		genReqId: (req) => req.requestId ?? randomUUID(),
		customProps: (req, res) => ({ requestId: res.getHeader("x-request-id") }),
		redact: ["req.headers.authorization", "req.headers.cookie"],
```

**脱敏是硬要求**：`authorization`、`cookie` 必须 redact——日志泄 token 是真实事故。

## 阶段 3：定时清理 + 测试 + 上线（能交付才算毕业）

### 1. 定时清理（把 07 篇的调度用起来）

```ts
// src/tasks/tasks.tasks.ts
import { Injectable, Logger } from "@nestjs/common";
import { Cron, CronExpression } from "@nestjs/schedule";
import { PrismaService } from "../prisma/prisma.service";

@Injectable()
export class TasksTasks {
	private readonly logger = new Logger(TasksTasks.name);
	constructor(private readonly prisma: PrismaService) {}

	/** 每天 03:10 把"已完成且超过 30 天"的软删记录真正删掉 */
	@Cron("10 3 * * *")
	async purgeDone() {
		const cutoff = new Date(Date.now() - 30 * 24 * 3600 * 1000);
		const { count } = await this.prisma.task.deleteMany({
			where: { status: "done", updatedAt: { lt: cutoff } },
		});
		if (count > 0) this.logger.log(`purged ${count} finished tasks`);
	}
}
```

## 常见坑

1. **`@Query()` 里字符串没转数字**：`_page=2` 拿到的是 `"2"`，`(page-1)*limit` 变字符串拼接。用 `@Type(() => Number)` 或 `@Transform`。
2. **`findMany` + `count` 分两次查**：中间有人插入时 `total` 和 `items` 对不上。用 `$transaction`。
3. **物理删除**：误删无法恢复、审计无迹。默认软删，另配清理任务。
4. **refresh token 放 localStorage**：等于给 XSS 送长期凭证。httpOnly + `path` 限定到刷新接口。
5. **JWT 密钥写在代码里**：换密钥要改代码 + 重启；放环境变量，且 access/refresh 用**不同**密钥。
6. **日志打印整个 `req`**：`authorization`、`cookie`、密码字段全进日志。用 redact 白名单。
7. **`ValidationPipe` 没开 `whitelist`**：前端多传 `role: "admin"` 会被原样落到 `data`。
8. **SQLite 开多实例**：写锁冲突直接 500。要么单实例，要么换 MySQL/Postgres。
9. **e2e 连开发库**：跑一次测试把开发数据清空，是新人最常犯的事故。
10. **`migrate dev` 上生产**：会尝试重置。生产只用 `migrate deploy`。

## 毕业自测：10 题

1. `Module` / `Controller` / `Provider` 各解决什么问题？为什么 controller 里不该有 `prisma`？
2. 为什么 `update` 之前要先 `findOne`？（Prisma 更新不存在的 id 会抛 P2025，但错误体不友好，且软删记录会被"复活"）
3. `hasNext` 为什么不能用 `items.length === limit` 判断？（最后一页刚好满时误判；React 篇的 json-server 那样做是因为拿不到 total）
4. JWT 过期后前端该怎么做？`401 → refresh → 重放原请求` 这段逻辑放哪一层？（请求拦截器，不要每个页面写一遍）
5. `sameSite=lax` 与 `strict` 在这个场景下差在哪？（跨站直接打开链接时是否带 Cookie）
6. 日志里没有 `requestId` 会怎样？（并发时无法把报错与请求对上）
7. 单测和 e2e 各自"守"什么？（单测守逻辑分支，e2e 守协议与链路）
8. 为什么 `migrate deploy` 与 `migrate dev` 不能混用？
9. 软删后分页的 `total` 该怎么算？（必须带 `deletedAt: null` 条件，否则总数虚高）
10. 现在要给这个 API 加"批量删除 + 权限校验"，改哪几层？（DTO/controller、service 事务、guard 里的角色判断、e2e 补两条用例）
