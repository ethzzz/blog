## 条件类型的语法只有一句，行为有三层

```ts
type IsString<T> = T extends string ? true : false;
```

看起来像 `if`，但有三件事必须知道：**分发**、**联合的分配律**、**如何阻断分发**。

### 第一层：裸类型参数会分发

```ts
type ToArray<T> = T extends unknown ? T[] : never;

type R = ToArray<string | number>;   // string[] | number[]（不是 (string|number)[]）
```

因为 `T` 是"裸"的（直接出现在 `extends` 左边），TS 会把联合拆开逐个判断，再把结果**并起来**。

这个行为有时正是你要的：

```ts
type Exclude<T, U> = T extends U ? never : T;
type R = Exclude<'a' | 'b' | 'c', 'a'>;   // 'b' | 'c'  ← 靠分发删掉成员
```

### 第二层：怎么关掉分发

把类型包一层（通常是元组）：

```ts
type ToArrayNoDist<T> = [T] extends [unknown] ? T[] : never;
type R2 = ToArrayNoDist<string | number>;   // (string | number)[]
```

判断口诀：**裸参数 = 分发；包成 `[T]` = 不分发**。

### 第三层：`never` 的特殊行为

```ts
type Wrap<T> = T extends string ? T : never;
type R3 = Wrap<never>;      // never（不是 "never 不匹配"）
```

因为"分发空联合"得到空联合。这个坑常出现在：**给一个可能为 `never` 的类型做条件判断，结果整个类型消失了**。

## `infer`：在类型里做模式匹配

`infer` 声明一个"占位变量"，由编译器在匹配时填入。

### 1. 提取函数返回值 / 参数

```ts
type MyReturnType<F> = F extends (...args: any[]) => infer R ? R : never;
type MyParameters<F> = F extends (...args: infer P) => any ? P : never;

type F = (a: string, b: number) => boolean;
type R = MyReturnType<F>;    // boolean
type P = MyParameters<F>;    // [a: string, b: number]
```

### 2. 提取数组/元组元素

```ts
type ElementOf<T> = T extends readonly (infer E)[] ? E : never;
type E = ElementOf<string[]>;         // string

type First<T extends unknown[]> = T extends [infer H, ...unknown[]] ? H : never;
type F1 = First<[1, 2, 3]>;           // 1
```

### 3. 解包 Promise

```ts
type Unwrap<T> = T extends Promise<infer V> ? Unwrap<V> : T;
type U = Unwrap<Promise<Promise<number>>>;   // number（递归解到不是 Promise 为止）
```

### 4. 字符串解析（模板字面量 + infer）

```ts
type Split<S extends string, Sep extends string> =
  S extends `${infer Head}${Sep}${infer Tail}` ? [Head, ...Split<Tail, Sep>] : [S];

type Parts = Split<'a/b/c', '/'>;    // ['a', 'b', 'c']
```

### 5. 多个 `infer` 同时匹配

```ts
type ToFunc<T> = T extends (...args: infer A) => infer R ? { args: A; ret: R } : never;
```

## 递归类型：必须能终止

```ts
// ✅ 终止条件在"不是对象"时
type DeepReadonly<T> = T extends (infer U)[]
  ? ReadonlyArray<DeepReadonly<U>>
  : T extends object
    ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
    : T;

// ✅ 终止条件在"字符串耗尽"
type Paths<T> = T extends object
  ? {
      [K in keyof T & string]: T[K] extends object
        ? `${K}.${Paths<T[K]>}`
        : K;
    }[keyof T & string]
  : never;
```

**递归不终止的表现**：`tsc` 报 `Type instantiation is excessively deep and possibly infinite`，或编辑器直接卡死。加一层 `T extends any[] ? ... : ...` 的分支或加深度上限（`Depth extends number[]` 计数）能解决。

## 类型体操的边界

写类型的能力和可读性成反比。三条红线：

1. **超过 3 层嵌套条件类型** → 拆成命名中间类型，否则报错没人看得懂；
2. **需要写注释解释"这个类型在干什么"** → 说明它太聪明了，考虑用泛型 + 简单工具类型替代；
3. **只有你能维护** → 团队里没人敢改，等于给自己造了个只进不出的坑。

值得投入的类型体操只有两类：

- **库/框架作者**：SDK、ORM、路由、状态管理，类型就是 API；
- **业务里的高频模式**：表单字段推导、API 响应包装、路由参数提取（做过一次，全项目受益）。

其它场景，**清晰的具体类型 > 聪明的泛型**。

## 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| 条件类型结果"整个没了" | 分发遇到 `never` | 检查输入是否可能是 `never`，用 `[T] extends [U]` 阻断 |
| `infer` 拿到 `unknown` | 匹配位置太宽（`(...args: any[])` 已匹配） | 收紧匹配模式 |
| 递归报 excessively deep | 没有终止分支，或嵌套过深 | 加非对象分支；或限制深度 |
| 联合被拆开后结果不对 | 没意识到"裸参数分发" | 包成元组 `[T]` |
| 模板字面量 infer 结果带引号 | 字符串类型 vs 字面量 | 用 `extends string` 约束，必要时 `& string` |
| 编辑器卡死 | 复杂类型在超大联合上展开 | 给联合加 `as const` 收窄、或改运行时方案 |

## 练习

1. **验证分发与阻断**：写 `type A<T> = T extends string ? 1 : 0`，分别传 `'a' | 1` 与 `['a' | 1]` 版本，观察结果差异。  
   *自检*：能说出 `string | number` 分发后为什么得到 `1 | 0`。
2. **手写 `Awaited`**：实现 `Unwrap<T>` 解包任意层 `Promise`，并解释递归终止条件。  
   *自检*：`Unwrap<Promise<Promise<string>>>` 得到 `string`。
3. **写一个 `Paths` 类型**：把嵌套对象变成 `'a.b' | 'a.c'` 形式的联合，用于表单路径提示。  
   *自检*：能说清为什么只能用 `keyof T & string` 过滤掉 symbol/number 键。
