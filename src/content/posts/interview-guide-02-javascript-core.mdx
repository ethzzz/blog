## 数据类型

### Q1: JavaScript 有哪些数据类型？⭐ 🔥

**答：**

| 类型 | 分类 | 示例 |
|:--|:--|:--|
| `number` | 基本类型 | `1`, `3.14`, `NaN`, `Infinity` |
| `string` | 基本类型 | `'hello'`, `"world"` |
| `boolean` | 基本类型 | `true`, `false` |

| `symbol` | 基本类型 (ES6) | `Symbol('id')` |

```javascript
// 类型检测

// 准确检测
Object.prototype.toString.call(null)      // '[object Null]'

```

### Q2: null 和 undefined 的区别？⭐

**答：**

| 特性 | `null` | `undefined` |
|:--|:--|:--|
| 含义 | 空值，表示"没有对象" | 未定义，表示"缺少值" |

| 转换数字 | `0` | `NaN` |
| 使用场景 | 主动赋值 | 变量声明未赋值、函数无返回值 |

```javascript
null == undefined    // true（宽松相等）

Number(null)         // 0

// 实际使用
let obj = null;       // 明确表示空对象

```

### Q2b: 对象转原始值的规则是什么？`[] == ![]` 为什么是 true？⭐⭐ 🔥

**答：** 对象参与运算/比较前要先走 **ToPrimitive**，顺序是：

1. 有 `Symbol.toPrimitive` 就调它（hint 为 `'number'`/`'string'`/`'default'`）；
2. 否则 hint 是 `'string'` → 先 `toString()` 再 `valueOf()`；
3. 否则（number/default）→ **先 `valueOf()` 再 `toString()`**；
4. 两个都返回对象就抛 `TypeError`。

```javascript
const obj = {
  value: 3,
  valueOf() { return this.value; },
  toString() { return `v${this.value}`; },
};
obj + 1;        // 4      （default hint → valueOf）
`${obj}`;       // 'v3'   （string hint → toString）
Number(obj);    // 3
obj == '3';     // true   （== 比较时对象走 ToPrimitive，default hint）

// Symbol.toPrimitive 优先级最高
const money = {
  amount: 100,
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? `¥${this.amount}` : this.amount;
  },
};
`${money}`;  // '¥100'
money * 2;   // 200
```

**`==` 的比较规则（按优先级记四条就够）：**

1. **类型相同** → 等价于 `===`（`NaN` 除外，谁都不等）；
2. **`null == undefined`** → true，且它们俩**不等于任何其他值**（`null == 0` 是 false！）；
3. **对象 vs 原始值** → 对象先 ToPrimitive 再比；
4. **number vs string/boolean** → 都转成 number 再比（`'1' == true` → `1 == 1` → true）。

**经典题逐步拆解：**

```javascript
[] == ![]
// ① ![] → false（对象是 truthy）
// ② [] == false → 布尔转数字 → [] == 0
// ③ [] ToPrimitive：valueOf 返回自身（还是对象）→ toString() → ''
// ④ '' == 0 → 字符串转数字 → 0 == 0 → true

[] == false   // true（同上）
[] == 0       // true
[] == ''      // true（'' 转 0）
{} == '[object Object]' // true
```

**追问链：**

- **「工程里到底能不能用 `==`？」** 答：唯一被广泛接受的例外是 **`x == null`**（同时判 null 和 undefined，等价于 `x === null || x === undefined`）；其余一律 `===`。ESLint 的 `eqeqeq: ['error', 'always', { null: 'ignore' }]` 就是这个约定。
- **「`Object.is` 和 `===` 差在哪？」** 答：两处——`Object.is(NaN, NaN)` 为 true（`===` 为 false）；`Object.is(+0, -0)` 为 false（`===` 为 true）。React 的依赖比较、`useState` 判断状态是否变化用的就是 `Object.is` 语义。
- **「`{} + []` 和 `[] + {}` 为什么结果不同？」** 答：`[] + {}` 是加法：两边 ToPrimitive → `'' + '[object Object]'`。而语句开头的 `{} + []` 里 `{}` 被解析成**空代码块**，剩下 `+[]` 是一元正号 → `0`。这是语法解析题不是类型转换题，能指出这一层才算真懂。

### Q2c: 为什么 0.1 + 0.2 !== 0.3？金额计算怎么办？⭐⭐ 🔥

**答：** JS 的 number 是 **IEEE 754 双精度浮点**（64 位：1 符号 + 11 指数 + 52 尾数）。0.1 和 0.2 的二进制都是**无限循环小数**，存进 52 位尾数时被截断，两个近似值相加再舍入，得到 `0.30000000000000004`。

```javascript
0.1 + 0.2 === 0.3            // false
0.1 + 0.2                    // 0.30000000000000004

// 浮点比较：用误差容忍（epsilon）
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON  // true

// 安全整数：超过 2^53-1 的整数无法精确表示
Number.MAX_SAFE_INTEGER      // 9007199254740991
9007199254740992 === 9007199254740993  // true！精度已丢
Number.isSafeInteger(2 ** 53)          // false
```

**工程解法（按场景选）：**

| 场景 | 方案 |
|:--|:--|
| 金额 | **以「分」为单位用整数算**，展示时再除 100；或 decimal.js / big.js |
| 后端传的长 ID（订单号/雪花 ID） | 让后端**以字符串下发**，前端不 `JSON.parse` 成 number；或 `BigInt` |
| 大整数运算 | `BigInt`（`123n`），注意**不能和 number 混算**、`JSON.stringify` 会抛错 |
| 展示保留小数 | `toFixed` 是银行家舍入的近似实现（`(1.005).toFixed(2)` 是 `'1.00'`），精确舍入先乘成整数再处理 |

**追问：「BigInt 能直接 JSON 序列化吗？」** 答：不能，`JSON.stringify(1n)` 抛 `TypeError`。要么自定义 replacer 转字符串，要么用 `JSON.parse` 的 reviver 还原——这也是「长 ID 全链路用 string」成为大厂约定的原因之一。

### Q3: 深拷贝和浅拷贝的区别？如何实现深拷贝？⭐⭐ 🔥

**答：**

```javascript
// 浅拷贝：只复制第一层，引用类型仍共享
const obj = { a: 1, b: { c: 2 } };
const shallow = { ...obj };
// 或 Object.assign({}, obj)

shallow.b.c = 999;
console.log(obj.b.c); // 999，原对象也被修改

// 深拷贝：递归复制所有层级
const deep = JSON.parse(JSON.stringify(obj));
deep.b.c = 888;
console.log(obj.b.c); // 2，原对象不受影响
```

**深拷贝实现：**

```javascript
// 方法1：JSON（简单场景，有缺陷）
const copy1 = JSON.parse(JSON.stringify(obj));
// 缺陷：undefined/function/Symbol 会丢失，循环引用报错

// 方法2：递归实现
function deepClone(obj, map = new WeakMap()) {
  if (obj === null || typeof obj !== 'object') return obj;
  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj);
  
  // 处理循环引用
  if (map.has(obj)) return map.get(obj);
  
  const clone = Array.isArray(obj) ? [] : {};
  map.set(obj, clone);
  
  for (let key in obj) {
    if (obj.hasOwnProperty(key)) {
      clone[key] = deepClone(obj[key], map);
    }
  }
  return clone;
}

// 方法3：structuredClone（现代浏览器）
const copy3 = structuredClone(obj);
```

**追问链（这道题的分水岭在第 3 问）：**

- **「JSON 深拷贝到底丢什么？逐个说。」⭐⭐⭐**
  答：五类丢失/变形：① `undefined`、函数、`Symbol` 作为值被直接丢弃（作为对象属性时）；② `Date` 变成 ISO 字符串；③ `NaN` / `Infinity` 变成 `null`；④ `RegExp` 变成 `{}`；⑤ 循环引用直接抛错。另外还会丢原型（实例变普通对象）和不可枚举属性。所以 **JSON 深拷贝只在纯数据场景可用**（POJO + 基础类型），一旦对象带原型、Date、函数，就得换方案。
- **「`structuredClone` 能替代手写深拷贝吗？」**
  答：日常够用且更安全（原生实现、支持循环引用、支持 Date/Map/Set/RegExp/ArrayBuffer）。但它**不支持函数、Symbol、DOM 节点、class 实例的方法**，克隆 class 实例会丢原型变成普通对象。所以「配置数据/接口数据」用 structuredClone，「带行为/带原型的对象」还是得手写或走工厂函数重建。
- **「手写深拷贝里为什么用 WeakMap 而不是 Map 存循环引用？」**
  答：WeakMap 的 key 是弱引用，克隆完成后原对象若没有其他引用，可以被正常 GC；用 Map 会让所有被克隆过的对象**永久驻留**在 map 里，等于自己造了一个内存泄漏。这也是面试官判断「你是背代码还是真写过」的细节。
- **「深拷贝就一定要递归到底吗？」**
  答：不一定。实践中常用**按需深拷贝**：只对会变化的分支深拷贝（结构共享），其余复用引用。这也是 immer 这类库的思路——用 Proxy 记录改动，产出「看起来全新」的对象但共享未变部分，既满足不可变语义又不付出全量递归的代价。

## 作用域与闭包

### Q4: 什么是作用域？作用域链是什么？⭐⭐

**答：**

作用域是变量和函数的可访问范围，分为：
- **全局作用域**：在整个程序中可访问
- **函数作用域**：在函数内部可访问
- **块级作用域**（ES6）：`let/const` 在 `{}` 内

```javascript
// 作用域链：查找变量时逐级向上
var a = 'global';

function outer() {
  var b = 'outer';
  
  function inner() {
    var c = 'inner';
    console.log(a); // 'global'，沿作用域链找到全局
    console.log(b); // 'outer'
    console.log(c); // 'inner'
  }
  
  inner();
}

// 块级作用域
if (true) {
  let x = 1;
  var y = 2;
}
console.log(x); // ReferenceError
console.log(y); // 2（var 没有块级作用域）
```

### Q5: 什么是闭包？应用场景？⭐⭐ 🔥

**答：**

闭包是指函数能够访问其词法作用域中的变量，即使该函数在其词法作用域之外执行。

```javascript
// 闭包示例
function counter() {
  let count = 0; // 被闭包引用，不会被垃圾回收
  
  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount: () => count
  };
}

const c = counter();
c.increment(); // 1
c.increment(); // 2
c.getCount();  // 2
```

**应用场景：**

```javascript
// 1. 数据私有化
function createWallet(initial) {
  let balance = initial;
  
  return {
    deposit(amount) { balance += amount; },
    withdraw(amount) { balance -= amount; },
    getBalance() { return balance; }
  };
}

// 2. 函数柯里化
function multiply(a) {
  return function(b) {
    return a * b;
  };
}
const double = multiply(2);
double(5); // 10

// 3. 防抖节流
function debounce(fn, delay) {
  let timer = null; // 闭包保存定时器
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 4. 模块化（IIFE）
const module = (function() {
  let privateVar = 'private';
  
  return {
    getPrivate: () => privateVar
  };
})();
```

**闭包的问题：**
- 内存泄漏：闭包引用的变量不会被回收
- 解决：及时释放不需要的引用 `fn = null`

**追问链（闭包这题的高分点）：**

- **「『闭包导致内存泄漏』这句话对不对？」⭐⭐⭐**
  答：不严谨。闭包本身是正常且必要的机制，只有当「闭包的生命周期远长于所需数据」时才是问题——例如把大对象挂进一个永不移除的全局事件监听；或组件销毁后定时器仍在跑，里面的闭包持有整个组件作用域（连带 detached DOM）。**正确表述**：闭包会延长其捕获变量的存活时间，泄漏的判据是「本该回收的作用域被长期持有」。
- **「线上怎么确认是闭包泄漏？」**
  答：DevTools Memory 面板：① 拍两次堆快照（操作前/反复操作后），Comparison 视图看 `Detached HTMLElement` 与自定义类实例是否持续增长；② 用 Allocation instrumentation on timeline 定位持续分配的来源；③ 快照里展开 Retainers，往上追到「谁持有它」——通常能找到挂着闭包的事件监听/定时器。**能说出 Retainers 这一层，基本就是真排查过。**
- **「循环里的 `var` 为什么全部输出 3？」**
  答：`var i` 是函数作用域，三个 setTimeout 的回调共享**同一个 i**；循环结束时 i=3，回调执行时读到的自然是 3。改成 `let` 后，ES 规范为每次循环迭代**创建一个新的绑定**（相当于每轮都有独立的 i），所以输出 0/1/2。等价的老写法是 IIFE 包一层把 i 作为参数传进去。

### Q6: var、let、const 的区别？⭐ 🔥

**答：**

| 特性 | `var` | `let` | `const` |
|:--|:--|:--|:--|
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 变量提升 | 有（值为 undefined） | 有（暂时性死区） | 有（暂时性死区） |
| 重复声明 | 允许 | 不允许 | 不允许 |
| 重新赋值 | 允许 | 允许 | 不允许 |
| 全局声明 | 挂载到 window | 不挂载 | 不挂载 |

```javascript
// 变量提升
console.log(a); // undefined（var 提升）
var a = 1;

console.log(b); // ReferenceError（暂时性死区）
let b = 2;

// 经典面试题
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3 3 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 100);
}
// 输出：0 1 2（每次循环创建新的 j）

// const 注意
const obj = { a: 1 };
obj.a = 2;        // ✅ 允许，修改属性
obj = { b: 1 };   // ❌ 报错，不能重新赋值
```

## this 指向

### Q7: this 的指向规则？⭐⭐ 🔥

**答：**

| 调用方式 | this 指向 |
|:--|:--|
| `obj.fn()` | `obj` |
| `fn()` | `undefined`（严格模式）/ `window` |
| `new Fn()` | 新创建的实例 |
| `fn.call(obj)` | `obj` |
| `fn.apply(obj)` | `obj` |
| `fn.bind(obj)` | `obj` |
| 箭头函数 | 继承外层 this |

```javascript
// 1. 对象方法调用
const obj = {
  name: 'obj',
  fn() { console.log(this.name); }
};
obj.fn(); // 'obj'

// 2. 普通函数调用
function fn() { console.log(this); }
fn(); // window（非严格模式）

// 3. 构造函数
function Person(name) {
  this.name = name;
}
const p = new Person('Tom');
console.log(p.name); // 'Tom'

// 4. call/apply/bind
const ctx = { name: 'ctx' };
fn.call(ctx);    // this = ctx
fn.apply(ctx);   // this = ctx
const bound = fn.bind(ctx);
bound();         // this = ctx

// 5. 箭头函数
const arrow = {
  name: 'arrow',
  fn: () => console.log(this.name), // 外层 this（window）
  fn2() {
    return () => console.log(this.name); // 外层 this（arrow）
  }
};
arrow.fn();      // undefined
arrow.fn2()();   // 'arrow'

// 经典面试题
const person = {
  name: 'person',
  sayName: function() {
    console.log(this.name);
  }
};

const fn1 = person.sayName;
fn1(); // undefined（this 丢失）

const fn2 = person.sayName.bind(person);
fn2(); // 'person'
```

**追问链：**

- **「`bind` 之后的函数还能被 `new` 吗？this 还是绑定的那个吗？」⭐⭐⭐ 高频冷门题**
  答：能 `new`，但 **`new` 的优先级高于 bind**——`new boundFn()` 时 this 指向新实例，绑定的 this 被忽略。规范里叫「BoundFunctionCreate + [[Construct]]」：构造调用时会用绑定函数保存的 target 去构造，this 由 new 决定。推论：`bind` 只能保证「普通调用」时的 this，不能阻止被当构造函数用。
- **「箭头函数为什么不能当构造函数？」**
  答：箭头函数没有 `[[Construct]]` 内部方法、没有 `prototype` 属性、也没有自己的 `this`（词法继承）。`new (() => {})` 直接抛 `TypeError: not a constructor`。这正是它在回调场景好用的原因——不会意外改变 this，也不会被 new 出实例。
- **「`obj.fn()` 里的 this 是什么时候确定的？」**
  答：**调用时**，不是定义时。所以「把方法赋给变量再调用」会丢 this（`const f = obj.fn; f()` → undefined/global）。这也是 React 类组件时代 `this.handleClick = this.handleClick.bind(this)` 存在的原因。

### Q7b: new 一个对象时发生了什么？手写一个 new？⭐⭐ 🔥

**答：** 四步（顺序不能乱）：

1. 创建一个空对象，把它的 `[[Prototype]]` 指向构造函数的 `prototype`；
2. 以这个对象为 `this` 执行构造函数（传入参数）；
3. 如果构造函数**显式返回了一个对象**，就用那个对象；
4. 否则返回第 1 步创建的对象。

```javascript
function myNew(Constructor, ...args) {
  // 1. 创建对象并接上原型链
  const obj = Object.create(Constructor.prototype);
  // 2. 绑定 this 执行构造函数
  const result = Constructor.apply(obj, args);
  // 3/4. 构造函数返回对象则用之，否则用新对象
  //    注意：返回原始值（含 null）会被忽略
  return result !== null && (typeof result === 'object' || typeof result === 'function')
    ? result
    : obj;
}

function Person(name) { this.name = name; }
Person.prototype.sayHi = function () { console.log(this.name); };
myNew(Person, 'Tom').sayHi(); // 'Tom'
```

**追问链：**

- **「构造函数返回 `null` 会怎样？」** 答：被忽略，仍返回新实例——`typeof null === 'object'` 是陷阱，所以手写时必须显式排除 null。返回 `1`/`'x'` 同样被忽略，只有返回**对象/函数**才生效。
- **「`Object.create(null)` 创建的对象有什么特别？」** 答：没有原型，`toString`/`hasOwnProperty` 都没有，`instanceof Object` 为 false。适合做**纯字典**（不用担心 `__proto__`、`constructor` 这类键名污染），Vue 的依赖收集容器、很多库的内部 map 都用它。
- **「new 和 Object.create 的关系？」** 答：`Object.create(proto)` 只做第 1 步（建对象 + 接原型），不执行构造函数。寄生组合继承用它替代 `new Parent()`，就是为了**只接原型、不执行父类构造**（避免把父类实例属性挂到子类原型上）。

## 原型与继承

### Q8: 什么是原型链？⭐⭐ 🔥

**答：**

每个对象都有一个 `__proto__` 属性指向其构造函数的 `prototype`，形成链式结构。

```javascript
// 原型链图示
// 实例 --> 构造函数.prototype --> Object.prototype --> null

function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function() {
  console.log('Hi, ' + this.name);
};

const p = new Person('Tom');

p.__proto__ === Person.prototype;           // true
Person.prototype.__proto__ === Object.prototype; // true
Object.prototype.__proto__ === null;        // true

// 属性查找顺序
p.name;       // 自身属性
p.sayHi();    // 原型上的方法
p.toString(); // Object.prototype 上的方法
```

**关键概念：**

```javascript
// prototype：构造函数的原型对象
Person.prototype; // { sayHi: f, constructor: Person }

// __proto__：实例的原型引用（非标准但广泛支持）
p.__proto__; // 同 Person.prototype

// constructor：原型对象指向构造函数的引用
Person.prototype.constructor === Person; // true

// Object.getPrototypeOf（标准方法）
Object.getPrototypeOf(p) === Person.prototype; // true
```

### Q9: JavaScript 继承的几种方式？⭐⭐⭐

**答：**

```javascript
// 1. 原型链继承（缺陷：引用类型共享）
function Parent() {
  this.hobbies = ['reading'];
}
function Child() {}
Child.prototype = new Parent();

// 2. 构造函数继承（缺陷：无法继承原型方法）
function Parent(name) {
  this.name = name;
}
function Child(name) {
  Parent.call(this, name);
}

// 3. 组合继承（常用）
function Parent(name) {
  this.name = name;
}
Parent.prototype.sayName = function() {
  console.log(this.name);
};
function Child(name, age) {
  Parent.call(this, name); // 继承实例属性
  this.age = age;
}
Child.prototype = new Parent(); // 继承原型方法
Child.prototype.constructor = Child;

// 4. 寄生组合继承（最佳方案）
function inheritPrototype(Child, Parent) {
  const prototype = Object.create(Parent.prototype);
  prototype.constructor = Child;
  Child.prototype = prototype;
}
function Child(name, age) {
  Parent.call(this, name);
  this.age = age;
}
inheritPrototype(Child, Parent);

// 5. ES6 Class（推荐）
class Parent {
  constructor(name) {
    this.name = name;
  }
  sayName() {
    console.log(this.name);
  }
}
class Child extends Parent {
  constructor(name, age) {
    super(name); // 必须先调用 super
    this.age = age;
  }
}
```

**追问链：**

- **「为什么 `super()` 之前访问 `this` 会报错？」⭐⭐⭐**
  答：ES6 的类实例创建分两步：派生类的 `this` **由父类构造函数创建**，在 `super()` 返回之前，绑定还不存在（处于 TDZ）。所以 `this.x = 1` 写在 `super()` 之前会抛 `ReferenceError: Must call super constructor before accessing 'this'`。这是与 ES5 组合继承最本质的差异——ES5 里 `Parent.call(this)` 时 this 已经存在。
- **「ES6 class 和寄生组合继承是两套东西吗？」**
  答：不是，class 就是寄生组合继承的语法糖，但多了三条硬约束：① 类只能用 `new` 调用（直接 `Parent()` 抛错）；② 原型方法**不可枚举**（`for...in` 拿不到，ES5 手写会拿到）；③ 类声明不会变量提升（同样有 TDZ）。理解这三条，才不会被「class 是不是新机制」这类问题绕住。

### Q10: instanceof 的原理？如何实现？⭐⭐

**答：**

```javascript
// instanceof 检测构造函数的 prototype 是否出现在对象的原型链上
[] instanceof Array;    // true
[] instanceof Object;   // true（原型链上）

// 手动实现
function myInstanceof(obj, Constructor) {
  let proto = Object.getPrototypeOf(obj);
  const prototype = Constructor.prototype;
  
  while (proto !== null) {
    if (proto === prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }
  return false;
}

myInstanceof([], Array);  // true
myInstanceof([], Object); // true
myInstanceof({}, Array);  // false
```

### Q11b: 迭代器协议是什么？generator 怎么实现惰性序列？⭐⭐⭐

**答：** `for...of`、展开运算符、解构、`Array.from` 背后都是同一套协议：**对象上有 `[Symbol.iterator]()` 方法，返回一个带 `next()` 的对象，`next()` 返回 `{ value, done }`**。

```javascript
// 让普通对象可 for...of
const range = {
  from: 1, to: 5,
  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;
    return {
      next() {
        return current <= last
          ? { value: current++, done: false }
          : { value: undefined, done: true };
      },
    };
  },
};
[...range]; // [1, 2, 3, 4, 5]

// generator 是迭代器的语法糖：yield 一次 = next() 一次
function* fib() {
  let [a, b] = [0, 1];
  while (true) { yield a; [a, b] = [b, a + b]; }
}
const it = fib();
it.next().value; // 0
it.next().value; // 1
it.next().value; // 1 —— 无限序列，但只在要的时候算（惰性）
```

**追问链：**

- **「`for...of` 和 `for...in` 的本质区别？」** 答：`for...in` 遍历**可枚举字符串键**（含原型链上的，所以要用 `hasOwnProperty` 过滤或干脆别用）；`for...of` 走**迭代器协议**，遍历的是值。普通对象没有 `[Symbol.iterator]`，`for...of` 直接抛错——「对象能不能 for...of」取决于有没有实现协议，不是取决于它是不是对象。
- **「generator 和 async/await 什么关系？」** 答：async/await 本质是 **generator + 自动执行器**的语法糖：`yield` 一个 Promise，执行器在 then 里调 `next(value)` 把结果送回去。co 库就是这个执行器的手写版。能讲出这层，「async 原理」这类题就通了。
- **「迭代器有什么用武之地？」** 答：① 惰性/无限序列（分页拉取、斐波那契、读大文件流）；② 自定义数据结构的遍历语义（树的中序遍历写成 generator，调用方 `for...of` 即可）；③ `yield*` 委托实现生成器组合。异步迭代器（`[Symbol.asyncIterator]` + `for await...of`）是同一套协议的 Promise 版，Node 流和分页 API 消费都靠它。

### Q12: Map 和 Object 的区别？⭐⭐

**答：**

| 特性 | `Map` | `Object` |
|:--|:--|:--|
| 键类型 | 任意值 | 字符串/Symbol |
| 键顺序 | 插入顺序 | 不保证 |
| 大小 | `size` 属性 | 需手动计算 |
| 迭代 | 可迭代 | 需 `Object.keys()` |
| 性能 | 频繁增删更优 | 少量数据更优 |

```javascript
// Map 操作
const map = new Map();
map.set('key', 'value');
map.set(1, 'number key');
map.set({}, 'object key'); // 对象作为键

map.get('key');      // 'value'
map.has('key');      // true
map.delete('key');   // true
map.size;            // 2

// 遍历
map.forEach((v, k) => console.log(k, v));
for (const [k, v] of map) { }

// 转换
const arr = [...map];           // Map -> Array
const obj = Object.fromEntries(map); // Map -> Object
const map2 = new Map(Object.entries(obj)); // Object -> Map
```

### Q12b: WeakMap/WeakSet 和 Map/Set 的区别？什么场景必须用弱引用？⭐⭐

**答：** 核心差异一句话：**WeakMap 的 key（WeakSet 的成员）是弱引用——不阻止 GC，因此不可遍历、没有 size**。

| | Map / Set | WeakMap / WeakSet |
|:--|:--|:--|
| key 类型 | 任意值 | 只能是对象（WeakSet 成员同理） |
| 引用强度 | 强引用，key 活着 map 就活着 | 弱引用，对象无其他引用时可被回收 |
| 遍历/size | 支持 | **不支持**（回收时机不确定，遍历结果不可预测） |
| 典型用途 | 通用字典/去重 | 「给对象挂元数据，但不想延长它的寿命」 |

```javascript
// 场景一：DOM 节点元数据（节点移除后自动可回收）
const meta = new WeakMap();
meta.set(domNode, { clickCount: 0 });
// 用 Map 的话：节点从 DOM 移除后仍被 meta 持有 → detached DOM 泄漏

// 场景二：以对象为 key 的缓存（深拷贝的循环引用记录同款）
const cache = new WeakMap();
function heavyCompute(config) {
  if (cache.has(config)) return cache.get(config);
  const result = doExpensiveWork(config);
  cache.set(config, result);
  return result;
}
// config 被丢弃后，对应缓存自动失效，不用手动清理

// 场景三：类的私有字段（class #field 之前的经典方案）
const _private = new WeakMap();
class Wallet {
  constructor(balance) { _private.set(this, { balance }); }
  getBalance() { return _private.get(this).balance; }
}
```

**追问：「为什么 WeakMap 不可遍历？」** 答：如果允许遍历，遍历结果就会依赖 GC 时机——同一份代码两次运行可能拿到不同的键集合，语义不可预测。规范干脆禁止暴露内容，只留 `get/set/has/delete` 四个点操作。**「弱引用 + 可遍历」在语义上是矛盾的**，这句是本题的题眼。

### Q13: Proxy 和 Object.defineProperty 的区别？⭐⭐⭐ 🔥

**答：**

| 特性 | `Object.defineProperty` | `Proxy` |
|:--|:--|:--|
| 监听粒度 | 单个属性 | 整个对象 |
| 数组支持 | 需重写方法 | 原生支持 |
| 新增属性 | 无法监听 | 可以监听 |
| 删除属性 | 无法监听 | 可以监听 |
| 性能 | 初始化递归 | 惰性代理 |

```javascript
// Object.defineProperty（Vue 2）
function defineReactive(obj, key, val) {
  Object.defineProperty(obj, key, {
    get() { return val; },
    set(newVal) { val = newVal; }
  });
}
// 缺陷：无法监听 obj.newKey = value

// Proxy（Vue 3）
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    track(target, key); // 依赖收集
    return Reflect.get(target, key, receiver);
  },
  set(target, key, value, receiver) {
    trigger(target, key); // 触发更新
    return Reflect.set(target, key, value, receiver);
  },
  deleteProperty(target, key) {
    trigger(target, key);
    return Reflect.deleteProperty(target, key);
  }
});
// 优势：可以监听所有操作
```

**追问链（Proxy 题的深度全在这三问）：**

- **「为什么 handler 里一定要用 `Reflect`？直接 `target[key]` 不行吗？」⭐⭐⭐**
  答：两个前提：① `Reflect.get(target, key, receiver)` 会把 **receiver（即 proxy 自身）作为 getter 的 this** 传下去，如果对象里有 getter 且内部访问其他属性，才能继续走 proxy 的拦截；直接 `target[key]` 会让 getter 里的 this 指向原始对象，**丢掉后续拦截**（嵌套属性不再响应式，Vue 3 早期一堆 bug 就源于此）。② `Reflect.set` 会返回布尔值，能忠实反映「赋值是否成功」（比如目标属性是 `writable: false` 时），而普通赋值在严格模式下抛错，行为不一致。
- **「Proxy 有什么代价？」**
  答：① 每次属性访问多一层函数调用，热点路径上开销可观（Vue 3 因此对 `shallowRef`、`markRaw` 做了逃生口）；② 代理后的对象与原对象 `!==`，把 proxy 传给第三方库（尤其做 `instanceof` / identity 判断的库）可能出错；③ 某些内建对象（Map/Set/Date）需要额外绑定，直接代理会导致内部槽失效。
- **「能撤销代理吗？」**
  答：能，`new Proxy(target, { ... })` 配 `Proxy.revocable(target, handler)`，拿到 `{ proxy, revoke }`，调用 `revoke()` 之后所有操作抛 `TypeError`。典型用途是组件卸载后立刻让旧引用失效，防止异步回调继续写状态。

## 常见坑速查表

| 现象 | 根因 | 解法 |
|:--|:--|:--|
| JSON 深拷贝后日期变字符串、`NaN` 变 null | JSON 只支持有限类型 | 换 `structuredClone`，或手写递归 |
| 深拷贝带循环引用的对象直接抛错 | `JSON.stringify` 无法处理环 | 手写递归 + WeakMap 缓存 |
| 深拷贝后实例方法丢了 | 克隆只复制属性不复制原型 | 用工厂函数重建实例，或 `Object.create(proto)` 后拷属性 |
| 方法传给回调后 this 变 undefined | this 是调用时确定的 | `bind`、箭头函数，或在调用处 `obj.fn()` |
| `new` 之后 this 不是 bind 的对象 | new 优先级高于 bind | 这是规范行为；需要固定 this 就别让它被构造 |
| `super()` 之前访问 this 报错 | 派生类 this 由父类构造创建（TDZ） | 先 `super()`，再做任何 this 操作 |
| for 循环里 setTimeout 全输出同一个值 | `var` 共享同一绑定 | 改 `let` 或 IIFE 传参 |
| Proxy 代理后嵌套属性不响应 | handler 里用了 `target[key]` 丢 receiver | 一律走 `Reflect.get/set(target, key, receiver)` |
| 判空用 `if (obj)` 放过了 `0`/`''` | 隐式类型转换 | 显式 `obj != null`，或 `??` 兜默认值 |
| `null == 0` 期望 true 实际 false | null 只与 undefined 宽松相等 | 记特例：`x == null` 只判空，别参与数值比较 |
| 金额相加出现 0.30000000000000004 | IEEE 754 浮点截断 | 以分为单位整数运算 / decimal.js |
| 后端长 ID 到前端末位变 0 | 超过 2^53-1 精度丢失 | 全链路字符串传输，或 BigInt |
| 手写 new 后返回了 null | `typeof null === 'object'` 误判 | 显式排除 null 再判对象/函数 |
| `for...in` 遍历出原型上的属性 | 枚举含继承的可枚举键 | 换 `Object.keys` / `for...of` + entries |
| 对象做 Map key 后内存只涨不降 | 强引用持有已废弃对象 | 元数据/缓存场景换 WeakMap |

## 深水区追问（2026 补充）

**Q：执行上下文里「变量环境」和「词法环境」为什么要分开？`let` 的暂时性死区是怎么实现的？**

规范里一个执行上下文有两套环境记录：`var` 声明与函数声明进**变量环境**，`let` / `const` / `class` 进**词法环境**（块级作用域的每一层是一个独立词法环境，用 outer 指针串成作用域链）。暂时性死区不是「变量不存在」，而是**绑定已创建、状态却是 uninitialized**：进入块时名字就登记进词法环境，直到声明语句执行才置为已初始化，此间任何读取都抛 `ReferenceError`——所以 `typeof x` 也会抛（与真正未声明的变量不同，后者返回 `'undefined'`）。`for (let i ...)` 能每次迭代拿到新绑定，靠的正是「每轮迭代复制一份词法环境」的规范约定，不是运行时魔法。

**Q：属性描述符里哪些开关一旦设下就回不去？`Object.freeze` 冻的是多深？**

`configurable: false` 是**单向门**：不能改回 true，也不能把数据属性改成访问器属性，只能在 `writable` 仍为 true 时改 `value`、或把 `writable` 从 true 改成 false。`writable: false` 同理不可逆。三个实用推论：① 一旦用 `defineProperty` 装了 getter/setter，就没有 `value` 可读了，想同时保留得自己维护闭包变量；② `enumerable: false` 的属性会从 `Object.keys`、展开运算符、`JSON.stringify`、`for...in` 里全部消失，但 `in` 与直接访问仍拿得到——这是「拷贝完少字段」的隐藏原因；③ `Object.freeze` 只冻结**自有属性**，嵌套对象照样能改，深冻结要递归（Vue 的 `readonly` 也是浅层，内层在访问时才递归包装）。

**Q：`WeakRef` / `FinalizationRegistry` 能干什么？为什么不能拿它当缓存？**

`WeakRef.deref()` 返回目标或 `undefined`，适合做「有就用、没有就算了」的大对象旁路（例如已解析的图片位图、编译后的模板）。不能当 LRU 用的原因是**回收时机完全由引擎决定**：内存充裕时可能一直不回收，内存紧张时刚 `deref()` 出来的引用下次访问就可能变 `undefined`；`FinalizationRegistry` 的回调更**不保证执行**，不能在里面做关键清理。可控缓存靠显式淘汰策略（大小/时间上限），`WeakRef` 只能用来「省内存」，不能用来「保证命中」。

**Q：事件委托的边界在哪？哪些事件根本委托不了？**

四类边界：① **不冒泡**的事件——`focus` / `blur`（要么用捕获阶段，要么改用 `focusin` / `focusout`）、`mouseenter` / `mouseleave`、`load` / `error`（img 的 error 不冒泡，只能在捕获阶段接）；② **被中断**——子树里任何一处 `stopPropagation()` 都会让委托层收不到，第三方组件内部调了你就会失灵；③ **Shadow DOM**——跨宿主边界时事件会 retarget，`event.target` 已被改写，要用 `composedPath()` 找真实节点；④ **成本反转**——每次点击都要在深树祖先上跑 `closest()` / `matches()`，列表项少而层级深时直接绑反而更快。另外委托挂到 `document` 时，Portal 到 body 之外的弹层、iframe 内部的点击都收不到。
