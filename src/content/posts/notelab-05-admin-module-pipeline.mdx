## 知识地图

```text
新增模块 xxx（例：spire 爬塔 / loot 摸金 / dev_notes 项目实践）
│
├── ① Java · XxxController          单键读写 + 白名单 + 懒 seed（+ publish）
├── ② Java · MenuTree + PageRoutes  双登记，必须一一对应
└── ③ B 端 · lib/xxx.ts + page.tsx  表单与提交，脏标记走整份比对
        │
        └─（仅 C 端消费的内容）→ 发布快照 xxx_published + 匿名只读接口

顺序不能换：Java 菜单没上，B 端页面做得再好也进不去。
```

## 一、先做一个判断：这个模块要不要「发布」

这一步决定后面要不要做快照，做错了要返工，所以放在最前面。

| 形态 | 例子 | 要不要 publish | 理由 |
|---|---|---|---|
| C 端会消费的内容 | 爬塔配置、摸金玩法 | ✅ 要 | 编辑到一半就上线，前台直接呈现半成品 |
| 纯后台知识/工具 | 项目实践汇总 | ❌ 不要 | 只有自己在后台看，编辑即生效 |

判断只有一条：**这段数据会不会被未登录的访客看到**。会，就走发布态；不会，就别给自己加戏。

## 二、Java 侧：一个 Controller，三个动作

不建表，仍然写进 `ui_config` 的单键（理由见第二篇）。整包读写，三个动作：

```java
// 读：某切片为空时回内置默认常量，不主动写库（懒 seed）
@GetMapping("/api/xxx")
public Resp<JsonNode> get(HttpServletRequest request) {
    if (AuthUtil.user(request) == null) return AuthUtil.unauth();
    return Resp.ok(xxxService.of(UiConfigService.getConfig()));
}

// 写：手工白名单逐字段 put，整包覆盖
@PostMapping("/api/xxx")
public Resp<Void> save(@RequestBody JsonNode body, HttpServletRequest request) {
    if (AuthUtil.user(request) == null) return AuthUtil.unauth();
    xxxService.putWhitelisted(UiConfigService.getConfig(), body); // 只认列表里的键
    UiConfigService.invalidate();
    return Resp.ok();
}
```

三个必须记住的细节：

1. **懒 seed 不写库**：读到空切片就返回代码里的 `BASE_*` 常量。好处是改默认值不需要迁移脚本；代价是"库里有值时改代码常量不生效"——想在线上拿到最新默认值，就把该切片写成空值让后端回落（这是我后来才想到的省事手法）。
2. **净化只管结构与体积，不管语义**：条数、单条字符上限（`MAX_XXX_CHARS`）、必填字段。一条不合法就丢那一条，**不要让整包 400**，否则用户改一个字段失败，整份配置回不来。
3. **白名单有两处**，这是本模块最贵的坑（下面第五节展开）。

C 端消费还要加 `publish` / `unpublish`（把当前值复制进 `xxx_published`），并在 C 端配置控制器里加一个**匿名可读**的快照接口。

## 三、菜单与路由：双登记必须一一对应

```java
// MenuTree.java —— 顶层分组用 g_ 前缀，「游戏配置」下的子分组才用 gc_
g_practice → 叶子 { path: "/dev-summary", name: "项目实践" }

// PageRoutes.java —— 一一对应追加
new String[]{"/dev-summary", "项目实践"}
```

两种漏法的症状完全不同，都能把人骗到怀疑人生：

- **只加菜单不加路由** → 叶子被 RBAC 过滤掉，**谁都看不见这个入口**，包括超管。表现为"我明明加了菜单"。
- **只加路由不加菜单** → 路由能直达，但后台没有入口，用户永远找不到。

还有两个约定容易写错：菜单的 `path` **不含** `/admin` 前缀（basePath 由前端框架自己拼）；`g_` 与 `gc_` 用错前缀会造成断言的**假阴性**——你以为没生效，其实是被挂到了别的分组下。

启动时后端会 upsert `page:<path>`，但**非超管角色要再去「角色组管理」重新勾选**，否则新页面对老角色不可见。这条每次都会被忘。

## 四、B 端：lib + 页面，脏标记别手写

```ts
// src/lib/xxx-content.ts
export const loadXxx = () => apiJson<XxxDoc>("/api/xxx");
export const saveXxx = (doc: XxxDoc) =>
    postJson("/api/xxx", stripReadOnly(doc));   // baseBalance 这类只读字段提交前剔除
```

两条我自己踩出来的规矩：

- **脏标记走「整份文档序列化后与基线比对」**，不要每个 setter 手动置位。手写置位迟早漏一个字段，漏的那个字段就是"我改了但没提示我保存"。
- **保存 = 全量提交**。后端是整包覆盖写，前端少带任何一个切片，那个切片就被清空。所以一个模块多个编辑页时，我会加一层 `layout.tsx` 做共享 Provider + 顶部动作条（保存 / 发布 / 脏标记）+ 加载门（数据没就绪时子页干脆不挂载）——防止某个子页先渲染出来、保存时带着空数据覆盖整包。

## 五、六条验收断言（照着跑，别凭感觉）

```bash
# 1. 匿名禁写
curl -s -o /dev/null -w "%{http_code}\n" https://<域名>/api/xxx        # 期望 401
# 2. C 端接口匿名可读；未发布时切片为空
curl -s https://<域名>/api/c/xxx/content | head -c 200                 # 期望 200 + 空
# 3. 懒 seed 生效
#    GET 回来的条数 > 0
# 4. 白名单真的在拦
#    POST 里塞一个 evil 脏键 → 再 GET，keys 里不应出现 evil
# 5. 往返无损
#    改一个值 → POST → GET 读回确认 → 还原
# 6. RBAC 过滤真的生效
#    用一个普通账号登录，菜单里看不到新分组
```

发布链路另测一条：**未发布时 C 端各切片全空 → publish → C 端读到与后台一致**。这条专门用来抓"匿名接口读了编辑态"的错误——它属于安全事故，不是显示 bug。

## 六、症状 → 根因定位表

| 症状 | 大概率根因 | 一分钟验证 |
|---|---|---|
| 保存成功，刷新就没了，且不报错 | 白名单只改了 `save()` 的 put 列表，漏了读取分支 | 直接查库那一行 JSON 里有没有该键 |
| 后台菜单里看不到新页面 | 只加了菜单没加路由，被 RBAC 过滤 | 查 `PageRoutes` 是否有对应项 |
| 有路由没入口 | 只登记路由没登记菜单 | 手动访问路径能进就说明菜单侧缺 |
| 新角色看不到、老角色能看到 | 启动 upsert 了页面，但角色组没重新勾选 | 角色组管理里勾一次 |
| 改了代码里的默认值线上没变 | 库里已有该键，懒 seed 不覆盖 | 把该切片 POST 成空值再看读回 |
| 一个子页保存后别的切片被清空 | 全量提交时没带齐所有切片 | 保存前打印提交体，比对键数量 |
| C 端读到了没发布的内容 | 匿名接口指错了键（读了编辑态而非 `xxx_published`） | 未发布状态下请求，应返回空 |

第一条是这门课最贵的一课：**"保存成功、刷新就没了"一定是白名单两处不同步**。它不会报错，因为写入侧确实收到了，读取侧只是不认识这个键。

## 七、两个环境层的坑（与架构无关，但会吃掉半天）

- **antd `Select` 的 `onChange` 参数类型含 `undefined`**，直接传给要 `string` 的函数会 `TS2322`，B 端每个新页面都会中一次。加 `typeof v === "string"` 守卫或 `v ?? 默认值`，别用 `!` 骗编译器。
- **新增 C 端路由前缀要先 grep nginx 的 location**。`location ^~ /blog` 的优先级高于 `/`，落在它覆盖范围内的新前缀，代码部署了也打不到应用——这类问题的特征是"接口 404 但后端日志里连请求都没进来"。

## 小结

- 先判断要不要发布态：只有访客会看到的内容才做快照。
- 三处必改按顺序：Java Controller → 菜单与路由双登记 → B 端 lib 与页面。
- 白名单是两处（写入 put 列表 + 读取分支），漏一处就是"静默丢数据"。
- 脏标记走整份比对、保存走全量提交，多页模块共享 Provider 与加载门。
- 验收要能跑出确定性结论：六条断言 + 一条发布链路，全部可 curl。

## 练习

1. 拿一个你现有的后台配置项，把它改造成"某切片为空时回落到代码常量"的懒 seed 形态，验证「把该切片写空 → 读回得到最新默认值」这条路径。
2. 故意只改 `save()` 的白名单、不改读取分支，复现一次"保存成功刷新就没了"，再用定位表里那招确认根因在库里。
3. 给一个模块写完整的六条验收断言脚本（含 401 / 匿名 200 / 白名单拦脏键 / 往返无损），跑通后收进项目脚本目录，以后每个新模块复用同一份。
