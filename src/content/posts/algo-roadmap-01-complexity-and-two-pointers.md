> [!NOTE]
> 双指针是前端面试出场率最高的算法技巧，没有之一。而复杂度分析是你写完代码后的必答追问。这篇把两者打包讲透——先会"说复杂度"，再会"用双指针"。

---

## 1. 大 O：面试官想听什么

面试里说复杂度，其实只需要掌握四个档位：

| 复杂度 | 名字 | 直觉 | 典型场景 |
|--------|------|------|----------|
| O(1) | 常数 | 与规模无关 | 哈希表取值、数组下标访问 |
| O(log n) | 对数 | 每次砍一半 | 二分查找、平衡树操作 |
| O(n) | 线性 | 扫一遍 | 遍历数组、双指针 |
| O(n log n) | 线性对数 | 排序级别 | 内置 sort、归并 |
| O(n²) | 平方 | 双重循环 | 暴力枚举所有两两组合 |

几个实战要点：

**嵌套循环不一定是 O(n²)。** 外层 `for (let i = 0; i < n; i++)` 内层 `while (i < n)` 递增，总执行次数还是 O(n)——比如滑动窗口。看总执行次数，别只看循环层数。

**空间复杂度别忽略递归栈。** 递归深度 n 的代码，空间复杂度就是 O(n)，哪怕你没有额外开数组。面试官问"空间复杂度"时把调用栈算进去，是加分的细节。

**n 的规模暗示了目标复杂度。** 面试官说 n ≤ 10⁵，你给出 O(n²) 基本就挂了；n ≤ 100，O(n³) 都能过。拿到题先看数据范围再动手，这是老手的第一反应。

一个常用的"能过"参考：1 秒内大约能执行 10⁸ 次基本操作。所以 n=10⁵ 时目标复杂度是 O(n log n) 或 O(n)。

## 2. 对撞指针：从两端向中间收

**套路模板**：一个左指针 `l` 从头开始，一个右指针 `r` 从尾开始，根据比较结果决定移动哪一边。

例题 1：**两数之和 II（输入有序数组）**。找出有序数组中两个数之和等于 target 的下标。

```ts
function twoSum(nums: number[], target: number): number[] {
  let l = 0, r = nums.length - 1;
  while (l < r) {
    const sum = nums[l] + nums[r];
    if (sum === target) return [l, r];   // 命中
    if (sum < target) l++;               // 和太小，左指针右移增大
    else r--;                            // 和太大，右指针左移减小
  }
  return [];
}
```

逐行讲：`l` 和 `r` 分别指向最小和最大值。`sum < target` 时，说明右边的数配 `nums[l]` 都太大了？不对——说明**任何数配 `nums[l]` 都不够大或刚好**，因此 `nums[l]` 可以永久淘汰，`l++`。同理 `sum > target` 时 `nums[r]` 永久淘汰。每次循环淘汰一个元素，所以是 O(n) 时间 O(1) 空间。

例题 2：**盛最多水的容器**。选两条竖线使盛水最多。

```ts
function maxArea(height: number[]): number {
  let l = 0, r = height.length - 1, ans = 0;
  while (l < r) {
    ans = Math.max(ans, (r - l) * Math.min(height[l], height[r]));
    height[l] < height[r] ? l++ : r--;   // 移动矮的那边
  }
  return ans;
}
```

核心证明一句话：水高由矮的决定，移动高的那边宽度还变小、高度不会变好，必然更差；移动矮的那边才有可能更好。面试时能把这个"为什么移动矮的"讲清楚，比写出代码更重要。

## 3. 快慢指针：同一方向的追赶

**套路模板**：两个指针同向移动，速度不同或起点不同，用于找中点、判环、去重。

例题：**移除元素 / 有序数组去重**。原地修改，返回新长度。

```ts
function removeDuplicates(nums: number[]): number {
  if (nums.length === 0) return 0;
  let slow = 0;                            // slow：下一个"已确认唯一"的坑位
  for (let fast = 1; fast < nums.length; fast++) {
    if (nums[fast] !== nums[slow]) {
      slow++;
      nums[slow] = nums[fast];             // 把新值填进坑位
    }
  }
  return slow + 1;
}
```

逐行讲：`slow` 左边永远是处理好的前缀，`fast` 负责探路。遇到不重复的值就"填坑"并推进 `slow`。这类"读写指针分离"的写法在前端处理列表数据时也很常用，比如就地过滤一个有序列表。

快慢指针判环（第 05 篇链表篇会展开）：慢指针每次走 1 步、快指针每次走 2 步，若有环必相遇——快指针相对慢指针每轮多走 1 步，在环里迟早"追圈"。这个追及直觉记住就行。

## 4. 前缀和：把"区间求和"变 O(1)

**套路模板**：先扫一遍算出 `prefix[i] = nums[0..i-1] 的和`，之后任意区间 `[l, r)` 的和就是 `prefix[r] - prefix[l]`。

```ts
function buildPrefix(nums: number[]): number[] {
  const prefix = [0];                      // prefix[0] = 0 是关键哨兵
  for (let i = 0; i < nums.length; i++) {
    prefix.push(prefix[i] + nums[i]);
  }
  return prefix;
}
// 区间 [l, r) 的和 = prefix[r] - prefix[l]
```

`prefix[0] = 0` 这个哨兵让 `[0, k)` 这种从头开始的区间不用特判，是前缀和最容易被面试官追问的细节。

例题：**寻找数组的中心下标**。中心下标左边元素和等于右边元素和。

```ts
function pivotIndex(nums: number[]): number {
  const total = nums.reduce((a, b) => a + b, 0);
  let leftSum = 0;
  for (let i = 0; i < nums.length; i++) {
    // 右边和 = 总和 - 左边和 - 当前元素
    if (leftSum * 2 + nums[i] === total) return i;
    leftSum += nums[i];
  }
  return -1;
}
```

这题是前缀思想的变体：不存前缀数组，用"总和减左边"推导右边，空间降到 O(1)。面试里这种"省掉数组"的小优化非常加分。

## 小结

- 复杂度四档：O(1)、O(log n)、O(n)、O(n log n)，看数据范围反推目标复杂度。
- 对撞指针：两端向中间，每轮淘汰一个元素，O(n) 解决两数之和、盛水容器。
- 快慢指针：同向追赶，读写分离，解决去重与原地修改类问题。
- 前缀和：`prefix[r] - prefix[l]` 把区间和降到 O(1)，哨兵 `prefix[0]=0` 免特判。
