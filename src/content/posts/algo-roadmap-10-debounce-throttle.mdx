> [!NOTE]
> 防抖节流是前端手写题第一梯队，而且**层层加码**：基础版 → 立即执行 → cancel/flush → leading/trailing 可配。这篇按真实追问顺序一版一版写，每版都给验证代码。

---

## 1. 先讲清概念（这步决定追问走向）

面试先给一句准话，再动手：

- **防抖 debounce**：事件停止触发 n 毫秒后才执行；期间再触发就重新计时。关键词"**最后一次说了算**"。场景：搜索联想、表单校验、resize 结束后重算。
- **节流 throttle**：n 毫秒内最多执行一次。关键词"**按固定频率执行**"。场景：滚动加载、拖拽、按钮防连点。

一句话区分：**防抖是"等你别闹了再做"，节流是"再闹我也按节奏做"。**

## 2. 防抖：从基础版到可用版

### 2.1 基础版

```ts
function debounce<T extends (...args: any[]) => void>(fn: T, delay: number) {
  let timer: ReturnType<typeof setTimeout> | null = null;

  return function (this: unknown, ...args: Parameters<T>) {
    if (timer) clearTimeout(timer); // 重新计时
    timer = setTimeout(() => {
      timer = null;
      fn.apply(this, args);         // 透传 this 与参数
    }, delay);
  };
}
```

三个必讲细节：

1. **`fn.apply(this, args)`**：事件处理里的 `this` 和参数必须透传。写成 `fn(...args)` 会丢 `this`。
2. **返回普通函数而不是箭头函数**：箭头函数没有自己的 `this`，拿不到调用上下文。
3. **`timer = null` 在回调里重置**：不清的话，下一次判断"是否在等待期"就会错。

### 2.2 加 immediate、cancel、flush

```ts
type Debounced<T extends (...args: any[]) => void> = T & {
  cancel: () => void;
  flush: () => void;
};

function debounce<T extends (...args: any[]) => void>(
  fn: T,
  delay: number,
  immediate = false,
): Debounced<T> {
  let timer: ReturnType<typeof setTimeout> | null = null;
  let lastArgs: Parameters<T> | null = null;
  let lastThis: unknown = null;

  const debounced = function (this: unknown, ...args: Parameters<T>) {
    const callNow = immediate && !timer; // 静止后的第一次
    lastArgs = args;
    lastThis = this;

    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (!immediate && lastArgs) fn.apply(lastThis, lastArgs);
      lastArgs = null;
    }, delay);

    if (callNow) fn.apply(this, args);
  } as Debounced<T>;

  debounced.cancel = () => {
    if (timer) clearTimeout(timer);
    timer = null;
    lastArgs = null;
  };

  // 立刻结算：把还在等待的那次提前执行掉
  debounced.flush = () => {
    if (!timer || !lastArgs) return;
    clearTimeout(timer);
    timer = null;
    fn.apply(lastThis, lastArgs);
    lastArgs = null;
  };

  return debounced;
}
```

`immediate` 的关键在 `!timer`：只有"定时器不存在"（说明距离上次执行已超过 delay）才立即调用。**`timer = null` 必须在回调里重置**，否则 immediate 永远只有第一次生效。

`flush` 的用途：表单点"提交"时，用户可能刚输入完还没到 300ms，需要把待执行的那次立刻结算，否则提交的是旧值。这是 `cancel` 之外最常被追问的一个 API。

### 2.3 跑一遍验证

```ts
const log = (x: number) => console.log('run', x);
const d = debounce(log, 300);

d(1); d(2); d(3);
// 300ms 后只打印 "run 3"

const d2 = debounce(log, 300, true);
d2(1); // 立即打印 run 1
setTimeout(() => d2(2), 100); // 不打印
setTimeout(() => d2(3), 500); // 立即打印 run 3（已过 300ms 静默）

d(9);
d.flush(); // 立即打印 run 9
```

### 2.4 React 里的正确清理

```tsx
useEffect(() => {
  const onResize = debounce(() => setWidth(window.innerWidth), 200);
  window.addEventListener('resize', onResize);
  return () => {
    window.removeEventListener('resize', onResize);
    onResize.cancel(); // 组件卸载时清掉待执行的定时器
  };
}, []);
```

**只 removeEventListener 不够**：已经排队的定时器仍会在卸载后触发，导致 `setState on unmounted component` 或内存泄漏。

## 3. 节流：两种基础实现

### 3.1 时间戳版（leading）

```ts
function throttleTimestamp<T extends (...args: any[]) => void>(fn: T, interval: number) {
  let last = 0;
  return function (this: unknown, ...args: Parameters<T>) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}
```

首次触发时 `last = 0`，所以**立即执行**；停止触发后不会补最后一次。

### 3.2 定时器版（trailing）

```ts
function throttleTimer<T extends (...args: any[]) => void>(fn: T, interval: number) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  return function (this: unknown, ...args: Parameters<T>) {
    if (timer) return; // 冷却中，直接忽略
    timer = setTimeout(() => {
      timer = null;
      fn.apply(this, args);
    }, interval);
  };
}
```

首次触发是**延迟执行**；停止后会把最后一次补上。

| 版本 | 首次触发 | 停止后 | 适合 |
| --- | --- | --- | --- |
| 时间戳版 | 立即 | 不补 | 滚动进度、快速响应 |
| 定时器版 | 延迟 | 补一次 | 搜索输入、需要最后一次 |
| rAF 版 | 下一帧 | 每帧最多一次 | 动画、滚动渲染 |

### 3.3 leading/trailing 可配版

```ts
function throttle<T extends (...args: any[]) => void>(
  fn: T,
  interval: number,
  { leading = true, trailing = true } = {},
) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  let last = 0;
  let lastArgs: Parameters<T> | null = null;
  let lastThis: unknown = null;

  const throttled = function (this: unknown, ...args: Parameters<T>) {
    lastArgs = args;
    lastThis = this;

    const now = Date.now();
    if (!last && !leading) last = now; // 首次且不 leading：假装刚执行过

    const remain = interval - (now - last);
    if (remain <= 0) {
      if (timer) { clearTimeout(timer); timer = null; }
      last = now;
      fn.apply(this, args);
      lastArgs = null;
    } else if (!timer && trailing) {
      timer = setTimeout(() => {
        last = leading ? Date.now() : 0;
        timer = null;
        if (lastArgs) fn.apply(lastThis, lastArgs);
        lastArgs = null;
      }, remain);
    }
  } as T & { cancel: () => void };

  throttled.cancel = () => {
    if (timer) clearTimeout(timer);
    timer = null;
    last = 0;
    lastArgs = null;
  };

  return throttled;
}
```

写不出这版也没关系——**能把表格里的行为差异讲清楚**，分数基本拿满。这版的价值在于：它同时具备"立即执行"和"补最后一次"两条路径，理解它就理解了时间戳版与定时器版的全部差异。

## 4. rAF 节流：与渲染帧对齐

```ts
function rafThrottle<T extends (...args: any[]) => void>(fn: T) {
  let ticking = false;
  let lastArgs: Parameters<T> | null = null;
  let lastThis: unknown = null;

  return function (this: unknown, ...args: Parameters<T>) {
    lastArgs = args;
    lastThis = this;
    if (ticking) return;

    ticking = true;
    requestAnimationFrame(() => {
      ticking = false;
      if (lastArgs) fn.apply(lastThis, lastArgs);
      lastArgs = null;
    });
  };
}
```

三个要点：

- `ticking` 保证**每帧最多执行一次**；
- `lastArgs` 保留帧内的最新参数（帧内触发 5 次，只执行最终状态）；
- **标签页隐藏时 rAF 自动暂停**，比 `setTimeout(16)` 省电，也不会在后台堆积任务。

追问"rAF 和 `setTimeout(16)` 的区别"：rAF 与屏幕刷新同步、后台自动暂停、不保证 16ms（120Hz 屏是 8.3ms）；`setTimeout` 是最小延迟且会被节流到 4ms 以上。

## 5. 场景选型表

| 场景 | 选择 | 理由 |
| --- | --- | --- |
| 搜索框输入联想 | debounce 300–500ms | 只要最后一次 |
| 表单实时校验 | debounce 200ms + flush | 提交时立即结算 |
| 滚动加载更多 | throttle 100–200ms | 要持续响应 |
| 拖拽/缩放 | rAF 节流 | 与帧对齐 |
| 按钮防连点 | throttle leading | 首次立即，冷却期忽略 |
| resize 重算布局 | debounce 150ms | 结束后算一次 |
| 埋点上报 | throttle 1s + flush | 控制频率，离开前补发 |

---

## 6. 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| `this` 丢失 | 用了箭头函数 / `fn(...args)` | 普通函数 + `apply` |
| immediate 只生效一次 | 回调里没重置 `timer = null` | 在 setTimeout 内重置 |
| 组件卸载后仍执行 | 只 removeEventListener | 额外 `debounced.cancel()` |
| 提交时用了旧值 | 待执行的那次还没触发 | 调 `flush()` |
| 节流首次不执行 | 用了定时器版 | 换时间戳版或 `leading: true` |
| 节流最后不执行 | 用了时间戳版 | 换定时器版或 `trailing: true` |
| 后台标签页任务堆积 | `setTimeout` 驱动 | 改 rAF 节流 |
| 帧内参数串了 | 没保存 `lastArgs` | 每次触发都更新 |

---

## 7. 小结

- 防抖：clearTimeout 重新计时；完整版补 `immediate`（`!timer`）、`cancel`、`flush`。
- 节流：时间戳版 leading、定时器版 trailing，合体版两者可配。
- rAF 节流：`ticking` + `lastArgs`，与渲染帧对齐、后台暂停。
- 选型看"要不要最后一次"和"要不要持续响应"。
