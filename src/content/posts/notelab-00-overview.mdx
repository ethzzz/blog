其他模块讲的是"别人的东西怎么用"，这个系列讲的是**我自己的项目怎么活下来**。NoteLab 是我从零维护的自托管知识库，横跨前后端和运维，踩的坑足够攒成一个系列，就开在这儿。

> [!NOTE]
> 系列现有 **8 篇**。01–04 是第一批（环境、架构、AI 落地、部署验收），05–08 补齐了当时没写的四块：加一个模块的完整动作、发布态与编辑态的分离、会骗你的检查、以及环境不对称这件事本身。

## 项目矩阵长什么样

```text
NoteLab
├── notelab-java   Spring Boot 后端：业务 API、内容服务（:8001）
├── notelab-b      B 端管理后台：配置生成、内容管理（:3020）
├── notelab-c      C 端 Next.js 前台：游戏、工具、阅读（:3010）
└── MySQL          数据落点（:3306），ui_config 单键存配置
```

一台服务器、一套 nginx、几个 pm2 进程——麻雀虽小，但三仓协同该有的问题一个不少。路由归属长这样，它决定了"我明明部署了为什么打不到"这类问题的排查方向：

| 前缀 | 落到哪 | 说明 |
| --- | --- | --- |
| `/`、`/games` | C 端前台 | 匿名可见，只读消费 |
| `/admin` | B 端后台 | 写入口，需登录 |
| `/api` | Java 后端 | 业务与内容接口 |
| `/blog` | 静态博客 | 就是你现在看的这个站；`^~` 优先级高于 `/` |

按编号读即可，它们之间是递进关系而不是并列专题。三种起点的跳法：

- **只关心"这架构合理吗"**：02 → 06 → 05。先接受架构，再看它逼出来的两个设计决定。
- **要往里面加东西**：05 → 06 → 01。动作清单、发布语义，然后回到环境把开发机支起来。
- **被"明明改了却没生效"卡住**：07 → 04 → 08。这三篇合起来就是那个问题的完整答案。

## 八篇之外的候选

低代码表单、爬塔玩法（Spire）的配置化、跨仓契约测试——都想写，但都还没写到"能给出可复现判据"的程度。这个系列的规矩是：**没有验收断言的内容不发布**。

## 这个系列明确不写什么

- **不写可定位的生产信息**：服务器地址、内部凭据、可被拿来伪造会话的构造方法，一概不进正文。示例里出现的域名和端口是最小组合，够你理解结构了。
- **不写教程式内容**："10 分钟搭建 XXX"这种我写不了，因为我的环境处处不齐（见 08）。
- **不承诺跟进**：项目还在演进，个别结论会被后续推翻。推翻时我会改正文并在末尾留一条修订说明，而不是悄悄改掉。

## 你能从这儿带走什么

不是教程，是**实录**：每个坑都带现场痕迹和验证过的解法。如果你也在维护一个多仓全栈项目，这几条大概率能直接抄：

- 配置读写分离的边界怎么划（02）、发布快照的复制语义怎么定（06）；
- 加模块时的三处必改与六条可执行断言（05）；
- 部署后那三层证据怎么取（04）、以及哪些绿灯不能信（07）；
- 一张「检查项 × 机器」的能力矩阵（08）——我认为这条最值钱，因为它把"本地复现不了"从半天缩到几分钟。
