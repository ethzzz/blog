## 2. 依赖注入：不要自己 new

```java
@RestController
@RequestMapping("/api/tasks")
public class TaskController {
    private final TaskService service;

    // 构造器注入：只有这一个构造器时 @Autowired 可省略
    public TaskController(TaskService service) {
        this.service = service;
    }
}
```

```java
@Service
public class TaskService {
    private final TaskMapper mapper;

    public TaskService(TaskMapper mapper) {
        this.mapper = mapper;
    }
}
```

三个注解的分工要说清：

| 注解 | 位置 | 语义 |
| :-- | :-- | :-- |
| `@RestController` | Controller 类 | 返回值直接序列化成 JSON |
| `@Service` | Service 类 | 业务层组件（语义标记，本质都是 Bean） |
| `@Mapper` | Mapper 接口 | 由 MyBatis 生成代理实现 |

**为什么用构造器注入**：依赖不可变（`final`）、方便单元测试直接 `new`、启动时就能暴露循环依赖。字段注入（`@Autowired` 写在字段上）写起来短，但测试必须起容器，且容易掩盖循环依赖。

> Java 的 Bean 默认是**单例**。不要在 Controller/Service 里放可变成员变量保存「当前用户」之类的请求态——那是线程安全问题，不是 Spring 的问题。

Mapper 用注解写简单 SQL，复杂 SQL（动态条件、批量）再上 XML：

```java title="src/main/java/com/demo/taskcenter/task/TaskMapper.java"
package com.demo.taskcenter.task;

import org.apache.ibatis.annotations.*;

import java.util.List;

@Mapper
public interface TaskMapper {

    @Select("SELECT * FROM task WHERE id = #{id}")
    Task findById(@Param("id") long id);

    @Select("SELECT * FROM task WHERE id = #{id} FOR UPDATE")
    Task findByIdForUpdate(@Param("id") long id);

    @Select("""
        SELECT * FROM task
        WHERE (#{done} IS NULL OR done = #{done})
          AND (#{keyword} IS NULL OR title LIKE CONCAT('%', #{keyword}, '%'))
        ORDER BY priority ASC, id DESC
        LIMIT #{limit} OFFSET #{offset}
        """)
    List<Task> page(@Param("done") Boolean done,
                    @Param("keyword") String keyword,
                    @Param("limit") int limit,
                    @Param("offset") long offset);

    @Insert("""
        INSERT INTO task(title, done, priority)
        VALUES(#{title}, #{done}, #{priority})
        """)
    @Options(useGeneratedKeys = true, keyProperty = "id")
    int insert(Task task);

    @Update("UPDATE task SET title = #{title}, done = #{done}, priority = #{priority} WHERE id = #{id}")
    int update(Task task);

    @Delete("DELETE FROM task WHERE id = #{id}")
    int delete(@Param("id") long id);
}
```

JDBC 在底层管理连接、执行语句并读取结果。MyBatis 把 Mapper 调用映射为 SQL，负责绑定参数和映射结果。Spring 将同一事务内的 Mapper 调用关联到对应的数据库连接。

`#{}` 与 `${}` 的区别如下。

| 写法 | 行为 | 安全性 |
| :-- | :-- | :-- |
| `#{name}` | 生成 SQL 占位符 `?` 并绑定值 | 用于业务输入值 |
| `${name}` | 直接插入 SQL 文本 | 动态排序需要先映射到服务端定义的固定列名 |

排序字段这种确实拼 SQL 的场景，也要先过白名单：

```java
private static final Set<String> SORTABLE = Set.of("priority", "created_at", "id");

String sort = SORTABLE.contains(req.sort()) ? req.sort() : "id";
```

## 4. 事务：`@Transactional` 的正确姿势

```java title="src/main/java/com/demo/taskcenter/task/TaskService.java"
package com.demo.taskcenter.task;

import com.demo.taskcenter.common.BusinessException;
import com.demo.taskcenter.task.dto.TaskSaveReq;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Service
public class TaskService {

    private final TaskMapper mapper;

    public TaskService(TaskMapper mapper) {
        this.mapper = mapper;
    }

    public Task get(long id) {
        Task task = mapper.findById(id);
        if (task == null) throw new BusinessException(404, "任务不存在");
        return task;
    }

    public List<Task> page(Boolean done, String keyword, int limit, long offset) {
        return mapper.page(done, keyword, limit, offset);
    }

    @Transactional
    public Task create(TaskSaveReq req) {
        Task task = new Task();
        task.setTitle(req.title());
        task.setDone(false);
        task.setPriority(req.priority() == null ? 3 : req.priority());
        mapper.insert(task);
        return get(task.getId());
    }

    @Transactional
    public Task update(long id, TaskSaveReq req) {
        Task task = getForUpdate(id);
        task.setTitle(req.title());
        task.setPriority(req.priority() == null ? 3 : req.priority());
        mapper.update(task);
        return get(id);
    }

    public void delete(long id) {
        if (mapper.delete(id) == 0) throw new BusinessException(404, "任务不存在");
    }

    @Transactional(rollbackFor = Exception.class)
    public void complete(long id) {
        Task task = getForUpdate(id);
        task.setDone(true);
        mapper.update(task);
        // 模拟后续步骤失败：前面的 update 必须一起回滚
        if (task.getPriority() < 0) throw new IllegalStateException("数据异常");
    }

    private Task getForUpdate(long id) {
        Task task = mapper.findByIdForUpdate(id);
        if (task == null) throw new BusinessException(404, "任务不存在");
        return task;
    }
}
```

创建后查询一次，让数据库生成的 ID 和时间一起返回。修改前用 `FOR UPDATE` 锁定任务行，完成状态和标题变更同时到达时，两次写入会按顺序读写，避免拿着过期对象覆盖彼此的字段。`complete` 留给本篇的回滚测试，阶段十三会为它增加 HTTP 入口与审计。

三个容易踩的点：

1. **默认对 `RuntimeException` 和 `Error` 回滚**。受检异常（如 `IOException`）若也应触发回滚，可为相应方法配置 `rollbackFor`。
2. **同类内部调用不走代理**：`this.complete()` 调用不会开事务。要么拆到另一个 Bean，要么用 `AopContext.currentProxy()`（不推荐）。
3. **事务里别做慢操作**：调外部 HTTP、发消息、睡 3 秒，都会把数据库连接占住。把非数据库操作挪到事务外，或改用事件/消息。

传播行为先记住两个最常用的：

| 传播 | 场景 |
| :-- | :-- |
| `REQUIRED`（默认） | 有事务就加入，没有就新建 |
| `REQUIRES_NEW` | 一定要独立事务（如写审计日志，主流程失败也要保留） |

## 5. 参数校验与统一错误

不要在 Controller 里手写一堆 `if (title == null)`，用 Bean Validation：

```java title="src/main/java/com/demo/taskcenter/task/dto/TaskSaveReq.java"

import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;

public record TaskSaveReq(
    @NotBlank(message = "标题不能为空")
```

统一返回体与全局异常处理，避免每个接口各写一套错误格式：

```java title="src/main/java/com/demo/taskcenter/common/ApiResponse.java"
package com.demo.taskcenter.common;

public record ApiResponse<T>(int code, String message, T data) {
    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(0, "ok", data);
    }
    public static <T> ApiResponse<T> fail(int code, String message) {
        return new ApiResponse<>(code, message, null);
    }
}
```

```java title="src/main/java/com/demo/taskcenter/common/GlobalExceptionHandler.java"
package com.demo.taskcenter.common;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.web.ErrorResponse;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;

@RestControllerAdvice
public class GlobalExceptionHandler {
    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    /** 参数校验失败：400 + 第一条字段错误 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiResponse<Void> onInvalid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .findFirst()
                .map(err -> err.getField() + ": " + err.getDefaultMessage())
                .orElse("参数不合法");
        return ApiResponse.fail(400, msg);
    }

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiResponse<Void>> onBusiness(BusinessException e) {
        return ResponseEntity.status(e.getCode())
                .body(ApiResponse.fail(e.getCode(), e.getMessage()));
    }

    @ExceptionHandler({HttpMessageNotReadableException.class, MethodArgumentTypeMismatchException.class})
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiResponse<Void> onMalformedRequest() {
        return ApiResponse.fail(400, "请求体或参数格式不合法");
    }

    /** 兜底：不要把堆栈直接返回给前端 */
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Void>> onUnknown(Exception e) {
        if (e instanceof ErrorResponse error && error.getStatusCode().is4xxClientError()) {
            return ResponseEntity.status(error.getStatusCode())
                    .body(ApiResponse.fail(error.getStatusCode().value(), "请求无法处理"));
        }
        log.error("Unhandled request error", e);
        return ResponseEntity.internalServerError()
                .body(ApiResponse.fail(500, "服务器开小差了，请稍后再试"));
    }
}
```

**前端视角**：这套结构等价于你在 Next.js 里写的 `route handler + zod + 统一 error JSON`。区别是 Java 把「校验」放进了框架层，`@Valid` 失败会在进方法前被拦下。

## 6. 把接口串起来

```java title="src/main/java/com/demo/taskcenter/task/TaskController.java"
package com.demo.taskcenter.task;

import com.demo.taskcenter.common.ApiResponse;
import com.demo.taskcenter.task.dto.TaskSaveReq;
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    private final TaskService service;

    public TaskController(TaskService service) {
        this.service = service;
    }

    @GetMapping
    public ApiResponse<List<Task>> list(@RequestParam(required = false) Boolean done,
                                        @RequestParam(required = false) String keyword,
                                        @RequestParam(defaultValue = "1") int page,
                                        @RequestParam(defaultValue = "20") int size) {
        int limit = Math.min(Math.max(size, 1), 100);
        long offset = Math.max((long) page - 1, 0) * limit;
        return ApiResponse.ok(service.page(done, keyword, limit, offset));
    }

    @GetMapping("/{id}")
    public ApiResponse<Task> get(@PathVariable long id) {
        return ApiResponse.ok(service.get(id));
    }

    @PostMapping
    public ApiResponse<Task> create(@Valid @RequestBody TaskSaveReq req) {
        return ApiResponse.ok(service.create(req));
    }

    @PutMapping("/{id}")
    public ApiResponse<Task> update(@PathVariable long id,
                                    @Valid @RequestBody TaskSaveReq req) {
        return ApiResponse.ok(service.update(id, req));
    }

    @DeleteMapping("/{id}")
    public ApiResponse<Void> delete(@PathVariable long id) {
        service.delete(id);
        return ApiResponse.ok(null);
    }
}
```

本篇将 `size` 限制在 1–100，页码小于 1 时从第一页取。先将 `page` 转为 `long`，极端页码也不会把偏移量算成负数。阶段十四会把越界改成显式报错，阶段十五再比较深分页的成本。

```bash
export DB_PASSWORD=task-lab-password

docker exec task-center-mysql sh -c \
  'mysql -h 127.0.0.1 -u "$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" -e "SELECT 1"'
```

首次启动需要初始化，若查询连不上，先看 `docker logs task-center-mysql`，服务就绪后重试 `SELECT 1`。以后可用 `docker start task-center-mysql` 复用这个容器。当前终端在 `task-center` 根目录执行 `mvn spring-boot:run`。应用启动时执行 `schema.sql`。

在另一终端执行以下命令。第一次响应的 `data.id` 填入 `ID`，其余命令会核对同一条任务。

```bash
BASE=http://127.0.0.1:8081/api/tasks
curl -i -H 'Content-Type: application/json' -d '{"title":"整理工单","priority":2}' "$BASE"

# 把 1 换成上一步的 data.id
ID=1
curl -i "$BASE/$ID"
curl -i -X PUT -H 'Content-Type: application/json' -d '{"title":"整理新工单","priority":1}' "$BASE/$ID"
curl -i --get --data-urlencode 'done=false' --data-urlencode 'keyword=新工单' "$BASE"
curl -i -H 'Content-Type: application/json' -d '{"title":" "}' "$BASE"
curl -i -X DELETE "$BASE/$ID"
curl -i "$BASE/$ID"
```

按顺序核对 HTTP 状态 `200、200、200、200、400、200、404`。列表里应有修改后的标题。这个版本的创建接口返回 `200`，阶段十四会改成 `201` 和明确的响应契约。

```java title="src/test/java/com/demo/taskcenter/task/TaskControllerTest.java"
    void create_should_reject_blank_title() throws Exception {
        mvc.perform(post("/api/tasks")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"title\":\"  \",\"priority\":3}"))
            .andExpect(status().isBadRequest())
            .andExpect(jsonPath("$.code").value(400));
    }

    @Test
    void complete_should_roll_back_on_failure_after_update() {
        Task invalid = new Task();
        invalid.setTitle("回滚实验");
        invalid.setDone(false);
        invalid.setPriority(-1);
        mapper.insert(invalid);
        long id = invalid.getId();
        try {
            assertThrows(IllegalStateException.class, () -> service.complete(id));
            assertFalse(mapper.findById(id).getDone());
        } finally {
            mapper.delete(id);
        }
    }
}
```

## 8. 上线前必须知道的坑

| 坑 | 现象 | 处理 |
| :-- | :-- | :-- |
| 查询值通过 `${}` 拼入 SQL | 用户输入改变查询语句结构 | 用 `#{}` 绑定值，排序列名单独映射 |
| 驼峰没映射 | `createdAt` 永远 null | `map-underscore-to-camel-case: true` |
| 时区错 8 小时 | 前端把没有偏移量的 `LocalDateTime` 当成 UTC | 先约定字段的业务语义，再按阶段十四确立序列化契约 |
| 事务不生效 | 异常了数据还在 | 检查同类调用、`rollbackFor`、方法是否 `public` |
| N+1 查询 | 列表页 100 条发 101 条 SQL | 批量查询 `IN`、联表或两级缓存 |
| 连接池打满 | 偶发超时 | 事务里别做 HTTP/文件操作，检查连接泄漏 |
| 异常堆栈外泄 | 暴露表名/路径 | 全局兜底只返回通用文案，细节进日志 |

## 小结

这一篇没有新语法，重点是把已有知识**按真实工程顺序组装**：

- Spring Boot 提供容器与 HTTP 出入口；`@RestController` / `@Service` / `@Mapper` 各就各位；
- MyBatis 用 `#{}` 把参数安全地送进 SQL，用 `@Options` 取回自增主键；
- `@Transactional` 管的是一组数据库操作的原子性，回滚实验可以验证代理和数据库是否一起生效。
- 校验放在 DTO 上、错误格式收在 `@RestControllerAdvice`，接口层只留编排；
- 分页参数、排序字段、异常信息这三处是安全与稳定的高发区。
