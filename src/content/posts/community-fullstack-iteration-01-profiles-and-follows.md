发帖审核和举报闭环跑通后，读者可以从帖子进入作者主页，查看其公开内容并关注作者。登录用户可以修改昵称和简介，在「我的关注」统一管理关注关系，也能从关注通知打开对方的主页。

## 公开主页和私人设置

公开主页 `/users/:id` 展示昵称、简介、加入日期、关注数、关注者数和公开帖子。Express 只读取活跃用户，并在数据库查询里限制帖子状态为 `published`。邮箱、密码哈希和关注名单留在各自的权限边界内。草稿、待审、驳回和已删除帖子无法从主页查询。

`/settings/profile` 允许登录用户修改自己的昵称和简介。写接口从验签后的 JWT 读取用户 ID，Zod 仅接收昵称和简介，并按数据库字段长度校验。简介传空值时清除已有内容。`/settings/following` 展示本人的关注名单，可跳转到目标主页或直接取消关注。

| 接口 | 访问方式 | 返回或操作 |
| --- | --- | --- |
| `GET /api/v1/users/:id?before=` | 公开 | 个人资料、统计和公开帖子分页 |
| `GET /api/v1/users/me` | 登录 | 本人资料 |
| `PATCH /api/v1/users/me` | 登录 | 修改昵称或简介 |
| `GET /api/v1/users/me/following?before=` | 登录 | 本人的关注名单分页 |
| `GET /api/v1/users/:id/follow` | 登录 | 当前用户是否关注此人 |
| `POST /api/v1/users/:id/follow` / `DELETE /api/v1/users/:id/follow` | 登录 | 关注或取消关注 |

帖子和关注名单每页取 20 条，用下一条记录判断是否还有后续页。游标对应帖子的 ID 或被关注用户的 ID，查询按 ID 降序取游标之前的数据。较新的记录插入时，已经打开的下一页可以继续从原来的位置读。

## 关注按钮和通知共用一条关系

先前的关注按钮把初始状态设为「未关注」，刷新后会丢失显示状态。现在按钮先从 Express 读取当前关注关系，资料页、帖子详情和「我的关注」复用同一组件。React Query 的缓存键同时包含当前用户与目标用户的 ID。写成功后重新读取关系，同时刷新页面上的统计或关注名单。

写操作继续沿用 MySQL `follows` 表的联合主键。首次创建关系时，Express 在同一数据库事务里写入 `follow.created` Outbox 事件。已有的通知 worker 将事件写成站内通知。通知上的「查看关注者主页」使用实际触发关注的用户 ID。

这轮功能使用现有的用户、帖子、关注和通知表。Next.js 通过同源 BFF 调用公共 API，NestJS 仍负责帖子审核、举报和审计。审核中的帖子继续遵守此前的可见性规则，个人主页与公开搜索使用同一个已发布状态。

## 验证时看什么

API 测试用 21 篇已发布帖子、草稿和待审核帖子验证两页查询、字段公开范围和封禁状态。浏览器测试使用两个会话，验证资料保存后刷新仍可读取、访客能看主页、关注状态刷新后仍保留、关注通知能回到对应用户主页，以及取消关注后名单和按钮同步更新。本轮本地生产构建通过，5 条 Playwright 用例全部通过。
