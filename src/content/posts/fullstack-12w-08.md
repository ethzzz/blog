## 本周目标

- 理解缓存三大坑：击穿（单 key 过期瞬压）、雪崩（批量过期）、穿透（查不存在的 key）。
- 用 Redis 给热点接口（配置读取）加缓存。
- 实现简单令牌桶限流。
- 用 `autocannon`/`ab` 压测前后对比。

## 核心概念速记（详文 →）

- 队列与定时任务：[/blog/posts/node-roadmap-10-queue-and-schedule/](/blog/posts/node-roadmap-10-queue-and-schedule/)
- （Redis 缓存实践本系列补充，深度见后端面试篇）

**记忆锚点**：

- 击穿：热点 key 过期瞬间海量请求打到 DB → 用"互斥锁"或"逻辑过期"挡。
- 雪崩：大量 key 同时过期 → 过期时间加随机抖动。
- 穿透：查不存在的数据 → 布隆过滤器或缓存空值。

## 落到我项目的动作

- 给 Spire/loot 的配置读取接口加 Redis 缓存（这些配置读多写少，典型缓存场景）。
- 加一个令牌桶限流中间件，保护热点接口。

## 本周交付物（可见）

- 带缓存 + 限流的接口 + 一个压测小脚本（node 写，对比 QPS/延迟）。

## 面试一句话

"缓存三坑——击穿用锁/逻辑过期、雪崩用过期抖动、穿透用布隆/空值；限流保护系统不被单点打垮，令牌桶适合平滑限流。"

## 易错点 / 记忆锚点

- 缓存必须设 TTL，否则脏数据永久留存；写操作后记得主动失效缓存。
- 限流要区分"用户级"和"全局级"，别把正常用户也限了。

## 练习

1. 给配置接口加 Redis 缓存 + TTL 抖动，压测对比 QPS。
2. 实现令牌桶限流中间件，验证超额请求被 429。
3. 制造一次缓存击穿（让热点 key 过期瞬间发压），观察 DB 压力，再用锁修复。
