## 1. 模块（Modules）

**概念：** 把代码拆分成多个文件。每个文件就是一个模块，可以导出内容供其他文件导入。

`math.js`：

```js
export function add(a, b) {
  return a + b;
}

export const PI = 3.14159;

export default function multiply(a, b) {
  return a * b;
}
```

`app.js`：

```js
import multiply, { add, PI } from "./math.js";
import { readFile } from "node:fs/promises"; // 内置模块

console.log(add(2, 3));      // 5
console.log(multiply(4, 5)); // 20
console.log(PI);
```

**注意事项**

- 相对路径导入时要写 `.js` 扩展名。
- 内置模块使用 `node:` 前缀。
- 旧代码使用 CommonJS（`require` 和 `module.exports`）。很多第三方包仍在使用，所以两种写法都要认识。

## 2. 异步代码与事件循环

**概念：** Node 用一个线程运行你的 JavaScript。耗时操作（文件、网络、定时器）会被交给系统处理，完成后再执行回调。这样 Node 才能保持响应。

### 回调、Promise、async/await

```js
// 1) 回调风格（旧）
setTimeout(() => console.log("callback done"), 100);

// 2) Promise 风格
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
wait(100).then(() => console.log("promise done"));

// 3) async/await（推荐）
async function main() {
  await wait(100);
  console.log("await done");
}
main();
```

### 并行执行任务

```js
const fakeFetch = async (name, ms) => {
  await wait(ms);
  return `${name} loaded`;
};

console.time("sequential");
await fakeFetch("a", 300);
await fakeFetch("b", 300);
console.timeEnd("sequential"); // 约 600ms

console.time("parallel");
const results = await Promise.all([
  fakeFetch("a", 300),
  fakeFetch("b", 300),
]);
console.timeEnd("parallel"); // 约 300ms
console.log(results);
```

### 执行顺序

```js
console.log("1 sync");

setTimeout(() => console.log("4 timeout"), 0);

Promise.resolve().then(() => console.log("3 microtask"));

console.log("2 sync");
```

输出顺序：`1 sync`、`2 sync`、`3 microtask`、`4 timeout`。

**规则：** 先执行同步代码，然后是微任务（Promise），最后是定时器和 I/O 回调。

**常见错误：** 阻塞事件循环。

```js
// 错误示范：运行期间会冻结所有其他请求
while (Date.now() < Date.now() + 5000) {}
```

繁重的 CPU 计算应该放到 worker 线程中（见第 9 节）。

## 3. 文件操作

**概念：** `fs/promises` 模块可以在不阻塞的情况下读写文件。用 `path` 来安全地拼接文件路径。

```js
import { readFile, writeFile, appendFile, readdir, mkdir } from "node:fs/promises";
import path from "node:path";
import { fileURLToPath } from "node:url";

// ES Modules 没有 __dirname，需要自己构造
const __dirname = path.dirname(fileURLToPath(import.meta.url));
const dataDir = path.join(__dirname, "data");

await mkdir(dataDir, { recursive: true });

const file = path.join(dataDir, "notes.txt");
await writeFile(file, "First note\n", "utf8");
await appendFile(file, "Second note\n");

const text = await readFile(file, "utf8");
console.log(text);

console.log(await readdir(dataDir)); // [ 'notes.txt' ]
```

### 错误处理

```js
try {
  await readFile("missing.txt", "utf8");
} catch (err) {
  if (err.code === "ENOENT") {
    console.log("文件不存在");
  } else {
    throw err; // 不要隐藏意料之外的错误
  }
}
```

### 处理 JSON

```js
const config = { theme: "dark", retries: 3 };
await writeFile("config.json", JSON.stringify(config, null, 2));

const loaded = JSON.parse(await readFile("config.json", "utf8"));
console.log(loaded.theme); // dark
```

## 4. 事件（Events）

**概念：** Node 中很多对象都是事件发射器。用 `on` 注册监听器，用 `emit` 触发事件。服务器、流和许多库都基于这种模式。

```js
import { EventEmitter } from "node:events";

class OrderService extends EventEmitter {
  placeOrder(item) {
    console.log(`Order placed: ${item}`);
    this.emit("order", { item, time: Date.now() });
  }
}

const orders = new OrderService();

orders.on("order", (data) => console.log("Email sent for", data.item));
orders.on("order", (data) => console.log("Stock updated for", data.item));
orders.once("order", () => console.log("First order bonus!"));

orders.placeOrder("book");
orders.placeOrder("pen");
```

**提示：** 可能出错的发射器一定要添加 `error` 监听器。没有处理的 `error` 事件会让进程崩溃。

## 5. 流（Streams）

**概念：** 流把数据分成小块逐步处理，而不是一次性全部加载到内存。处理大文件、上传和网络数据时要用流。

复制大文件而不占用大量内存：

```js
import { createReadStream, createWriteStream } from "node:fs";
import { pipeline } from "node:stream/promises";
import { createGzip } from "node:zlib";

await pipeline(
  createReadStream("big-file.txt"),
  createGzip(),
  createWriteStream("big-file.txt.gz")
);
console.log("压缩完成");
```

`pipeline` 会自动处理错误和资源清理。

### 自定义转换流

```js
import { Transform } from "node:stream";
import { pipeline } from "node:stream/promises";

const upperCase = new Transform({
  transform(chunk, encoding, callback) {
    callback(null, chunk.toString().toUpperCase());
  },
});

await pipeline(process.stdin, upperCase, process.stdout);
```

运行后输入一些文字，它会以大写形式输出。

### 逐行读取文件

```js
import { createReadStream } from "node:fs";
import readline from "node:readline";

const rl = readline.createInterface({
  input: createReadStream("access.log"),
  crlfDelay: Infinity,
});

let errors = 0;
for await (const line of rl) {
  if (line.includes("ERROR")) errors++;
}
console.log(`发现 ${errors} 个错误`);
```

## 6. 原生 HTTP 服务器

**概念：** Express 是建立在 Node 的 `http` 模块之上的。不用框架写一遍，你就能明白框架替你做了什么。

```js
import http from "node:http";

const todos = [{ id: 1, title: "Learn Node", done: false }];

const server = http.createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host}`);

  if (req.method === "GET" && url.pathname === "/todos") {
    res.writeHead(200, { "Content-Type": "application/json" });
    return res.end(JSON.stringify(todos));
  }

  if (req.method === "POST" && url.pathname === "/todos") {
    let body = "";
    for await (const chunk of req) body += chunk;

    try {
      const { title } = JSON.parse(body);
      const todo = { id: todos.length + 1, title, done: false };
      todos.push(todo);
      res.writeHead(201, { "Content-Type": "application/json" });
      return res.end(JSON.stringify(todo));
    } catch {
      res.writeHead(400, { "Content-Type": "application/json" });
      return res.end(JSON.stringify({ error: "Invalid JSON" }));
    }
  }

  res.writeHead(404, { "Content-Type": "application/json" });
  res.end(JSON.stringify({ error: "Not found" }));
});

server.listen(3000, () => console.log("Listening on http://localhost:3000"));
```

测试：

```bash
curl http://localhost:3000/todos
curl -X POST http://localhost:3000/todos \
  -H "Content-Type: application/json" \
  -d '{"title":"Write code"}'
```

可以看到，路由、请求体解析和错误处理都要手动完成，工作量不小。这正是 Express 要解决的问题。

## 7. Express：构建 REST API

**概念：** Express 提供路由和中间件。中间件是一个在路由之前运行的函数，它可以读取或修改请求、直接返回响应，或者调用 `next()` 把控制权交给下一个处理者。

安装：

```bash
npm install express
```

`server.js`：

```js
import express from "express";

const app = express();
app.use(express.json()); // 解析 JSON 请求体

// 自定义中间件：记录每个请求
app.use((req, res, next) => {
  console.log(`${req.method} ${req.url}`);
  next();
});

let todos = [{ id: 1, title: "Learn Express", done: false }];
let nextId = 2;

// 查询全部
app.get("/todos", (req, res) => {
  res.json(todos);
});

// 查询单个
app.get("/todos/:id", (req, res) => {
  const todo = todos.find((t) => t.id === Number(req.params.id));
  if (!todo) return res.status(404).json({ error: "Todo not found" });
  res.json(todo);
});

// 创建
app.post("/todos", (req, res) => {
  const { title } = req.body;
  if (typeof title !== "string" || title.trim() === "") {
    return res.status(400).json({ error: "title is required" });
  }
  const todo = { id: nextId++, title: title.trim(), done: false };
  todos.push(todo);
  res.status(201).json(todo);
});

// 更新
app.patch("/todos/:id", (req, res) => {
  const todo = todos.find((t) => t.id === Number(req.params.id));
  if (!todo) return res.status(404).json({ error: "Todo not found" });

  if (req.body.title !== undefined) todo.title = req.body.title;
  if (req.body.done !== undefined) todo.done = Boolean(req.body.done);
  res.json(todo);
});

// 删除
app.delete("/todos/:id", (req, res) => {
  const before = todos.length;
  todos = todos.filter((t) => t.id !== Number(req.params.id));
  if (todos.length === before) {
    return res.status(404).json({ error: "Todo not found" });
  }
  res.status(204).end();
});

// 未知路由返回 404
app.use((req, res) => {
  res.status(404).json({ error: "Route not found" });
});

// 统一错误处理（必须有 4 个参数）
app.use((err, req, res, next) => {
  console.error(err);
  res.status(500).json({ error: "Something went wrong" });
});

const port = process.env.PORT || 3000;
app.listen(port, () => console.log(`API running on port ${port}`));
```

**需要记住的 HTTP 方法和状态码**

| 操作 | 方法 | 成功状态码 |
| --- | --- | --- |
| 列表或读取 | GET | 200 |
| 创建 | POST | 201 |
| 更新 | PATCH 或 PUT | 200 |
| 删除 | DELETE | 204 |
| 输入有误 | 任意 | 400 |
| 未找到 | 任意 | 404 |
| 服务器错误 | 任意 | 500 |

### Express 中的异步错误

在 Express 5 中，`async` 处理函数里抛出的错误会自动交给错误处理中间件。在 Express 4 中需要手动包装：

```js
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get("/users/:id", asyncHandler(async (req, res) => {
  const user = await findUser(req.params.id); // 如果抛出错误，会进入错误处理器
  res.json(user);
}));
```

### 用路由器组织代码

`routes/todos.js`：

```js
import { Router } from "express";

const router = Router();

router.get("/", (req, res) => res.json([]));
router.post("/", (req, res) => res.status(201).json(req.body));

export default router;
```

在 `server.js` 中：

```js
import todosRouter from "./routes/todos.js";
app.use("/todos", todosRouter);
```

## 9. 用 Worker 线程处理 CPU 密集任务

**概念：** Node 只有一个主线程，所以繁重的计算会阻塞所有请求。Worker 线程可以把这类工作放到另一个线程并行运行。

`worker.js`：

```js
import { parentPort, workerData } from "node:worker_threads";

function fib(n) {
  return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

parentPort.postMessage(fib(workerData));
```

`main.js`：

```js
import { Worker } from "node:worker_threads";

function runFib(n) {
  return new Promise((resolve, reject) => {
    const worker = new Worker(new URL("./worker.js", import.meta.url), {
      workerData: n,
    });
    worker.on("message", resolve);
    worker.on("error", reject);
  });
}

console.log("开始计算...");
const result = await runFib(40);
console.log("结果:", result);
```

Worker 适合 CPU 密集型工作（图像处理、哈希、解析）。它不能加速 I/O，因为 I/O 本来就是非阻塞的。

## 11. 优雅关闭与进程错误

**概念：** 在生产环境中，服务器会经常被停止和重启。要干净地关闭连接，避免丢失正在处理的请求。

```js
import http from "node:http";

const server = http.createServer((req, res) => res.end("ok"));
server.listen(3000);

function shutdown(signal) {
  console.log(`${signal} received, closing server...`);
  server.close(() => {
    console.log("Closed. Bye.");
    process.exit(0);
  });
  // 如果耗时太久，强制退出
  setTimeout(() => process.exit(1), 10_000).unref();
}

process.on("SIGTERM", () => shutdown("SIGTERM"));
process.on("SIGINT", () => shutdown("SIGINT"));

process.on("unhandledRejection", (reason) => {
  console.error("Unhandled rejection:", reason);
  process.exit(1);
});
```

## 12. 数据库

**概念：** 服务器重启后，内存中的数据就会丢失。数据库可以永久保存数据，并支持高效查询。先学 SQL（PostgreSQL 是最佳默认选择），再学文档数据库和缓存。

### 必须掌握的 SQL 基础

```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'user',
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_posts_user_id ON posts(user_id);

-- 连接查询：文章及其作者邮箱
SELECT p.id, p.title, u.email
FROM posts p
JOIN users u ON u.id = p.user_id
WHERE p.created_at > now() - interval '7 days'
ORDER BY p.created_at DESC
LIMIT 20;
```

**记住：** 主键标识每一行，外键连接表，索引加快读取（但会略微减慢写入），约束保护数据完整性。

### 在 Node 中使用 PostgreSQL

```bash
npm install pg
```

`db.js`：

```js
import pg from "pg";

export const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 10, // 连接池最大连接数
});

export async function query(text, params) {
  const result = await pool.query(text, params);
  return result.rows;
}
```

**一定要使用参数（`$1`、`$2`）。** 永远不要把用户输入直接拼接进 SQL，这就是 SQL 注入的来源。

```js
import { query } from "./db.js";

// 安全
const rows = await query("SELECT * FROM users WHERE email = $1", [email]);

// 危险：绝对不要这样写
// await query(`SELECT * FROM users WHERE email = '${email}'`);
```

### 事务

当多条语句必须一起成功或一起失败时，使用事务。

```js
import { pool } from "./db.js";

export async function transfer(fromId, toId, amount) {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    await client.query(
      "UPDATE accounts SET balance = balance - $1 WHERE id = $2",
      [amount, fromId]
    );
    await client.query(
      "UPDATE accounts SET balance = balance + $1 WHERE id = $2",
      [amount, toId]
    );
    await client.query("COMMIT");
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release(); // 一定要把连接还给连接池
  }
}
```

### Repository 层

不要把 SQL 写在路由处理函数里。

```js
// repositories/posts.js
import { query } from "../db.js";

export const postsRepo = {
  list: (limit = 20, offset = 0) =>
    query("SELECT * FROM posts ORDER BY id DESC LIMIT $1 OFFSET $2", [limit, offset]),

  findById: async (id) => {
    const rows = await query("SELECT * FROM posts WHERE id = $1", [id]);
    return rows[0] ?? null;
  },

  create: async ({ userId, title, body }) => {
    const rows = await query(
      "INSERT INTO posts (user_id, title, body) VALUES ($1, $2, $3) RETURNING *",

    );

  },

  remove: (id) => query("DELETE FROM posts WHERE id = $1", [id]),
};
```

### 注册与登录

```js
import bcrypt from "bcrypt";
import jwt from "jsonwebtoken";
import { query } from "../db.js";
import { AppError } from "../utils/errors.js";

const JWT_SECRET = process.env.JWT_SECRET;

export async function register(email, password) {
  const hash = await bcrypt.hash(password, 12); // 永远不要明文存储密码
  try {
    const rows = await query(
      "INSERT INTO users (email, password_hash) VALUES ($1, $2) RETURNING id, email, role",
      [email, hash]
    );
    return rows[0];
  } catch (err) {
    if (err.code === "23505") throw new AppError("Email already used", 409, "EMAIL_TAKEN");
    throw err;
  }
}

export async function login(email, password) {
  const [user] = await query("SELECT * FROM users WHERE email = $1", [email]);
  const ok = user && (await bcrypt.compare(password, user.password_hash));
  if (!ok) throw new AppError("Invalid email or password", 401, "BAD_CREDENTIALS");

  const token = jwt.sign({ sub: user.id, role: user.role }, JWT_SECRET, {
    expiresIn: "15m",
  });
  return { token };
}
```

对“邮箱不存在”和“密码错误”使用相同的提示。不同的提示会让攻击者发现哪些邮箱已注册。

### 认证中间件与角色检查

```js
import jwt from "jsonwebtoken";
import { AppError } from "../utils/errors.js";

export function requireAuth(req, res, next) {
  const header = req.headers.authorization || "";
  const [scheme, token] = header.split(" ");
  if (scheme !== "Bearer" || !token) {
    return next(new AppError("Missing token", 401, "NO_TOKEN"));
  }
  try {
    const payload = jwt.verify(token, process.env.JWT_SECRET);
    req.user = { id: payload.sub, role: payload.role };
    next();
  } catch {
    next(new AppError("Invalid or expired token", 401, "BAD_TOKEN"));
  }
}

export const requireRole = (...roles) => (req, res, next) => {
  if (!roles.includes(req.user.role)) {
    return next(new AppError("Forbidden", 403, "FORBIDDEN"));
  }
  next();
};
```

```js
app.get("/me", requireAuth, (req, res) => res.json(req.user));
app.delete("/users/:id", requireAuth, requireRole("admin"), deleteUserHandler);
```

### Token 策略简介

| Token | 有效期 | 存放位置 |
| --- | --- | --- |
| 访问令牌（JWT） | 5-15 分钟 | 内存或 `Authorization` 请求头 |

## 15. 安全要点

**概念：** 大多数安全事故都源于一小撮众所周知的错误。把下面这些默认做法用到每个项目里。



### 安全检查清单

- [ ] 密码使用 bcrypt 或 argon2 哈希
- [ ] SQL 查询全部参数化
- [ ] 所有输入都经过验证（请求体、查询参数、路径参数、请求头）
- [ ] 密钥只放在环境变量中，绝不提交到 Git
- [ ] 全站使用 HTTPS；Cookie 设置 `HttpOnly`、`Secure`、`SameSite`
- [ ] 登录和公开接口设置了限流
- [ ] 每个受保护路由都做了授权检查，包括所有权
- [ ] 错误响应不暴露堆栈信息或 SQL
- [ ] 定期运行 `npm audit` 并保持依赖更新
- [ ] 日志中不包含密码、令牌或完整银行卡号

```ts
// todos/todos.service.ts  （provider：业务逻辑）
import { Injectable, NotFoundException } from "@nestjs/common";

@Injectable()
export class TodosService {
  private todos: { id: number; title: string; done: boolean }[] = [];
  private nextId = 1;

  findAll() {
    return this.todos;
  }

  findOne(id: number) {
    const todo = this.todos.find((t) => t.id === id);
    if (!todo) throw new NotFoundException(`Todo ${id} not found`);
    return todo;
  }

  create(title: string) {
    const todo = { id: this.nextId++, title, done: false };
    this.todos.push(todo);
    return todo;
  }
}
```

## 20. 使用 WebSocket 实现实时通信

**概念：** HTTP 是“请求—响应”模式。WebSocket 会保持连接打开，服务器可以随时主动推送数据（聊天、实时仪表盘、游戏）。

```js
import { createServer } from "node:http";
import { Server } from "socket.io";

const httpServer = createServer();
const io = new Server(httpServer, { cors: { origin: "http://localhost:5173" } });

io.on("connection", (socket) => {
  console.log("connected:", socket.id);

  socket.on("join", (room) => {
    socket.join(room);
    socket.to(room).emit("system", `${socket.id} joined ${room}`);

  socket.on("message", ({ room, text }) => {
    io.to(room).emit("message", { from: socket.id, text, at: Date.now() });
  });

  socket.on("disconnect", () => console.log("disconnected:", socket.id));
});

httpServer.listen(3001);
```

```js
socket.emit("message", { room: "general", text: "Hello everyone" });
```

**生产环境注意事项：** 要对连接做认证（例如在 `io.use(...)` 中间件里检查令牌）。运行多个服务器实例时，要添加共享适配器（如 Redis adapter），这样消息才能到达连接在其他实例上的用户。

## 21. GraphQL（概览）

**概念：** 使用 GraphQL 时，客户端通过单一接口精确请求自己需要的字段。它减少了过度获取数据，适合有多种客户端的应用。

```bash
npm install graphql graphql-yoga
```

```js
import { createServer } from "node:http";
import { createYoga, createSchema } from "graphql-yoga";

const posts = [
  { id: "1", title: "Hello GraphQL", authorId: "10" },
  { id: "2", title: "Node is great", authorId: "10" },
];
const authors = { "10": { id: "10", name: "Ada" } };

const schema = createSchema({
  typeDefs: /* GraphQL */ `
    type Author { id: ID!, name: String! }
    type Post { id: ID!, title: String!, author: Author! }
    type Query {
      posts: [Post!]!
      post(id: ID!): Post
    }
    type Mutation {
      addPost(title: String!, authorId: ID!): Post!
    }
  `,
  resolvers: {
    Query: {
      posts: () => posts,
      post: (_, { id }) => posts.find((p) => p.id === id) ?? null,
    },
    Mutation: {
      addPost: (_, { title, authorId }) => {
        const post = { id: String(posts.length + 1), title, authorId };
        posts.push(post);
        return post;
      },
    },
    Post: {
      author: (post) => authors[post.authorId], // 只有被请求时才会解析
    },
  },
});

createServer(createYoga({ schema })).listen(4000);
```

查询示例：

```graphql
query {
  posts {
    title
    author { name }
  }
}
```

**注意 N+1 问题：** 像 `Post.author` 这样的 resolver 如果每次都查数据库，就会产生 N+1。请使用 DataLoader 之类的批处理工具。

## 22. 后台任务与队列

**概念：** 不要让用户等待耗时的工作（发邮件、缩放图片、生成报表）。把任务放进队列，让独立的 worker 去处理。

```bash
npm install bullmq
```

`queue.js`（生产者）：

```js
import { Queue } from "bullmq";

const connection = { host: "127.0.0.1", port: 6379 };
export const emailQueue = new Queue("emails", { connection });

// 在请求处理函数中
await emailQueue.add(
  "welcome",
  { to: "user@example.com" },
  { attempts: 3, backoff: { type: "exponential", delay: 2000 } }
);
```

`worker.js`（消费者，作为独立进程运行）：

```js
import { Worker } from "bullmq";

const connection = { host: "127.0.0.1", port: 6379 };

const worker = new Worker(
  "emails",
  async (job) => {
    console.log(`Sending ${job.name} email to ${job.data.to}`);
    // await sendEmail(job.data.to) ...
  },
  { connection, concurrency: 5 }
);

worker.on("completed", (job) => console.log(`Job ${job.id} done`));
worker.on("failed", (job, err) => console.error(`Job ${job?.id} failed:`, err.message));
```

**设计规则：** 任务可能因为重试而运行多次，所以要保证它们是**幂等**的：运行两次不能导致重复扣款或重复发送。

## 23. 日志与可观测性

**概念：** 在生产环境中你无法附加调试器。日志、指标和链路追踪是你了解应用运行状况的方式。

```bash
npm install pino pino-http
```

```js
import pino from "pino";
import pinoHttp from "pino-http";

export const logger = pino({
  level: process.env.LOG_LEVEL || "info",
  redact: ["req.headers.authorization", "*.password"], // 绝不记录敏感信息
});

app.use(pinoHttp({ logger })); // 以 JSON 记录每个请求及耗时

logger.info({ userId: 42, action: "login" }, "user logged in");
logger.error({ err }, "payment failed");
```

**日志规则**

- 记录**结构化 JSON**，而不是随意的字符串，方便工具检索。
- 正确使用级别：`error`（需要处理）、`warn`（异常但已处理）、`info`（关键事件）、`debug`（开发细节）。
- 给每条日志附加**请求 ID**，这样才能跨服务追踪同一个请求。
- 为负载均衡器添加健康检查接口：

```js
app.get("/health", async (req, res) => {
  try {
    await pool.query("SELECT 1");
    res.json({ status: "ok" });
  } catch {
    res.status(503).json({ status: "database_unavailable" });
  }
});
```

想获得更深入的可见性，可以添加指标（Prometheus 和 Grafana）、分布式追踪（OpenTelemetry）和错误追踪（Sentry）。

## 24. 端到端测试 API

**概念：** 单元测试检查小函数。集成测试调用真实的路由，验证整个流程，包括验证逻辑和数据库。

```bash
npm install -D supertest
```

`app.js` 必须导出 app，且不要调用 `listen`：

```js
// app.js
import express from "express";
export const app = express();
app.use(express.json());
app.post("/todos", (req, res) => {
  if (!req.body.title) return res.status(400).json({ error: "title is required" });
  res.status(201).json({ id: 1, title: req.body.title });
});
```

```js
// app.test.js
import { test, describe } from "node:test";
import assert from "node:assert/strict";
import request from "supertest";
import { app } from "./app.js";

describe("POST /todos", () => {
  test("creates a todo", async () => {
    const res = await request(app).post("/todos").send({ title: "Test" });
    assert.equal(res.status, 201);
    assert.equal(res.body.title, "Test");
  });

  test("rejects missing title", async () => {
    const res = await request(app).post("/todos").send({});
    assert.equal(res.status, 400);
  });
});
```

### Mock（模拟）

```js
import { mock, test } from "node:test";
import assert from "node:assert/strict";

test("calls the email sender once", async () => {
  const sendEmail = mock.fn(async () => true);

  await registerUser({ email: "a@b.com" }, { sendEmail }); // 依赖通过参数传入

  assert.equal(sendEmail.mock.callCount(), 1);
});
```

**测试建议**

- 把依赖作为参数传入，这样就能用假对象替换它们。
- 使用独立的测试数据库，并在每个测试之间重置。
- 测试不顺利的路径：错误输入、缺少认证、资源不存在。
- 追求的是信心，而不是覆盖率数字。

**概念：** 容器把你的应用和它精确的运行环境打包在一起，因此在你的笔记本、CI 和生产环境中运行结果一致。

## 26. 使用 GitHub Actions 实现 CI/CD

## 27. 性能与 Node.js 内部机制

**概念：** Node 处理 I/O 很快，但只有一个主线程。性能优化的本质，就是让这个线程保持空闲，并合理使用资源。

### 事件循环的执行顺序

```js
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
process.nextTick(() => console.log("nextTick"));
Promise.resolve().then(() => console.log("promise"));
console.log("sync");
// sync、nextTick、promise，然后是 timeout/immediate
```

需要记住的顺序：同步代码，然后是 `process.nextTick`，然后是 Promise 微任务，最后才是事件循环各阶段（定时器、I/O 回调、`setImmediate`）。

### 用 cluster 使用所有 CPU 核心

```js
import cluster from "node:cluster";
import { availableParallelism } from "node:os";
import http from "node:http";

if (cluster.isPrimary) {
  const count = availableParallelism();
  for (let i = 0; i < count; i++) cluster.fork();

  cluster.on("exit", (worker) => {
    console.log(`worker ${worker.process.pid} died, starting a new one`);
    cluster.fork();
  });
} else {
  http
    .createServer((req, res) => res.end(`handled by ${process.pid}\n`))
    .listen(3000);
}
```

在容器环境中，许多团队改为每个容器只运行一个进程，由编排系统来扩展容器数量。

### 先测量，再优化

```bash
# 压力测试
npx autocannon -c 100 -d 20 http://localhost:3000/posts

# CPU 分析：运行后，用 Chrome DevTools 打开生成的文件
node --cpu-prof server.js

# 用调试器检查
node --inspect server.js
```

### 典型的内存泄漏

```js
const cache = {}; // 会无限增长

app.get("/user/:id", async (req, res) => {
  cache[req.params.id] = await loadUser(req.params.id); // 从不清除
  res.json(cache[req.params.id]);
});
```

解决办法：使用有上限的缓存（限制最大条目数的 LRU 缓存）或 TTL（过期时间）。还要留意被遗忘的定时器、每个请求都添加的监听器，以及占用大量内存的闭包。

### 性能检查清单

- [ ] 请求处理函数中没有同步的文件或加密调用
- [ ] 数据库查询使用索引，没有 N+1 模式
- [ ] 响应已分页；大数据用流传输
- [ ] 高频读取使用带过期时间的缓存
- [ ] CPU 密集型工作运行在 worker 线程或队列中
- [ ] 连接池大小设置合理
- [ ] 文本响应启用了压缩
- [ ] 每次优化前后都做了测量

## 28. 架构模式

**概念：** 好的架构能让代码在增长过程中仍然易于修改。目标是关注点分离：每个部分只负责一件事。

### 分层

| 层 | 职责 | 了解的内容 |
| --- | --- | --- |
| 路由 / 控制器 | 解析请求，调用 service，返回响应 | HTTP |
| Service（服务层） | 业务规则 | 领域概念 |
| Repository（仓储层） | 读写数据 | 数据库 |

### 不用框架也能做依赖注入

```js
// service 接收自己需要的依赖，而不是自己去导入
export function createPostsService({ postsRepo, cache, logger }) {
  return {
    async get(id) {
      const cached = await cache.get(`post:${id}`);
      if (cached) return cached;

      const post = await postsRepo.findById(id);
      if (!post) throw new NotFoundError("Post");

      await cache.set(`post:${id}`, post);
      logger.debug({ id }, "post loaded from database");
      return post;
    },
  };
}

// 在启动时一次性完成组装
const postsService = createPostsService({ postsRepo, cache, logger });
```

这样测试会很容易：传入假的 repository 和 cache 即可。

### 常用设计模式

| 模式 | 适用场景 |
| --- | --- |
| Repository | 想隐藏数据库细节 |
| Factory（工厂） | 对象创建有多种变体 |
| Strategy（策略） | 需要替换算法（支付渠道、存储后端） |
| Observer（观察者，事件） | 多个部分需要响应同一件事 |
| Adapter（适配器） | 把第三方 API 包装成自己的接口 |

### 先做单体

先从**模块化单体**开始：一个可部署的应用，内部有清晰的模块划分。只有在有具体理由时（独立扩展、独立团队、不同的发布节奏）才拆分成微服务，因为微服务会带来网络故障、部署复杂度和调试成本。

### API 设计规则

- 资源用名词（`/posts`、`/posts/:id/comments`），动作用 HTTP 方法表达。
- 返回一致的错误结构：`{ error, code, details? }`。
- 必须破坏兼容性时再做版本化（`/v1/...`）。
- 对可能被重试的 `POST` 操作，用幂等键保证**幂等**。
- 用 OpenAPI 编写 API 文档。
