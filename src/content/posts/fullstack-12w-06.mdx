## 本周目标

- 定下一套 REST 风格约定（资源命名、状态码、错误体）。
- 统一分页/过滤/排序参数格式。
- 用 `@nestjs/swagger` 生成 OpenAPI 文档。
- 设计 API 版本化策略（`/v1`）。

## 核心概念速记（详文 →）

- 后端面试（含 API 设计取舍）：[/blog/posts/interview-guide-11-backend/](/blog/posts/interview-guide-11-backend/)

**记忆锚点**：

- 分页三件套：`page`/`pageSize` 或 `cursor`；过滤用统一 query 前缀；排序 `sort=field:desc`。
- 版本化不是"加个 v1 就完事"，要想清楚"旧版本如何共存与退休"。
- Swagger 不是文档负担，是前后端契约——改接口先改注解。

## 落到我项目的动作

- 写一份内部 API 规范 markdown（可直接进 NoteLab 文档库）。

## 本周交付物（可见）

- Swagger 文档（本地可访问）+ 一份 API 规范文档，提交。

## 面试一句话

"API 设计的核心是契约稳定与向前兼容；版本化让我能改接口而不破坏已有前端，退休旧版本要有明确时间表。"

## 易错点 / 记忆锚点

- 别用 `200` 包所有错误；该 `400`/`401`/`403`/`404`/`409` 就用，前端才能正确分支。
- `PUT` vs `PATCH`：整体替换 vs 局部更新，语义乱用会让缓存和幂等出问题。

## 练习

1. 给现有接口补 `@ApiProperty` 注解，跑出 Swagger。
2. 写一份 10 条以内的 API 规范（命名、分页、错误码、版本化）。
3. 设计"给一个接口加必填字段"的兼容方案，保证旧前端不崩。
