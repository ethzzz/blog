> [!NOTE]
> 哈希表的核心思想就一句话：**用 O(n) 空间换 O(1) 查找**。看到"找配对""数次数""判重复""缓存"，第一反应就该是它。这篇除了题，还会讲清 JS 里到底该用 `Map`、对象还是 `Set`。

---

## 1. 先选对容器：Map / 对象 / Set

| 容器 | 键类型 | 顺序 | 原型污染 | 适合 |
| --- | --- | --- | --- | --- |
| `Object` | 字符串 / Symbol（数字会被转字符串） | 整数键升序 + 插入序 | **有**（`__proto__`） | 配置、JSON、固定字段 |
| `Map` | **任意类型**（对象、NaN 都行） | 严格插入序 | 无 | 频繁增删、键是数字/对象 |
| `Set` | 值即键 | 插入序 | 无 | 去重、判存在 |
| 定长数组 | 数字下标 | — | 无 | 字符集固定（26 字母、128 ASCII） |

三个实际影响：

```ts
// ① 对象的键会被转成字符串
const o: Record<number, string> = {};
o[1] = 'a';
o['1'] = 'b';
console.log(o[1]); // 'b' —— 同一个键

// ② 对象有原型链，查 'constructor' 会命中
const m = new Map();
console.log(m.get('constructor'));       // undefined
console.log(({} as any)['constructor']); // [Function: Object]

// ③ Map 的键是引用
const a = { id: 1 };
const map = new Map<object, string>([[a, 'x']]);
console.log(map.get({ id: 1 }));         // undefined —— 不是同一个对象
console.log(map.get(a));                 // 'x'
```

**选型口诀**：键是数字或需要频繁增删 → `Map`；只要去重/判存在 → `Set`；字符集固定 → 数组；要序列化成 JSON → 对象。

## 2. 两数之和：先查后存

暴力是 O(n²)：每个数都和后面的配一次。哈希把它降到 O(n)：

```ts
function twoSum(nums: number[], target: number): number[] {
  const seen = new Map<number, number>(); // 值 → 下标
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need)!, i];
    seen.set(nums[i], i); // 先查后存
  }
  return [];
}
```

**为什么必须"先查后存"**：若先存再查，`target = 6`、`nums = [3, 3]` 时，第一个 3 存入后立刻查到"自己"，返回 `[0, 0]`——同一元素用了两次。先查后存天然避免了自匹配。

### 2.1 家族成员与"换个条件换个解法"

| 题目 | 解法 | 复杂度 | 关键点 |
| --- | --- | --- | --- |
| 1. 两数之和 | 哈希一次遍历 | O(n) / O(n) | 先查后存 |
| 167. 两数之和 II（有序） | 对撞指针 | O(n) / **O(1)** | 有序 → 换方案 |
| 15. 三数之和 | 排序 + 对撞 | O(n²) / O(1) | 三处去重 |
| 128. 最长连续序列 | Set + 起点剪枝 | O(n) / O(n) | 只从起点数 |

面试官给"有序"两个字，就是在提示你"别用哈希，用双指针省空间"。**能主动换方案，比写出来更重要。**

### 2.2 最长连续序列：为什么只从起点数仍是 O(n)

```ts
function longestConsecutive(nums: number[]): number {
  const set = new Set(nums);
  let ans = 0;

  for (const x of set) {
    if (set.has(x - 1)) continue; // 有前驱 → 不是起点，跳过
    let len = 1;
    while (set.has(x + len)) len++;
    ans = Math.max(ans, len);
  }
  return ans;
}
```

复杂度追问的标准回答：**外层每个元素只被看一眼；内层 `while` 只会从"起点"开始，且整条序列的每个元素只被数一次**。所以总操作 ≤ 2n，是 O(n)，不是 O(n²)。

如果去掉 `set.has(x - 1) continue` 这个剪枝，`[1,2,3,...,n]` 会退化成 O(n²)——这是本题唯一的考点。

## 3. 字符统计：三种写法与 key 的取舍

```ts
// ① 对象：最顺手，但键会被转字符串
function charCount(s: string): Record<string, number> {
  const count: Record<string, number> = {};
  for (const ch of s) count[ch] = (count[ch] ?? 0) + 1;
  return count;
}

// ② Map：键保持类型，适合非字符串键
const m = new Map<string, number>();

// ③ 定长数组：字符集固定时最快（26 字母）
const cnt = new Array(26).fill(0);
for (const ch of s) cnt[ch.charCodeAt(0) - 97]++;
```

遍历字符串统计**永远用 `for...of`**：它按码点迭代，`for...in` 走的是下标。

### 3.1 有效的字母异位词

```ts
function isAnagram(s: string, t: string): boolean {
  if (s.length !== t.length) return false;
  const count = new Map<string, number>();
  for (const ch of s) count.set(ch, (count.get(ch) ?? 0) + 1);
  for (const ch of t) {
    const c = count.get(ch);
    if (!c) return false; // 没有 或 已耗尽
    count.set(ch, c - 1);
  }
  return true;
}
```

长度相等 + 每次减法都成功 ⇔ 字符及次数完全一致。

### 3.2 字母异位词分组：用"规范化结果"当 key

```ts
function groupAnagrams(strs: string[]): string[][] {
  const groups = new Map<string, string[]>();
  for (const s of strs) {
    const key = [...s].sort().join(''); // 排序后作为规范形式
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key)!.push(s);
  }
  return [...groups.values()];
}
```

两种 key 的取舍是常见追问：

| key 方案 | 时间 | 空间 | 适用 |
| --- | --- | --- | --- |
| 排序后的字符串 | O(k log k) 每词 | O(k) | 通用、最好写 |
| 26 位计数数组转字符串 | O(k) 每词 | O(1) 额外 | 只有小写字母时更快 |
| 质数乘积 | O(k) | 大数溢出风险 | **不推荐**，长串会溢出 |

```ts
// 计数 key 版本
function groupAnagramsByCount(strs: string[]): string[][] {
  const groups = new Map<string, string[]>();
  for (const s of strs) {
    const cnt = new Array(26).fill(0);
    for (const ch of s) cnt[ch.charCodeAt(0) - 97]++;
    const key = cnt.join('#');
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key)!.push(s);
  }
  return [...groups.values()];
}
```

## 4. 判重复与最长无重复子串

```ts
// 存在重复元素：一行
const hasDuplicate = (nums: number[]): boolean => new Set(nums).size !== nums.length;
```

变体：**存在重复元素 II**（219 题）——要求两个相同元素的下标差不超过 k。这就不只是"判重复"，而是"维护一个大小不超过 k 的窗口"：

```ts
function containsNearbyDuplicate(nums: number[], k: number): boolean {
  const window = new Set<number>();
  for (let i = 0; i < nums.length; i++) {
    if (window.has(nums[i])) return true;
    window.add(nums[i]);
    if (window.size > k) window.delete(nums[i - k]); // 只保留最近 k 个
  }
  return false;
}
```

窗口里永远只有最近 k 个元素，所以命中时下标差必然 ≤ k。**Set 也能维护"有界窗口"，不只是全局去重。**

**最长无重复子串**有两个版本，面试建议直接给 Map 版：

```ts
// 版本 A：Set + 逐个收缩（好理解）
function lengthOfLongestSubstringA(s: string): number {
  const window = new Set<string>();
  let l = 0;
  let ans = 0;
  for (let r = 0; r < s.length; r++) {
    while (window.has(s[r])) {
      window.delete(s[l]);
      l++;
    }
    window.add(s[r]);
    ans = Math.max(ans, r - l + 1);
  }
  return ans;
}

// 版本 B：Map 记最近下标，左边界一步跳到位（推荐）
function lengthOfLongestSubstring(s: string): number {
  const last = new Map<string, number>();
  let l = 0;
  let ans = 0;
  for (let r = 0; r < s.length; r++) {
    const seen = last.get(s[r]);
    if (seen !== undefined && seen >= l) l = seen + 1;
    last.set(s[r], r);
    ans = Math.max(ans, r - l + 1);
  }
  return ans;
}
```

版本 A 的真实复杂度是 O(2n)（每个字符进出窗口各一次），说法上仍是 O(n)；版本 B 的 `l` 只前进，更接近严格线性。**`seen >= l` 这个判断不能省**，否则 `l` 会往回跳。

## 5. 场景题：哈希在前端里的真身

### 5.1 请求去重（并发合并）

```ts
const pending = new Map<string, Promise<unknown>>();

export function onceRequest<T>(key: string, fn: () => Promise<T>): Promise<T> {
  const existing = pending.get(key);
  if (existing) return existing as Promise<T>;

  const p = fn().finally(() => pending.delete(key)); // 成功失败都要清
  pending.set(key, p);
  return p;
}
```

三个细节：`finally` 保证失败也能重试；key 要包含参数（`url + JSON.stringify(body)`）；如果需要"失败后短期不重试"，把 `finally` 换成 `catch` 后再决定是否删除。

### 5.2 LRU 缓存

```ts
class LRUCache {
  private map = new Map<number, number>();

  constructor(private readonly cap: number) {}

  get(key: number): number {
    const val = this.map.get(key);
    if (val === undefined) return -1;
    this.map.delete(key);
    this.map.set(key, val); // 删了再插 = 移到最新
    return val;
  }

  put(key: number, value: number): void {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.cap) {
      // Map 的第一个 key 就是最久未使用
      this.map.delete(this.map.keys().next().value as number);
    }
  }
}
```

`Map` 的迭代顺序 = 插入顺序，所以"删了再插"就是把元素移到队尾。手写双向链表版本是 O(1) 严格保证，但代码量翻三倍；面试里能说清"Map 版依赖插入顺序，链表版不依赖语言特性"就够了。

## 6. 哈希冲突：被追问时的标准回答

哈希表不是"真的 O(1)"，平均 O(1)、最坏 O(n)（全部冲突）。

| 冲突处理 | 做法 | 特点 |
| --- | --- | --- |
| 拉链法 | 每个桶挂一个链表/树 | 实现简单；Java HashMap 在链表过长时转红黑树 |
| 开放寻址 | 冲突了就往后找空位 | 缓存友好；删除需要墓碑标记 |

JS 的 `Map` 由引擎实现（V8 用哈希表 + 有序索引），你**不需要关心实现细节**，但要知道两点：键的比较用 SameValueZero（`NaN` 等于 `NaN`），对象按引用比较。这两条决定了你在算法题里能不能把对象当键。

## 7. 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| 两数之和返回 `[i, i]` | 先存后查，用了自己 | 先查后存 |
| 三数之和超时 | 用哈希做三数 | 排序 + 对撞，O(n²) |
| 最长连续序列超时 | 没做起点剪枝 | `set.has(x-1)` 就跳过 |
| 异位词分组 key 冲突 | 用质数乘积，长串溢出 | 排序串或计数数组 |
| 对象当键取不到 | 对象按引用比较 | 用 id 字符串当键，或 WeakMap |
| 最长子串答案偏大 | `l` 回跳 | `seen >= l` 才更新 |
| 请求去重后永远失败 | `finally` 写在 `then` 里没清 | 用 `.finally()` 统一清理 |
| LRU 淘汰错元素 | 用对象存，顺序不可靠 | 用 `Map` 的插入顺序 |

---

## 8. 小结

- 容器选择：数字键/频繁增删用 `Map`，去重用 `Set`，固定字符集用数组，要序列化用对象。
- 两数之和：先查后存；有序版本换对撞指针。
- 最长连续序列：起点剪枝，总操作 ≤ 2n。
- 异位词分组：用规范化结果当 key（排序串或计数数组）。
- LRU：Map 的插入顺序是 JS 的福利，但要知道链表版的存在。
