## 自我介绍

### Q1: 请做一个自我介绍 ⭐ 🔥

**万能结构（1.5-2 分钟）：**

```
【身份标签】+【核心经历】+【技术亮点】+【为什么来这里】

模板：
"面试官好，我是 XXX，X 年前端开发经验，目前在 XX 公司担任 XX。

【经历】主要负责过 XX 类型的项目，比如 XXX（一句话概括业务），
       团队规模 X 人，我负责 XX 模块。

【亮点】技术栈以 Vue/React 为主，最近在深入研究 XX 方向（如低代码/
       性能优化/微前端），主导过 XXX 项目，把 XXX 指标从 A 提升到 B。

【动机】看到贵公司在 XX 领域的产品，我很有兴趣，希望能有机会
       在这里做出更多有价值的产品。"
```

**注意事项：**
- ❌ 不要背简历（面试官已经在看了）
- ❌ 不要说家庭、爱好、性格（除非被问）
- ❌ 不要超过 3 分钟（超时被打断很尴尬）
- ✅ 有量化数据（性能提升 X%、支持 X 万用户）
- ✅ 有技术亮点（1-2 个能展开深挖的点）
- ✅ 提前根据 JD 定制（关键词对齐）

**6 年经验者示例：**

> "面试官好，我是张三，6 年前端开发经验，目前在 XX 科技做高级前端。
>
> 我主要负责公司核心 SaaS 产品的前端架构和团队技术建设。之前主导过管理后台从 Vue2 + Element UI 迁移到 Vue3 + Vite + TypeScript 的项目，把首屏时间从 4.2s 优化到 1.5s，构建时间从 3 分钟降到 20 秒。
>
> 最近一年我在做前端基建方向，搭建了公司的组件库（80+ 组件，20+ 项目在用）、监控平台（错误率下降 60%）和低代码平台（运营配置活动页效率提升 5 倍）。技术栈以 Vue/React 双栈为主，也在推动 Monorepo 和微前端落地。
>
> 关注贵公司的产品很久了，特别是 XX 产品的技术挑战很吸引我，希望能有机会加入。"

## 项目介绍

### Q2: 介绍一个你最有成就感的项目 ⭐⭐⭐ 🔥

**STAR 法则（必背）：**

```
S (Situation) 情境：项目背景、业务价值、团队规模
T (Task)      任务：你负责什么、要解决什么问题
A (Action)    行动：你做了什么（技术方案 + 权衡 + 落地）
R (Result)    结果：量化数据（性能、效率、业务指标）
```

**示例（性能优化项目）：**

> **【S】** "去年公司 SaaS 产品的用户量从 1 万涨到 10 万，客户投诉页面加载慢、操作卡顿，续费率下滑了 8%。
>
> **【T】** 我作为前端负责人，主导整个产品的性能优化专项，目标是首屏 LCP 从 6.8s 降到 2.5s 以内，交互卡顿彻底消除。
>
> **【A】** 我先做了全面的性能诊断：用 Lighthouse + Performance 面板 + 自建 RUM 平台，定位到三大瓶颈：
> 1. 主包 3.2MB，echarts/moment/lodash 全量引入
> 2. 报表页串行请求 4 个接口，等待时间长
> 3. 表格一次渲染 5000 行 DOM，滚动掉帧
>
> 对应的方案：
> - echarts 按需注册组件，moment 换 dayjs，lodash 换 lodash-es，主包减到 780KB
> - 路由级代码分割 + Vite manualChunks 拆包 + Gzip + CDN
> - 推动后端做 BFF 聚合接口，前端 Promise.all 并行请求
> - 表格用虚拟列表，只渲染可视区 30 行
> - 建立前端性能监控看板，CI 加 bundlesize 检查防止退化
>
> **【R】** 上线一个月后：
> - LCP：6.8s → 1.9s（下降 72%）
> - INP：600ms → 80ms
> - 客诉工单减少 70%，续费率回升到 85%
> - 沉淀了团队的性能优化 checklist，后续项目直接复用"

**加分技巧：**
1. **有数据**：不说"提升性能"，说"LCP 从 6.8s 降到 1.9s"
2. **有权衡**：不说"我用了 X"，说"考虑过 A、B，最终选 X 因为..."
3. **有反思**：主动说"这个项目最大的教训是..."
4. **有沉淀**：优化后形成的规范、工具、文档、脚手架

### Q3: 项目中最难的技术点是什么？如何解决的？⭐⭐⭐ 🔥

**回答结构：**

```
【背景】为什么难（技术挑战 or 业务复杂度 or 团队协调）
【尝试】第一版方案是什么、为什么不 work
【突破】最终的方案 + 关键技术点
【验证】如何证明解决了（数据、监控、用户反馈）
【沉淀】文档/工具/规范
```

**示例（协同编辑难点）：**

> "背景：我们做在线文档时，遇到多人同时编辑冲突问题——A 和 B 同时改一段话，最终结果不可预测。
>
> 一开始我用的是简单的锁机制（编辑时锁定单元格），但用户体验很差，多人协作变成排队。
>
> 后来调研了 Google Docs 的 OT 算法和 Figma 的 CRDT 方案。OT 需要中央服务器严格协调，实现复杂；CRDT 数据结构本身保证一致性，支持离线。综合考虑后选了 Yjs（基于 CRDT），配合 WebSocket 做实时同步。
>
> 关键难点在于 Yjs 与我们自研富文本编辑器的绑定：Yjs 的数据结构是 Y.Text，编辑器是自定义 Schema，需要写双向转换层。最终花了两周搞定，光标同步、离线合并、历史版本都跑通。
>
> 验证：压测 100 人同时编辑一个文档，无冲突、无数据丢失，延迟 <200ms。
>
> 沉淀：写了一份《协同编辑技术方案》文档，在团队内部分享，后来另一个产品线也复用了这套方案。"

## 离职原因

### Q4: 你为什么从上一家公司离职？⭐ 🔥

**核心原则：**
- ❌ **不抱怨前公司、前老板、前同事**（哪怕真的很烂）
- ❌ **不说是为了钱**（哪怕是）
- ✅ **正面表达 + 未来导向**（追求什么，不是逃离什么）

**回答模板（按真实场景选）：**

| 真实原因 | 建议话术 |
|:--|:--|
| 技术成长受限 | "希望接触更大规模/更复杂的技术场景，贵公司在这方面有优势" |
| 业务方向不喜欢 | "对 XX 领域更感兴趣，看到贵公司在 XX 方向的产品非常认可" |
| 团队氛围差 | "希望加入更注重技术分享和工程文化的团队" |
| 加班太严重 | "希望在保持高效产出的同时，有更合理的工作节奏专注技术深度"（慎用） |
| 薪资低 | **不要说！** 说"寻求更符合个人能力和贡献的机会" |
| 公司裁员 | 直接说"公司业务调整，团队被优化，我在这个过程中也重新思考了职业方向" |
| 老板不好 | **绝对不说！** 说"寻求更好的技术导师和成长环境" |

**加分回答：**

> "我在上一家公司待了 3 年，从初级做到高级，负责了核心 SaaS 产品的前端架构，也带过 3 个人的小组，非常感谢公司的培养。选择离开主要是两个原因：
>
> 一是产品进入稳定期，技术挑战变少了，我希望接触更复杂的场景（比如大规模分布式前端架构、AI + 前端方向）；
>
> 二是关注贵公司很久了，特别是 XX 产品在 XX 领域的创新让我很兴奋，希望能在这样的团队里做出更有影响力的产品。"

## 职业规划

### Q5: 你的职业规划是什么？⭐⭐ 🔥

**回答框架（3-5 年）：**

```
【短期 1 年】融入团队 → 熟悉业务 → 独立承担核心模块
【中期 2-3 年】技术专家方向 or 技术管理方向 → 主导项目/技术选型
【长期 3-5 年】成为领域专家 or 技术负责人 → 影响业务方向
```

**示例（技术专家方向）：**

> "短期一年内，我希望快速融入团队，熟悉业务和现有技术栈，独立承担 1-2 个核心模块的开发。
>
> 中期 2-3 年，我想在前端架构方向深耕，比如性能优化、微前端、低代码这些领域，希望能主导一次大的技术升级或架构演进，成为团队里某个方向的技术专家。
>
> 长期 3-5 年，我希望成长为能独当一面的技术负责人，不只是写代码，而是能从业务视角思考技术方案，帮助团队做出更好的产品决策。当然，具体路径也会根据公司发展需要调整。"

**注意事项：**
- ❌ 别说"想创业"（面试官会觉得你不稳定）
- ❌ 别说"想转产品/管理"（除非应聘相应岗位）
- ❌ 别说"没想过"（显得没规划）
- ✅ 规划要和岗位匹配（应聘高级工程师，就说想成为架构师/技术专家）
- ✅ 表达要落地（不说空话"成为大牛"，说具体方向）

## 反问环节

### Q6: 你有什么想问我们的吗？⭐ 🔥

**核心原则：** 一定要问！不问 = 不感兴趣。但也不能问薪资、加班、假期（一面二面阶段）。

**推荐问题（按面试官身份分层）：**

**问技术面试官（一面/二面）：**
1. "团队目前的技术栈和架构是什么样的？未来一年有什么演进计划？"
2. "这个岗位主要会负责哪些模块？团队怎么分工？"
3. "团队目前遇到的最大技术挑战是什么？"
4. "团队的 Code Review、技术规范、上线流程是怎样的？"
5. "如果我入职，前 3 个月您希望我达成什么目标？"

**问技术 Leader / 总监（三面）：**
1. "这个岗位在团队中的定位是什么？未来 1-2 年的发展路径？"
2. "团队的技术文化和工程氛围是怎样的？有没有技术分享、Code Review、开源贡献？"
3. "您觉得团队里做得最好的和最需要改进的分别是什么？"
4. "公司对这个业务方向的长期规划是怎样的？"

**问 HR（HR 面）：**
1. "公司的培训体系和技术职级晋升机制是怎样的？"
2. "团队的规模、构成、汇报关系是怎样的？"
3. "面试流程还有几轮？大概什么时候能有反馈？"
4. **薪资、期权、加班、假期**：HR 面可以问，但要放到最后

**❌ 千万别问：**
- "加班多吗？"（一面二面问 = 直接扣分）
- "有没有对象/单身吗？"（不专业）
- 能百度到的公司基本信息
- 面试表现如何（让面试官尴尬）

## 压力面 / 冲突处理

### Q7: 和产品/后端/设计有分歧怎么办？⭐⭐ 🔥

**回答框架：**

```
1. 先理解对方立场（不是敌对，是共同目标）
2. 用数据和事实说话（不是"我觉得"）
3. 找共同上级或第三方评审（避免死磕）
4. 决定后果断执行（不带着情绪做）
```

**示例回答：**

> "我之前遇到过一个典型案例：产品要求首页加载 20 个模块的内容，我评估后觉得会严重影响性能（首屏可能超过 5s）。
>
> 我没有直接说'这个做不了'，而是先做了两件事：
> 1. 拉了一版原型，实际测了性能数据，用 Lighthouse 报告说明问题
> 2. 找了几个类似产品（比如竞品）的首页设计做对比
>
> 然后和产品沟通：我理解你想让用户看到更多内容的初衷，但数据显示 20 个模块会让首屏慢 3 秒，用户流失率会上升 X%。我提了两个折中方案：
> - 方案 A：首屏保留 8 个核心模块，其他做成 Tab 切换
> - 方案 B：全部保留，但用懒加载 + 骨架屏，视觉上不阻塞
>
> 最后产品选了方案 A，上线后首屏 1.8s，用户停留时长反而提升了。
>
> 我的经验是：分歧不可怕，可怕的是没有数据和替代方案。前端要用专业能力帮产品做更好的决策，而不是简单说'做不了'。"

### Q8: 如果领导给你一个不合理的需求（工期短、任务重），你怎么办？⭐⭐

```
1. 先明确需求边界（是不是真的"不合理"，还是自己评估失误）
2. 拆分优先级：必须做的 / 可以延后的 / 可以砍的
3. 给领导选择题，而不是判断题
   "如果本周上线，只能完成 A + B；如果延到下周，可以完成 A + B + C。您看哪个方案更符合业务节奏？"
4. 明确风险：如果强推，哪些质量指标会打折（测试覆盖率、性能优化）
5. 记录决策：邮件/文档同步，避免后期背锅
6. 执行阶段：拉齐每日进度，遇到问题及时暴露
```

### Q9: 你的缺点是什么？⭐

**核心原则：**
- ❌ 不说假缺点（"我太追求完美了"、"我工作太拼了" —— 面试官内心 OS：滚）
- ❌ 不说真致命伤（"我脾气差"、"我不爱学习"、"我经常迟到"）
- ✅ 说真实但可改进的缺点 + 已经在做的行动

**示例：**

> "我以前有个问题是过于追求技术完美，做一个组件会花很多时间打磨细节，导致进度慢。后来我意识到业务价值优先，现在的做法是：先出 MVP 满足业务，再用业余时间迭代优化。
>
> 另一个是公开表达能力偏弱，之前在团队分享会紧张。我这一年主动承担了 3 次内部分享，还参加了一个技术演讲社群，现在已经好很多了。"

## 薪资谈判

### Q10: 期望薪资是多少？⭐ 🔥

**核心策略：**

```
1. 先反问对方范围（如果 HR 主动问）
   "方便告诉我这个岗位的薪资范围吗？我看看是否匹配。"

2. 报数字要给区间，别给单点
   ❌ "我要 30K"
   ✅ "根据我的经验和市场情况，期望在 30-35K，具体可以根据
       整体 package（期权、奖金、福利）综合考虑"

3. 有底线的自信
   - 底线：目前薪资 × 1.2（低于这个数宁可不来）
   - 期望：目前薪资 × 1.4-1.5（合理涨幅）
   - 理想：目前薪资 × 1.8+（如果技术面评价很高可以争取）

4. 别只看月薪，看总包
   - 月薪 × 12 or 13 or 14（几薪）
   - 期权 / 股票（上市公司看当前价，未上市看估值）
   - 年终奖 / 项目奖金
   - 补贴（餐补、房补、交通、通讯）
   - 五险一金基数（按实际工资还是最低标准？）
   - 年假、病假、产假
   - 加班文化（大小周？996？）

5. 手里有多个 Offer 时
   "我目前有几个 Offer 在谈，其中 X 公司给到 XXK，但贵公司
    是我的第一选择，如果 package 能匹配，我会优先考虑。"
```

**6 年经验薪资参考（一线城市 2026）：**

| 公司类型 | 月薪范围 | 总包 |
|:--|:--|:--|
| 大厂 P6/P7 | 35-55K × 15-16 薪 | 60-100W |
| 独角兽 | 30-45K × 14-15 薪 + 期权 | 50-80W |
| 中型互联网 | 25-40K × 13-14 薪 | 40-60W |
| 传统行业 IT | 20-30K × 13 薪 | 30-45W |

**注意：** 具体数字因城市、行业、公司差异很大，面试前可以在脉脉、看准网、OfferShow 查一下该公司该岗位的行情。

## 团队协作与领导力

### Q11: 你带过新人吗？如何培养？⭐⭐

```
带新人的四个阶段：

1. 入职第一周：环境搭建
   - 准备好开发环境文档（不要口头讲）
   - 指定 Mentor（每天固定 30 分钟答疑）
   - 分配一个小任务（bug 修复 / 简单需求）建立信心

2. 第一月：熟悉业务
   - 参与需求评审、Code Review（先旁听再发言）
   - 承担独立小模块开发
   - 每周一对一 sync，收集困惑和反馈

3. 前三月：独立承担
   - 分配完整需求（从评审到上线）
   - Code Review 严格把关，重点讲"为什么"而不只是"怎么改"
   - 引导写技术文档、总结沉淀

4. 半年后：技术成长
   - 鼓励做技术分享、参与架构讨论
   - 给挑战性任务（性能优化、技术选型）
   - 帮助规划职业发展路径

关键心态：
- 允许犯错（在可控范围内），不要事事亲为
- 多问"你怎么想"，少说"你这样做"
- 及时肯定，具体反馈（不说"做得好"，说"这个方案考虑到了 X 场景，很棒"）
```

### Q12: 如何推动团队做技术改进（比如引入 TypeScript）？⭐⭐⭐

```
技术改革的常见阻力：
- 老代码迁移成本高
- 团队学习曲线
- 短期业务压力大
- 部分成员抵触

推动策略：

1. 数据说话，不做空谈
   ❌ "TS 好，我们应该用"
   ✅ "调研了 3 个业界项目，用 TS 后线上 bug 率下降 40%，
       我们过去半年的 P0 事故中有 60% 是类型问题"

2. 从增量开始，不搞"一次性大爆炸"
   - 新模块强制 TS，老代码保留 JS
   - allowJs: true 共存，逐步迁移
   - 先做工具函数、类型定义（低风险的模块）

3. 建样板工程 + 文档
   - 挑一个中等复杂度模块作为示范
   - 写《TS 迁移手册》《常见类型模式》
   - 团队分享会讲透

4. 拉关键人物背书
   - 先说服技术负责人 / 团队 Leader
   - 找 1-2 个有影响力的同事做首批尝鲜者
   - 用他们的正面反馈带动其他人

5. 提供工具降低成本
   - 配好 ESLint / tsconfig 模板
   - CI 加类型检查（不能通过就不让合）
   - 常见类型的 Snippet / 代码模板

6. 度量效果，持续迭代
   - 三个月后统计 bug 率、开发效率
   - 收集团队反馈，调整规范
   - 沉淀最佳实践
```

## 学习能力与技术热情

### Q13: 你最近在学习什么新技术？⭐

**回答策略：**

```
1. 说真话（面试官可能会深挖）
2. 有系统性（不是"随便看看"，而是"深入实践"）
3. 有输出（写了博客 / 做了 Demo / 用在了项目里）
```

**示例：**

> "最近半年我在深入研究两个方向：
>
> 一是 **AI + 前端**，特别是 LLM 应用开发。我用 Vercel AI SDK + Next.js 做了一个内部工具，让运营可以用自然语言查询数据。技术上研究了 SSE 流式响应、Prompt Engineering、Function Calling。这个项目让部门的数据分析效率提升了 3 倍。
>
> 二是 **Rust + WASM 在前端的应用**。我用 Rust 写了一个图片处理库编译到 WASM，替换掉原来纯 JS 的实现，性能提升了 8 倍。相关的学习笔记我发在了个人博客上（可以顺便秀一下你的博客地址）。
>
> 学习方法上，我习惯'先动手做小项目，再系统看文档，最后写博客总结'，这样印象最深。"

**加分点：**
- 有 GitHub / 博客 / 开源贡献
- 关注具体技术公众号、周刊（阮一峰周刊、字节技术、掘金等）
- 参加技术大会 / Meetup

### Q14: 遇到不会的技术问题怎么办？⭐

```
标准回答（体现方法论）：

1. 官方文档优先（MDN / React 官方 / Vue 官方）
2. 搜索引擎（Google > 百度，英文 > 中文）
3. 社区（Stack Overflow / GitHub Issues / 掘金 / V2EX）
4. AI 工具（ChatGPT / Claude / Copilot，但要验证）
5. 团队同事（先自己查 30 分钟，实在不行再问，问的时候带上"我尝试了什么"）
6. 源码阅读（终极手段，特别是框架 bug）

关键原则：
- 不是"不会就放弃"，而是"不会就查+验证+沉淀"
- 每次解决问题后写文档，避免团队重复踩坑
- 定期回顾，把高频问题变成工具/规范
```

## 面试全流程

### Q15: 完整的面试流程是怎样的？如何准备？⭐⭐

```
中高级前端典型流程：

1. HR 电话沟通（15-30 min）
   - 基本情况、期望薪资、离职原因
   - 目的：初筛，判断是否匹配

2. 技术一面（60 min，同级工程师）
   - 基础知识（HTML/CSS/JS）
   - 手写代码（防抖节流、深拷贝等）
   - 项目细节

3. 技术二面（60 min，技术 Leader）
   - 深入原理（Vue/React 源码、性能优化）
   - 系统设计场景题
   - 项目难点、技术决策

4. 技术三面 / 交叉面（60 min，总监 or 其他团队 Leader）
   - 架构能力、技术视野
   - 团队协作、领导力
   - 职业规划

5. HR 面（30-45 min）
   - 稳定性、性格、期望薪资
   - 家庭情况（合规的公司不会问太多）

6. Offer 沟通
   - 薪资谈判
   - 期权、入职时间
```

**准备清单：**

```
【技术准备】
- 复习本宝典 18 篇文章，特别是标 🔥 的高频题
- 手写代码题练 3 遍以上（14 篇）
- 项目难点整理成 STAR 表述（每个项目准备 2-3 个亮点）
- 系统设计题准备 3-5 个万能模板（17 篇）

【公司调研】
- 公司业务、产品、技术栈
- 面试团队规模、组织架构
- 最近的融资、大事件
- 面试评价（脉脉、看准网）

【个人材料】
- 简历更新（量化数据、STAR 结构）
- 作品集：GitHub / 个人博客 / Demo 站
- 离职证明、学历证明、薪资流水（提前准备）

【面试当天】
- 提前 15 分钟到 / 提前测试视频面试设备
- 带纸笔（现场画架构图很加分）
- 着装整洁（互联网公司不用正装，干净即可）
- 准备一份"反问清单"（Q6）
```

### Q16: 面试中被问到不会的问题怎么办？⭐

```
❌ 千万不要：
- 强行编答案（面试官一深挖就穿帮）
- 直接说"不会"然后沉默（显得没思考）
- 转移话题（明显逃避）

✅ 正确姿势：

1. 承认 + 展示思路
   "这个具体的 API 我没用过，但我理解它可能是解决 XX 问题的，
    如果让我实现，我会从 XX 角度切入……"

2. 类比迁移
   "这个我不熟，但我用过类似的 XX，它的原理是……
    我猜这个技术可能也是类似的思路？"

3. 反问澄清
   "您能具体说下是在什么场景下用吗？我可能理解得不太准确。"
   （有时候面试官会给你提示）

4. 承诺后续
   "这个我确实没深入研究过，面试后我会去补一下。
    不过我之前遇到类似的 XX 问题时是这样解决的……"

关键是：展现你的思考方式和学习能力，而不是死记硬背的知识。
面试官考察的往往不是"你知不知道"，而是"你面对未知怎么应对"。
```

### Q17: 面试挂了如何复盘？⭐⭐

```
每次面试后立即做（趁记忆新鲜）：

1. 记录所有被问到的问题
   - 技术题：题目 + 我的答案 + 标准答案
   - 场景题：题目 + 我的思路 + 更好的思路
   - 软素质题：题目 + 我的回答 + 事后回想的最佳回答

2. 分类归因
   - 知识盲区（没学过）→ 系统学习
   - 表达问题（知道但没说清）→ 练习口述
   - 思路问题（想到但方向错）→ 看别人的思路
   - 紧张/时间不够 → 模拟面试练习

3. 更新面试宝典
   - 新题补进对应的文章
   - 好的答案沉淀成模板

4. 一周后回顾
   - 把新学的知识再复述一遍
   - 类似题目能否举一反三

我的经验：面试 5-10 家之后，会明显感觉题目开始重复。
前 3 家可以当"练手"，心仪的公司放中间或后面。
```

### Q18: 拿到多个 Offer 如何选择？⭐⭐

```
选择维度（按重要性排序）：

1. 业务方向 / 赛道
   - 朝阳行业（AI、新能源、出海）> 夕阳行业
   - 公司主营业务 > 边缘业务部门
   - 有增长空间的领域，个人成长更快

2. 团队和技术氛围
   - 团队规模（10-50 人是最舒服的规模）
   - Leader 背景（技术出身 or 业务出身）
   - 团队做过什么（有没有拿得出手的项目）
   - Code Review、技术分享、开源文化

3. 直属 Leader
   - 面试时的感觉：能不能聊得来
   - 他/她的技术视野、带人风格
   - 一个靠谱的 Leader 能让你 3 年成长翻倍

4. 薪资 Package
   - 现金部分：月薪 × 几薪
   - 长期激励：期权 / 股票（上市公司看现价，未上市打折看）
   - 隐性福利：五险一金基数、餐补房补、年假、体检

5. 工作强度 / 通勤
   - 大小周？996？弹性工作？
   - 通勤时间（每天 >2h 严重影响生活质量）
   - 远程办公支持

6. 公司稳定性
   - 融资轮次 / 现金流（未上市）
   - 财报 / 裁员历史（上市）
   - 业务是否核心（边缘业务容易被砍）

我的建议：
- 3-5 年经验：优先业务方向 + 团队氛围（成长期，选对方向最重要）
- 5-8 年经验：优先 Leader + 技术挑战（要有拿得出手的项目）
- 8 年+：优先业务前景 + 长期激励（考虑股权、期权）
```

## 复习卡片

> [!TIP]
> **软素质面试核心要点**
>
> 1. **自我介绍**：1.5-2 分钟，身份 + 经历 + 亮点 + 动机，有量化数据
> 2. **项目介绍**：STAR 法则，有数据、有权衡、有沉淀
> 3. **技术难点**：背景 → 尝试 → 突破 → 验证 → 沉淀
> 4. **离职原因**：不抱怨前公司，正面表达 + 未来导向
> 5. **职业规划**：3 段式（1 年 / 2-3 年 / 3-5 年），落地不空谈
> 6. **反问环节**：一定要问！技术面试官问技术、HR 面才问薪资
> 7. **冲突处理**：理解对方 → 数据说话 → 折中方案 → 果断执行
> 8. **缺点**：真实 + 可改进 + 已有行动
> 9. **薪资**：给区间不给单点，看总包不只看月薪
> 10. **带新人**：环境 → 业务 → 独立 → 成长，四阶段
> 11. **推动改进**：数据 → 增量 → 样板 → 关键人物 → 工具 → 度量
> 12. **学习能力**：说真话 + 有输出（博客 / GitHub / Demo）
> 13. **不会的题**：承认 + 展示思路 + 类比 + 承诺
> 14. **复盘**：立即记录 + 分类归因 + 更新宝典
> 15. **选 Offer**：业务 > 团队 > Leader > 薪资 > 强度 > 稳定性

---

> [!IMPORTANT]
> **最后的建议**
>
> 面试是双向选择，不是单向审判。你在展示能力的同时，也在评估这家公司是否值得加入。
>
> 保持自信但不傲慢、谦虚但不卑微。技术过硬 + 沟通清晰 + 职业规划明确 = 拿到心仪 Offer 的三大要素。
>
> 祝面试顺利！🎉
