## 泛型的本质：把"类型之间的关系"表达出来

不用泛型时，你只能二选一：

```ts
function firstAny(arr: any[]): any {}        // 关系丢了：进去是 string，出来是 any
function firstStr(arr: string[]): string {}  // 关系保住了，但只能处理 string
```

泛型是把这层关系**参数化**：

```ts
function first<T>(arr: T[]): T {             // 进来 T，出去还是 T
  return arr[0];
}
const a = first([1, 2]);      // number
const b = first(['x']);       // string
```

关键认知：**泛型的价值不是"通用"，而是"关系不丢"**。如果一个类型参数在签名里只出现一次，它就没在表达关系，等于 `any`。

```ts
// ❌ T 只出现一次：没有任何约束作用，调用方随便传
function log<T>(value: T): void { console.log(value); }

// ✅ 正确写法：不需要泛型
function log(value: unknown): void { console.log(value); }
```

这条判断标准能干掉一半"为了显得高级"的泛型。

## 基本形态

```ts
// 函数
function identity<T>(x: T): T { return x; }

// 接口
interface Box<T> { value: T }

// 类型别名
type Pair<A, B> = { first: A; second: B };

// 类
class Stack<T> {
  private items: T[] = [];
  push(item: T) { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
}
```

在 React / Vue 里也随处可见：

```ts
const [state, setState] = useState<User | null>(null);   // 显式指定
const ref = useRef<HTMLDivElement>(null);                // 元素类型约束
```

## 约束 `extends`：把"能做什么"写进类型

不约束的泛型什么都不能干：

```ts
function longest<T>(a: T, b: T): T {
  return a.length >= b.length ? a : b;   // ❌ T 上没有 length
}
```

加约束：

```ts
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;   // ✅
}
longest('abc', 'de');        // string
longest([1, 2], [3]);        // number[]
longest(1, 2);               // ❌ number 没有 length
```

`extends` 在泛型里是**"可赋值给"**的意思，不是继承。常用形态：

| 约束 | 含义 | 场景 |
| --- | --- | --- |
| `T extends object` | 非原始类型 | 只接受对象 |
| `T extends string` | 字符串（含字面量） | 模板字面量类型 |
| `K extends keyof T` | T 的键 | `get(obj, key)` |
| `T extends (...args: any) => any` | 是函数 | 提取返回值 |
| `T extends unknown[]` | 是数组 | 处理列表 |

## 默认值：给"最常用"的类型参数一个兜底

```ts
type ApiResponse<T = unknown, E = Error> =
  | { ok: true; data: T }
  | { ok: false; error: E };

type UserResp = ApiResponse<User>;        // E 默认 Error
type RawResp = ApiResponse;               // T = unknown, E = Error
```

默认值让调用方只在"需要精确"时才写类型参数——**这是让 API 用起来不啰嗦的关键**。

## 推断时机：为什么有时能省、有时必须写

```ts
first([1, 2]);                    // ✅ 从参数推断 T = number
new Stack();                      // ❌ 推断不出 T（没参数），默认 T = unknown
new Stack<number>();              // ✅ 显式给

// 泛型默认值能救这种场景
class Stack<T = unknown> {}
```

三条规律：

1. **从参数位置推断**：最可靠；
2. **从返回值推断**：TS 不做（不做"逆向推断"），必须显式写；
3. **推断不出来时**：落到默认值，没默认值就是 `unknown`。

## 泛型 + 约束的实战：一个类型安全的事件总线

```ts
type Events = {
  'user:login': { userId: string };
  'cart:add': { sku: string; qty: number };
};

class Bus<E extends Record<string, unknown>> {
  private handlers: { [K in keyof E]?: Array<(p: E[K]) => void> } = {};

  on<K extends keyof E>(event: K, handler: (payload: E[K]) => void) {
    (this.handlers[event] ??= []).push(handler);
  }

  emit<K extends keyof E>(event: K, payload: E[K]) {
    this.handlers[event]?.forEach((h) => h(payload));
  }
}

const bus = new Bus<Events>();
bus.emit('cart:add', { sku: 'a', qty: 1 });   // ✅
bus.emit('cart:add', { sku: 'a' });           // ❌ 少 qty
bus.emit('nope', {});                         // ❌ 事件名不存在
```

这段代码把"事件名 → 载荷形状"的关系完整编码进类型，**新增事件只改 `Events` 一处**。

## 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| 泛型参数推不出来，全变 `unknown` | 没有从参数位置提供信息 | 显式写 `<T>`，或加默认值 |
| `T` 上访问属性报"不存在" | 没加约束 | `T extends { id: string }` |
| 泛型函数里 `return null` 报错 | 返回类型被推断成 `T`，不接受 null | 返回类型写 `T \| null` |
| 一个函数 4 个泛型参数 | 想一次解决所有问题 | 拆函数，或用 `satisfies` 约束字面量 |
| 泛型类实例化后类型全 `any` | 用了 `new Stack<any>()` | 去掉 `any`，让推断或默认值生效 |
| 约束写成 `T extends string[]` 却传了元组 | 元组不能赋值给可变数组 | 用 `readonly string[]` 或 `unknown[]` |

## 验收清单

- [ ] 项目里的泛型参数**至少出现两次**（否则删掉换具体类型）
- [ ] 有约束的泛型（`extends`）而不是"裸 T + `as any` 访问属性"
- [ ] 公共 API 的类型参数有合理默认值（调用方不必每次都写）
- [ ] 能说清"为什么返回值位置不能反向推断类型参数"
- [ ] 能读懂 `useState<T>` / `useRef<T>` / `Promise<T>` 的签名结构
- [ ] 至少写过一处"事件名 → 载荷"这类键值联动类型

## 练习

1. **删掉一个无用的泛型**：找一个 `function f<T>(x: T): T` 式的"假泛型"，改成具体类型或 `unknown`，确认调用方代码没变。  
   *自检*：能说明"泛型只在表达关系时才有价值"。
2. **给泛型加约束**：把 `function pluck<T>(obj: T, key: string)` 改成 `K extends keyof T` 的版本，让返回值类型精确。  
   *自检*：调用 `pluck(user, 'name')` 返回 `string`，`pluck(user, 'nope')` 编译报错。
3. **补默认值**：给一个需要 2 个类型参数的接口加默认值，让 80% 的调用只写 1 个。  
   *自检*：能说明默认值降低了 API 的"仪式感成本"。
