> 这是一位写了多年 JS/TS 的前端工程师重学 Java 的路线，不是注解词典。起点是能写条件和循环，终点是独立交付带权限、测试、日志和回滚步骤的任务工单服务 `task-center`。全线 21 篇：00 是地图，01–12 保留基础编号，13–20 是八个工程阶段，每次前进都要留下可执行的证据。

## 一、先跑起来

先证明工具链能工作，再配置 IDE。语言示例统一 **JDK 21**，后端工程统一 **Maven 3.9、Spring Boot 3.5.7、MyBatis Starter 3.0.4**，数据库与缓存使用 MySQL 8.4、Redis 7.4。版本固定便于章节对照，不表示这些版本永远不需要安全更新，真实项目仍需维护受支持的补丁版本。

在终端执行环境检查，Windows 示例默认 Git Bash，IDE 也应选择相同 JDK。

```bash
java -version
javac -version
jshell --version
mvn -v
```

输出：前三项主版本为 21，最后一项 Maven 为 3.9.x，并显示 Java version 为 21。补丁号与供应商允许不同；如果 `java` 是 21、`mvn` 显示 17，先修正 `JAVA_HOME`，IDE 能运行不能证明命令行打包成功。Windows 的 `JAVA_HOME` 指向 JDK 根目录而不是 `bin`，Path 再加入其 `bin` 子目录，重新打开终端后复查。

从 JDK 供应商和 Apache Maven 的官方发行入口选择安装包，不复制来路不明的安装脚本。IDE 可用 IntelliJ IDEA 的免费功能或 VS Code 的 Java 扩展。Java 工程的 Maven 依赖与博客的 npm 依赖无关：在自己的 `task-center` 目录练习，不修改博客依赖。

用 JDK 自带 REPL 验证任务列表。下面整段是终端命令，单引号 heredoc 防止 shell 提前展开内容。

```bash
jshell --feedback concise <<'EOF'
import java.util.List;
record Task(String title, boolean done) {}
var tasks = List.of(new Task("read-java", false), new Task("setup-jdk", true));
System.out.println(tasks.stream().filter(task -> !task.done()).count());
/exit
EOF
```

输出：除 jshell 提示文字外，包含单独的 `1`。两条任务，一条未完成，这是任务中心最小的一次统计。现在只观察结果，`record`、泛型、Stream 会在后续展开；REPL 中定义类型，不等于已经保存磁盘项目代码。

从十二篇开始需要 Docker，届时检查客户端与服务端都能通信。

```bash
docker version
docker compose version
```

输出：第一条同时出现 Client 与 Server，第二条出现 Compose 版本。只有 Client 不算可运行环境，先启动 Docker Desktop 或自己的 Docker Engine。基础阶段不需要数据库，不必因为 Docker 尚未配好停在第一页。后续数据库只绑定本机回环地址，临时实验账号不能当公网部署账号。

## 二、机制：为什么先分层学习，而不是背框架

前端开发者容易把成功返回 JSON 当成一次交付。浏览器得到 200，只说明某次请求走完；没有参数校验，非法 JSON 可以绕过表单入库；没有归属条件，知道别人的任务编号就可能看到别人的内容；没有回滚预案，发布后发现错误也没有安全退路。

路线按责任递进，不是按热门技术堆积。第一层解决“代码能否表达业务”，第二层解决“数据与并发是否可靠”，第三层解决“别人能否安全地使用、测试和维护服务”。先有语言，再有容器，最后有交付证据，出问题才知道检查哪一层。

| 层级 | 篇目 | 核心问题 | 可判定的产物 |
| :-- | :-- | :-- | :-- |
| L1 语法与 OOP | 01–07 | 类型、分支、对象边界怎么表达 | 运行命令行练习，解释编译错误与对象调用 |
| L2 语言进阶 | 08–11 | 集合、异常、函数式与线程怎样协作 | 可重复的筛选统计，保留失败原因，修正共享状态竞争 |
| L3 工程与交付 | 12–20 | 请求如何可信地入库、授权、测试和上线 | 可验证、可观测、可回滚的工单服务 |

机制不是要求第一天读完整个 Spring 源码，而是每个现象至少追问一次原因。事务没回滚，不是“注解偶尔失灵”，可能是调用没经过代理，或异常类型与传播边界不符合预期；有索引仍然慢，可能是回表、扫描范围过大或排序。知道因果，才能设计实验，不必不断替换配置碰运气。

最小 demo 是局部证据，不是生产承诺。测试只覆盖它的输入与断言，本机一次请求不能证明容量，一次 EXPLAIN 只解释该数据分布与统计信息下的计划。路线不提供脱离机器、数据、负载的 QPS 和 GC 耗时数字，性能结论需要自己记录实验前提与观测。

## 三、按四类起点选择读法

**A：第一次写 Java。** 按 01–11 顺序走，先复制最小 demo，再关闭正文重写。不要跳过类型、引用相等、异常传播，它们影响 Mapper 参数、业务判断、事务结果；遇到注解先问“这是语言语法，还是框架解释的元数据”，避免把所有问题归到 Java 本身。

**B：熟悉 JS/TS，迁移心智模型。** 先看对照表，重点 02、05–10，再做 11 的线程实验。别把 `Map` 当普通对象，也别把 Future 当运行机制完全相同的 Promise。TS 类型声明通常不留在产出的 JS 中，Java 的编译检查与运行时类信息有不同边界；同叫泛型，不意味着运行时行为相同。

**C：会语法，准备写业务。** 用 08–11 练习检查基础，再从 12 连续做到 20。别先复制安全过滤链：先验证没有安全链时的 Controller、参数错误与 404，再加认证比较变化，否则 401、400、500 混在一起，很难确定请求走到了哪一步。

**D：准备面试或接手服务。** 用“讲结论—画调用链—跑反例—说修复边界”复习 08、11、13、15、16、19，再拿 20 讲完整业务。要能说明如何证明权限没有漏，而不只是列框架名。面试材料是实践的归纳，不是另一套只有名词的路线。

入口可以不同，毕业要求不能因此消失。熟悉语法可以通过自检跳过阅读，但不能跳过权限、数据库、测试、部署证据。遇到前置知识时补最小必要部分再回来，不必把每个新名词扩成一条支线。

## 五、前端工程师的心智模型对照

| 熟悉的概念 | Java 可借用的模型 | 必须保留的差别 |
| :-- | :-- | :-- |
| TS 类型注解 | 编译器检查变量、参数、返回值 | 类型正确不等于外部 JSON 合法，仍需校验 |
| JS number | `int`、`long`、`double` 各有范围 | 长整数需字符串协议，不能丢精度后再补救 |
| ES Module | package、import 组织名称 | import 不下载依赖，类路径与 Maven 解决可用性 |
| npm 依赖树 | Maven 坐标与解析 | JDK 是工具链，不是普通业务依赖 |
| 对象与 interface | 类、record、接口表达结构和行为 | 结构相似不会自动实现 Java 接口 |
| `===` | 基本值比较，对象常用 equals | 包装缓存和常量池可能掩盖引用比较错误 |
| provide/inject | Spring 提供依赖 | 生命周期、作用域、代理与并发有额外边界 |
| Express middleware | Servlet Filter 与 MVC 拦截器 | 层级不同，认证失败可能没到 Controller |
| Promise、事件循环 | Future、线程池与异步结果 | 多个请求线程可能同时读写同一字段 |
| 前端路由权限 | RBAC 角色与能力 | 隐藏按钮不是授权，还需校验数据归属 |
| localStorage | Redis 跨实例共享缓存 | 需处理失效、并发重建、数据库一致性 |
| 单测与浏览器 E2E | JUnit、切片、集成测试 | mock 通过不证明真实 SQL 成功 |
| 构建与发布 | Maven、镜像、服务发布 | 连接和后台任务需要探活、优雅停机 |

对照是入口，不是等号。前端组件临时变量通常属于一次渲染，单例 Service 字段却可能被多个请求共享；把 `currentUser` 放进成员变量，就可能串用户数据。身份应来自安全上下文或显式参数，不能存成全局可变状态。

事务也不是前端一次状态更新。数据库事务只约束参与同一资源事务的操作，不会撤销已发出的邮件、HTTP、Redis 写入。十八引入 Outbox，是把“业务已提交”和“通知应送达”之间的问题变成可重试、可观察的状态，不靠一次方法调用假装所有系统都原子完成。

## 六、做到什么算过：五条交付标准

1. **需求到接口可追踪。** 给出“创建任务”需求，能定位 DTO、Controller、Service、Mapper、SQL、测试。合法请求成功，空标题 400，不存在资源返回约定错误，不是全都 200。
2. **数据行为可解释。** 能选集合，用可重建的十万行数据执行 EXPLAIN，说明索引、扫描范围与回表；用两个数据库会话展示锁等待，不只背隔离级别。
3. **权限有负向证据。** 能写 SecurityFilterChain，区分未认证 401 与已认证无权 403；A 不能换编号读写 B 的任务，管理员和普通用户能力有边界。
4. **修改有回归保护。** Service 单测不启动数据库，MVC 切片覆盖契约与安全，Testcontainers 用真实 MySQL 验证 SQL；先观察断言失败，再验证修正后通过，不拿覆盖率代替断言质量。
5. **上线能观察也能退回。** Docker 启动应用、MySQL、Redis，探活与业务检查各自通过；日志能关联且不泄漏敏感数据；指定上一个镜像完成回滚，说明数据库是否兼容旧程序。

毕业交付对象是服务，不要求同时制作大型后台页面，curl 或已有前端都能消费它。六张表围绕用户、角色、用户角色、工单、审计、通知这些生命周期展开，不为凑复杂度；接口、索引、事务围绕真实查询与状态转换设计。

## 常见坑

| 现象 | 根因 | 解法 |
| :-- | :-- | :-- |
| IDE 能跑，Maven 编译失败 | SDK 与 JAVA_HOME 不同 | 同时核对三条版本命令 |
| 后篇代码出现未知列 | 前置迁移未执行 | 先查表结构再查框架 |
| 错误请求全是 500 | 没区分参数、权限、系统异常 | 分别验证 400/401/403/404 |
| 隐藏按钮仍能删别人任务 | 只做显示控制或角色检查 | 验证能力和数据归属 |
| 单测全绿，SQL 上线失败 | mock 没执行真实 SQL | 保留真实 MySQL 集成测试 |
| 换回旧镜像仍失败 | 表结构不兼容旧程序 | 兼容迁移并演练旧镜像 |
| 每个技术都开空项目 | 缺共同业务目标 | 回填 task-center 实验结论 |
