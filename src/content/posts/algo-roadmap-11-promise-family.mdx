## 1. 状态机与订阅

Promise 本质是三状态状态机：`pending → fulfilled` 或 `pending → rejected`，**一旦变更不可逆**。

```ts
class MyPromise<T> {
  private state: 'pending' | 'fulfilled' | 'rejected' = 'pending';
  private value?: T;
  private reason?: unknown;
  private cbs: Array<() => void> = []; // pending 期间的订阅者

  constructor(
    executor: (
      resolve: (v: T | PromiseLike<T>) => void,
      reject: (r: unknown) => void,
    ) => void,
  ) {
    const resolve = (v: T | PromiseLike<T>): void => {
      if (this.state !== 'pending') return; // 状态不可逆
      this.state = 'fulfilled';
      this.value = v as T;
      this.flush();
    };

    const reject = (r: unknown): void => {
      if (this.state !== 'pending') return;
      this.state = 'rejected';
      this.reason = r;
      this.flush();
    };

    try {
      executor(resolve, reject);
    } catch (e) {
      reject(e); // executor 同步抛错也要转成 reject
    }
  }

  private flush() {
    const cbs = this.cbs;
    this.cbs = [];
    cbs.forEach((cb) => cb());
  }
}
```

为什么需要 `cbs` 数组：`then` 可能在 `resolve` 之前就注册了（异步 resolve 的常见情况）。状态变更时统一发布，**这就是 Promise 的发布订阅模型**。

## 2. then 链：主战场

四个必须处理的问题：

1. **返回新 Promise**，不是 `this`；
2. **回调在微任务里执行**（原生行为，用 `queueMicrotask` 模拟）；
3. **回调抛错**要变成新 Promise 的 reject；
4. **缺省回调**：`onFulfilled` 缺省是值穿透，`onRejected` 缺省是继续抛错（所以 `.then().then().catch()` 能接住最初的错误）。

```ts
then<R1 = T, R2 = never>(
  onFulfilled?: ((v: T) => R1 | PromiseLike<R1>) | null,
  onRejected?: ((r: unknown) => R2 | PromiseLike<R2>) | null,
): MyPromise<R1 | R2> {
  const f = onFulfilled ?? ((v: T) => v as unknown as R1);
  const r = onRejected ?? ((e: unknown) => { throw e; });

  const p2 = new MyPromise<R1 | R2>((resolve, reject) => {
    const exec = (handler: (x: unknown) => unknown, input: unknown) => {
      queueMicrotask(() => {
        try {
          resolvePromise(p2, handler(input), resolve, reject);
        } catch (e) {
          reject(e);
        }
      });
    };

    if (this.state === 'fulfilled') exec(f as (x: unknown) => unknown, this.value);
    else if (this.state === 'rejected') exec(r as (x: unknown) => unknown, this.reason);
    else {
      this.cbs.push(
        () => exec(f as (x: unknown) => unknown, this.value),
        () => exec(r as (x: unknown) => unknown, this.reason),
      );
    }
  });

  return p2;
}
```

### 2.1 resolvePromise：吸收 thenable

```ts
function resolvePromise(
  p2: MyPromise<unknown>,
  result: unknown,
  resolve: (v: unknown) => void,
  reject: (r: unknown) => void,
): void {
  if (result === p2) {
    reject(new TypeError('Chaining cycle detected'));
    return;
  }

  if (result instanceof MyPromise) {
    result.then(resolve, reject);
    return;
  }

  if (result !== null && (typeof result === 'object' || typeof result === 'function')) {
    const then = (result as { then?: unknown }).then;
    if (typeof then === 'function') {
      let called = false;
      try {
        (then as (res: (v: unknown) => void, rej: (r: unknown) => void) => void).call(
          result,
          (v) => { if (!called) { called = true; resolvePromise(p2, v, resolve, reject); } },
          (r) => { if (!called) { called = true; reject(r); } },
        );
      } catch (e) {
        if (!called) reject(e);
      }
      return;
    }
  }

  resolve(result);
}
```

三个规范细节：

- **`result === p2` 要拒绝**（循环引用）；
- **`called` 标记**：thenable 可能既调 resolve 又调 reject，只认第一次；
- **嵌套 thenable** 要递归吸收，不能直接 `resolve(thenable)`。

### 2.2 补齐 catch / finally / 静态 resolve

```ts
catch<R = never>(onRejected?: (r: unknown) => R | PromiseLike<R>) {
  return this.then(null, onRejected);
}

finally(cb?: () => void) {
  return this.then(
    (v) => { cb?.(); return v; },
    (e) => { cb?.(); throw e; },
  );
}

static resolve<T>(v: T | PromiseLike<T>): MyPromise<T> {
  if (v instanceof MyPromise) return v;
  return new MyPromise<T>((resolve) => resolve(v));
}

static reject<T = never>(r: unknown): MyPromise<T> {
  return new MyPromise<T>((_, reject) => reject(r));
}
```

`finally` 的两个细节：**不改变值**（成功透传原值，失败继续抛），**如果回调抛错则覆盖原结果**。这也是原生 `finally` 的行为。

## 3. 四个静态方法：计数器 + 下标保序

```ts
static all<T>(promises: Iterable<T | PromiseLike<T>>): MyPromise<T[]> {
  return new MyPromise((resolve, reject) => {
    const list = [...promises];
    if (list.length === 0) return resolve([]); // 空数组立即成功

    const results = new Array<T>(list.length);
    let count = 0;
    list.forEach((p, i) => {
      MyPromise.resolve(p).then((v) => {
        results[i] = v; // 按下标存，顺序与输入一致
        if (++count === list.length) resolve(results);
      }, reject);       // 任一失败立即失败
    });
  });
}

static race<T>(promises: Iterable<T | PromiseLike<T>>): MyPromise<T> {
  return new MyPromise((resolve, reject) => {
    for (const p of promises) MyPromise.resolve(p).then(resolve, reject);
  });
}

static allSettled<T>(promises: Iterable<T | PromiseLike<T>>): MyPromise<unknown[]> {
  return new MyPromise((resolve) => {
    const list = [...promises];
    if (list.length === 0) return resolve([]);

    const results = new Array(list.length);
    let count = 0;
    const done = () => { if (++count === list.length) resolve(results); };

    list.forEach((p, i) => {
      MyPromise.resolve(p).then(
        (v) => { results[i] = { status: 'fulfilled', value: v }; done(); },
        (r) => { results[i] = { status: 'rejected', reason: r }; done(); },
      );
    });
  });
}

static any<T>(promises: Iterable<T | PromiseLike<T>>): MyPromise<T> {
  return new MyPromise((resolve, reject) => {
    const list = [...promises];
    const errors = new Array(list.length);
    let count = 0;

    list.forEach((p, i) => {
      MyPromise.resolve(p).then(resolve, (r) => {
        errors[i] = r;
        if (++count === list.length) {
          reject(new AggregateError(errors, 'All promises were rejected'));
        }
      });
    });
  });
}
```

一句话记住四兄弟：

| 方法 | 成功条件 | 失败条件 | 空数组 |
| --- | --- | --- | --- |
| `all` | 全部成功 | 任一失败 | 立即成功 `[]` |
| `race` | 第一个 settle（成功或失败） | 同左 | **永远 pending** |
| `allSettled` | 全部 settle | 从不失败 | 立即成功 `[]` |
| `any` | 任一成功 | 全部失败（AggregateError） | 立即失败 |

## 4. 并发限制器与 retry

```ts
async function promiseLimit<T>(
  tasks: Array<() => Promise<T>>,
  limit: number,
): Promise<T[]> {
  const results = new Array<T>(tasks.length);
  let next = 0;

  async function worker() {
    while (next < tasks.length) {
      const i = next++;
      results[i] = await tasks[i]();
    }
  }

  await Promise.all(
    Array.from({ length: Math.min(limit, tasks.length) }, () => worker()),
  );
  return results;
}
```

`next++` 在单线程事件循环里不会竞争；结果按下标写回，所以**返回顺序与输入一致**，与完成顺序无关。

```ts
// 失败重试：指数退避
function retry<T>(fn: () => Promise<T>, times: number, delay = 0): Promise<T> {
  return fn().catch((err) => {
    if (times <= 1) throw err;
    return new Promise((r) => setTimeout(r, delay)).then(() =>
      retry(fn, times - 1, delay ? delay * 2 : 0),
    );
  });
}
```

追问"怎么给单个任务加超时"：

```ts
const withTimeout = <T>(p: Promise<T>, ms: number) =>
  Promise.race([
    p,
    new Promise<never>((_, reject) =>
      setTimeout(() => reject(new Error('timeout')), ms)),
  ]);
```

## 5. 微任务执行顺序：必考题

```js
console.log('1');
setTimeout(() => console.log('2'));
Promise.resolve()
  .then(() => console.log('3'))
  .then(() => console.log('4'));
queueMicrotask(() => console.log('5'));
console.log('6');
```

输出：**1 → 6 → 3 → 5 → 4 → 2**。

解释：同步代码先跑（1、6）；然后清空微任务队列：`then(3)` 入队、`queueMicrotask(5)` 入队、3 执行时把 4 入队，所以顺序是 3、5、4；最后才是宏任务 2。

`async/await` 的对应关系：

```js
async function f() {
  console.log('a');
  await 1;           // await 之后的代码 = 微任务
  console.log('b');
}
f();
console.log('c');
// a c b
```

## 6. 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| then 里 `resolve` 的 Promise 没被等 | 没实现 thenable 吸收 | `resolvePromise` 递归处理 |
| 错误被吞掉 | `onRejected` 缺省写成了空函数 | 缺省要 `throw e` |
| `.then()` 后拿不到值 | 返回的是 `this` | 必须返回新 Promise |
| 状态被改两次 | 没做 pending 守卫 | 每次变更前判状态 |
| executor 抛错变 unhandled | 没 try/catch | 包一层转 reject |
| 循环引用死循环 | 没判 `result === p2` | 直接 reject TypeError |
| `race([])` 卡死 | 以为是 resolve | 空数组本就是永远 pending |
| `any([])` 行为错 | 没处理空数组 | 应立即 reject AggregateError |
| thenable 回调被调用两次 | 没 `called` 标记 | 只认第一次 |

## 7. 小结

- 状态机三状态不可逆；pending 期间用回调数组实现发布订阅。
- then：返回新 Promise + 微任务执行 + try/catch + 缺省穿透 + thenable 吸收。
- 四静态方法 = 计数器 + 下标保序，差异在"何时算失败"。
- 并发限制器 = N 个 worker 抢共享游标；retry = 递归 + 退避。
- 微任务先于宏任务，`await` 之后的代码是微任务。
