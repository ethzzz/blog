## 定义要精确：闭包不是"函数里套函数"

闭包 = **函数 + 它被创建时所在的作用域**。任何函数只要引用了外层变量，就形成了闭包——**哪怕没有嵌套函数**。

```js
const counter = (() => {
  let n = 0;                       // 被闭包"记住"
  return {
    inc: () => ++n,
    get: () => n,
  };
})();

counter.inc();
counter.inc();
counter.get();     // 2 —— n 没被销毁
```

`n` 在 IIFE 执行结束后本该消失，但因为返回的两个函数引用了它，**它被保留在内存里**。这就是闭包的全部魔法。

## 三个真实用途

### 1. 私有状态（模块模式）

```js
function createStore(initial) {
  let state = initial;              // 外部无法直接改
  const listeners = new Set();

  return {
    get: () => state,
    set(next) {
      state = typeof next === 'function' ? next(state) : next;
      listeners.forEach((l) => l(state));
    },
    subscribe(l) {
      listeners.add(l);
      return () => listeners.delete(l);   // 返回取消订阅，防止泄漏
    },
  };
}
```

这是 Redux/Zustand 内部的基本形态：**状态藏在闭包里，只能通过方法访问**。

### 2. 防抖 / 节流（保存计时器）

```js
function debounce(fn, wait = 300) {
  let timer = null;                  // 每次调用共享同一个 timer
  return (...args) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      fn(...args);
    }, wait);
  };
}
```

没有闭包就无法在多次调用之间保留 `timer`——这是"闭包存状态"的典型。

### 3. 一次性初始化（缓存）

```js
const getConfig = (() => {
  let cache;
  return () => (cache ??= loadConfig());   // 只加载一次
})();
```

## 闭包与内存：什么时候会泄漏

关键概念是**可达性**：只要还能从根（全局、当前调用栈）访问到，就不会被回收。

```js
function attach() {
  const hugeData = new Array(1e6).fill('x');   // 约 8MB
  return () => {
    return hugeData.length;      // ⚠️ 只用了 length，但整个数组被记住
  };
}
const fn = attach();
```

`fn` 活着，`hugeData` 就活着。修法：**只保留需要的那部分**。

```js
function attach() {
  const hugeData = new Array(1e6).fill('x');
  const len = hugeData.length;    // ✅ 只闭包住长度
  return () => len;
}
```

（现代引擎有"变量级别"的优化，理论上可能只保留用到的变量，但**不要依赖它**——不同引擎/不同代码形态表现不一致。）

另外两类常见泄漏：

```js
// 1) 未取消的订阅
useEffect(() => {
  store.subscribe(update);        // ❌ 没有返回取消函数
}, []);

// 2) 未清理的定时器，且回调引用了大对象
useEffect(() => {
  const id = setInterval(() => render(bigList), 1000);   // ❌ 没 clear
  return () => clearInterval(id);
}, []);
```

## 循环经典题：两种解法

```js
// ❌ 都是 3
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));

// ✅ 解法 1：let 的块级绑定（推荐）
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i));

// ✅ 解法 2：IIFE 造独立作用域（老代码常见）
for (var i = 0; i < 3; i++) {
  (function (j) {
    setTimeout(() => console.log(j));
  })(i);
}
```

本质：**闭包捕获的是"变量"，不是"值"**。要拿到每轮的值，就得每轮有一个新变量。

## 闭包不是"内存泄漏"，但会延长生命周期

| 说法 | 准确性 |
| --- | --- |
| "闭包会导致内存泄漏" | ❌ 不准确。闭包只是让变量活得更久 |
| "闭包持有大对象会导致泄漏" | ✅ 准确 |
| "全局存了闭包返回的函数，永不释放" | ✅ 这是真泄漏 |

判断方法：**Heap snapshot 里看 retained size**，找那些"本该消失却还在"的闭包作用域。

## 常见坑

| 现象 | 根因 | 解法 |
| --- | --- | --- |
| 循环回调都拿最后一个值 | 闭包捕获变量而非值 | `let` 或 IIFE |
| 内存阶梯上升 | 订阅/定时器没清理，闭包一直持有 | 返回取消函数并调用 |
| 组件卸载后还在更新状态 | 异步回调闭包住旧 setState | 用 `AbortController` 或标记 `mounted` |
| 以为闭包只存在于嵌套函数 | 定义不准确 | 任何引用外层变量的函数都是闭包 |
| 为了"省内存"到处手动置 null | 过度优化 | 保证可达性正确即可 |
