## 先定尺子：什么叫"JS 真的懂了"

不是背得出"原型链是 `__proto__` 指向"，而是这五件事都做得到：

1. **能解释任何诡异输出**：`[1,2,3].map(parseInt)` 为什么得到 `[1, NaN, NaN]`，不看答案也能推。
2. **能手写核心机制**：`new`、`instanceof`、`bind`、`debounce`、简易 `Promise`——手写过才算真懂。
3. **能画出调用栈与事件循环**：给一段 `async/await` + `setTimeout` 混排的代码，能说出打印顺序并说明原因。
4. **能定位内存泄漏**：知道闭包、全局引用、未清理监听各自怎么泄漏，能看 Heap snapshot。
5. **能设计模块边界**：什么时候该拆文件、循环依赖为什么会拿到 `undefined`、`ESM` 与 `CJS` 的差别。

第 1 条区分"记得住"和"理解"；第 2 条区分"看过文章"和"能写"。

## L1：语言机制（01–05）

**目标：把"能跑"变成"知道为什么这么跑"。**

- **01 作用域与提升**：`var/let/const` 的差别不止"块级"，还有暂时性死区；函数声明与表达式提升不同；循环里 `var` 的经典陷阱。
- **02 类型与隐式转换**：`typeof null === 'object'` 为什么、`==` 的转换表、`+` 到底是加还是拼、`Object.is` 与 `===` 的差别。
- **03 执行上下文与调用栈**：栈里放什么、为什么 `try/catch` 抓不到 `setTimeout` 里的错、错误栈怎么读。
- **04 this 绑定**：四条规则与优先级、箭头函数为什么没有自己的 `this`、三种"this 丢了"的现场。
- **05 闭包**：本质是"函数 + 它记住的词法环境"；三个真实用途；为什么会泄漏大对象。

> 读法：01→03→04→05 连读（**03 是 04/05 的地基**，先懂执行上下文，this 与闭包才不会变成口诀）；02 可以单独看。

## L2：对象与异步（06–09）

- **06 原型与原型链**：`prototype` / `__proto__` / `constructor` 三者的关系，属性查找链，手写 `instanceof`，原型污染攻击。
- **07 继承演进**：原型链继承的共享引用缺陷 → 构造函数继承 → 组合继承 → 寄生组合；`class extends` 的本质与 `super`。
- **08 事件循环**：宏任务/微任务、每轮循环的顺序、`setTimeout(fn, 0)` 到底多久、`await` 之后的代码为什么在微任务里。
- **09 函数式与高阶函数**：纯函数、柯里化、组合、不可变更新，以及 `map/filter/reduce` 的性能陷阱。

> 读法：06→07 连读（先懂原型再谈继承）；08 单篇最重要，前端所有"异步顺序题"都出自这里；09 按需。

## L3：工程表达（10–11）

- **10 模块化**：CJS 与 ESM 的求值差异、循环依赖的真实表现、ESM 的 live binding、动态 `import`。
- **11 错误处理与调试**：三类错误的捕获方式、`Promise` 拒绝链、统一错误对象、sourcemap 与断点技巧。

> 读法：10 在做组件库/工具库前必读；11 建议在第一次线上排查后回过头读，感受更深。

## 我踩过最贵的三个坑

- **循环里用 `var` 存事件回调**：所有回调拿到的都是最后一个值，排查了两小时。
- **以为 `try/catch` 能抓住 `Promise` 里的错**：没有 `await` 的 rejected promise 直接变成 unhandled rejection，线上静默失败。
- **循环依赖里取了模块顶层常量**：拿到 `undefined`，因为对方模块还没执行完——这个坑在重构时最容易引爆。

JS 的很多"坑"其实是**机制在正常工作**，只是你的预期错了。所以这一层不背结论，只讲机制。
