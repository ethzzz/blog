> [!NOTE]
> 这条路线假设你已经会一门语言（JS/TS/Java/Python 都行），不需要从"什么是变量"讲起。
> 目标很具体：**读完并做完，你能独立写一个带路由、鉴权、数据库、测试、能部署上线的 HTTP 服务**。
> 不追求把语法讲全，只讲"Go 和你想的不一样的地方"——那些才是会让人卡住的地方。

---

## 为什么要学 Go

- **部署太简单**：编译成一个静态二进制，扔到服务器就能跑。没有运行时、没有依赖目录、没有"我这台机器上是好的"。
- **并发是语言级能力**：goroutine + channel 不是库，是语法与运行时。写并发的心理负担比线程池小得多。
- **服务端生态正合适**：标准库就有 `net/http`、`database/sql`、`log/slog`，不装框架也能写；要框架再上 Gin/Echo/chi。
- **云原生事实标准**：Docker、Kubernetes、Terraform、Prometheus、etcd 都是 Go 写的——想往基础设施/平台方向走，这是门票。

**不适合什么**：不适合写 UI、不适合做脚本快速试错（Python 更爽）、GC 语言做极致低延迟不如 Rust/C++。

## 和 JS/Java 最不一样的 5 件事（先建立预期）

| 维度 | Go 的做法 | 你会踩的坑 |
|---|---|---|
| 类型 | 静态 + 强类型，无隐式转换 | `int` 与 `int64` 不能直接比较，得转 |
| 错误 | 返回 `error` 值，不抛异常 | 到处都是 `if err != nil`，这是**故意的** |
| 面向对象 | 没有 class/继承，只有 struct + 接口（**隐式实现**） | 找不到 `implements`，接口是"事后归纳"出来的 |
| 并发 | goroutine + channel，靠通信共享内存 | 竞态不会报错，只会在压力下偶发 |
| 内存 | 有 GC，但值/指针语义分明 | 大 struct 传值会整份拷贝，性能差异肉眼可见 |

## 13 篇学习地图

```text
Go 学习路线（13 篇）
├── 地基（能写出正确、地道的 Go）
│   ├── 01 环境与工具链        ← go mod / 目录结构 / gofmt / go vet / Makefile
│   ├── 02 类型系统与值语义    ← 零值 / 值 vs 指针 / slice 与 map 的坑
│   ├── 03 接口与组合          ← 隐式实现 / 小接口 / 嵌入 / 类型断言
│   └── 04 错误处理            ← error 是值 / %w 包装 / errors.Is·As / panic 边界
├── 并发（Go 的核心竞争力）
│   ├── 05 并发（上）          ← goroutine / channel / select / 关闭与广播
│   └── 06 并发（下）          ← sync / atomic / context 取消传播
├── 工程与性能
│   ├── 07 内存与性能          ← 逃逸分析 / GC / pprof / benchmark
│   ├── 08 标准库实战          ← net/http / encoding/json / log/slog / flag
│   └── 09 写一个 Web 服务      ← 路由 / 中间件 / 校验 / 统一错误 / 优雅关闭
├── 数据与质量
│   ├── 10 数据层              ← database/sql / 事务 / 连接池 / 迁移
│   └── 11 测试与工程质量      ← table-driven / httptest / -race / 覆盖率 / CI
└── 交付
    └── 12 毕业项目：任务 API   ← 与 React/Node 两篇同一份契约，部署上线
```

## 每阶段的产出（能验证的，不是"读过"）

| 阶段 | 做完你应该有的东西 | 验证方式 |
|---|---|---|
| 01–04 | 一个能 `go vet` + `golangci-lint` 全绿的 CLI 小工具 | `go build` + `go vet ./...` 无输出 |
| 05–06 | 一个并发爬取/限流的 demo | `go test -race ./...` 无竞态报告 |
| 07 | 一份 pprof 前后对比（优化前后的 ns/op） | `go test -bench . -benchmem` 数字对比 |
| 08–09 | 一个能跑的服务：健康检查 + 路由 + 中间件 | `curl` 返回预期 JSON |
| 10–11 | 数据层 + 一组测试 | `go test ./... -cover` 覆盖率 > 60% |
| 12 | 可上线的任务 API（Docker/pm2 任选） | 前端用同一份契约直连成功 |

---

## 怎么读

- **01–04 一定要动手**：Go 的坑都在"值语义"和"接口"上，光看会以为懂了。
- **05–06 是分水岭**：并发写不对不会立刻报错，只会在大压力下偶发。必须用 `-race` 跑测试。
- **07 别提前看**：没有性能问题就先别优化。等到有 benchmark 数字再回来。
- **12 是毕业项目**：和 [React 那篇](/blog/posts/react-roadmap-12-project-task-board/)、[Node 那篇](/blog/posts/node-roadmap-13-project-task-api/) 用**同一份接口契约**，做完你能横向对比三种语言写同一个服务。

## 时间预期

- 有编程基础、每天 2 小时：**3–4 周**走完 01–11，再加 1 周做毕业项目。
- 只想"能读懂 Go 代码、能改别人的服务"：01–04 + 08–09 够用，约 1 周。
- 别信"三天精通 Go"——语法三天能过，**并发与工程习惯**才是分水岭。

---

## 小结

Go 的哲学是"少而明确"：没有隐式转换、没有异常、没有继承、没有注解魔法。代价是代码看起来啰嗦，收益是**任何人读你的代码都不用猜**。

下一篇从环境与工具链开始——先把 `go mod`、`gofmt`、`go vet` 这套地基铺好，后面才不会被"为什么我的代码格式和别人不一样"绊住。
