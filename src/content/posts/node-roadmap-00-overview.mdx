## 0. 做到什么算过

不看"看完 14 篇"，看能不能做出这五个动作。都做到，就是能独立交付一个服务：

1. 能从一个需求**拆出接口、数据模型、错误码**三样东西，再去写代码。
2. 接口挂了能**从日志定位到具体一层**（路由、校验、数据库、第三方），而不是只看到 500。
3. 能说清你的服务**在并发 100 时会发生什么**：连接池会不会打满、内存会不会涨、哪些操作不是原子的。
4. 所有写接口都**默认不可信**：鉴权、校验、限流、幂等一个不缺。
5. 能把它**部署到一台服务器上**：进程守护、环境变量、健康检查、日志落盘、能回滚。

第 3 条是从"会写接口"到"敢上线"的分界。绝大多数线上事故不是语法错，是并发、连接、内存这类"前端碰不到的东西"。

## 三层结构

| 层 | 解决什么 | 篇目 | 过关标志 |
|---|---|---|---|
| **L1 地基** | 运行时、异步、HTTP | 01–03 | 能解释"为什么这段代码阻塞了其他请求" |
| **L2 工程** | NestJS、数据库、鉴权、日志、校验 | 04–08 | 能独立做出带登录与权限的模块 |
| **L3 生产** | 上传、队列、测试、部署 | 09–12 | 上线不靠人肉，出问题能查 |
| 项目 | 全部串起来 | 13 | 与 React 篇同一份契约，能联调 |

**编号是目录索引，不是阅读顺序。** 按你的起点选：

- **A. 只会前端，没写过 Node**：01 → 02 → 03 → 04 → 05 → 06，然后 07 → 08。这六篇是主干。
- **B. 写过 Express，想上 NestJS**：直接 04（IoC/DI 是它的地基）→ 08（校验与错误）→ 05（ORM 与事务）。
- **C. 已经在写，但在救火**（内存涨、接口慢、日志看不懂）：12（部署与性能）→ 07（日志）→ 05（N+1 与连接池）。
- **D. 要带团队**：04（结构约束）、08（统一的错误契约）、11（测试门槛）是重点。

## 1. 为什么前端要学 Node

先说三个我亲身的场景，你可能也遇到过：

1. **联调时被后端卡脖子**。接口字段不对、缺个聚合接口、想加个 mock 都要排队。会 Node 之后，我自己半小时就能起一个 BFF 层把数据拼好。
2. **性能问题的锅甩不出去**。页面慢，后端说"我这边很快"。你不会写服务端，就永远只能"猜测"。学了 Node 我才知道：慢的往往不是接口，是 N+1 查询和没加索引。
3. **全栈岗位的溢价真实存在**。我带的组里，能自己写 NestJS 的前端，绩效和薪资天花板明显高一截。不是要求你精通 DBA 级别的东西，而是"能独立交付一个完整服务"。

核心论点只有一句话：**你已经会 JS/TS 了，Node 是所有后端语言里对你迁移成本最低的一个**。语言零成本，剩下的全是"服务端思维方式"——这是这条路线真正要教的东西。

## 2. 前端思维 vs 服务端思维

这是我总结的最大障碍，先摆出来：

| 维度 | 前端习惯 | 服务端要求 |
| --- | --- | --- |
| 生命周期 | 页面刷新即重置 | 进程长跑几个月，内存泄漏会积累 |
| 错误处理 | try-catch 崩了刷新就好 | 一个未捕获异常可能拖垮整个进程 |
| 数据归属 | 数据在服务端，随便用 | 数据是你的责任，事务、并发、一致性 |
| 信任边界 | 用户输入可以大致信任 | 一切输入都是恶意的，必须校验 |
| 部署 | 构建产物扔 CDN | 进程、日志、监控、重启策略都要管 |

第 06 篇（安全）、第 07 篇（日志）、第 12 篇（部署）基本都在补这张表的右列。

## 3. 完整学习地图

```text
Node 全栈路线（14 篇）
├── 地基篇（前端友好区，你已有的知识直接平移）
│   ├── 01 Node 基础与模块系统     ← nvm / CommonJS vs ESM / fs / path
│   ├── 02 异步编程与事件循环     ← libuv / Stream / worker_threads
│   └── 03 HTTP 服务与中间件      ← 原生 http / Express / Koa 洋葱模型
├── 工程篇（NestJS 正统后端技能）
│   ├── 04 NestJS 入门            ← IoC/DI 原理 / 装饰器 / 三大件
│   ├── 05 数据库集成与 ORM       ← TypeORM vs Prisma / 事务 / 迁移
│   ├── 06 认证与安全             ← JWT vs Session / RBAC / helmet
│   ├── 07 配置与日志             ← 多环境配置 / pino / 链路 ID
│   └── 08 校验与错误处理         ← class-validator / 全局异常过滤器
└── 实战篇（生产环境真刀真枪）
    ├── 09 文件上传与大文件处理   ← multer / 流式 / OSS 直传
    ├── 10 消息队列与定时任务     ← BullMQ / 幂等 / @nestjs/schedule
    ├── 11 测试与调试             ← Jest / supertest / inspector
    └── 12 部署与性能             ← PM2 / Docker / nginx / 压测
```

读法建议：

- **01-03** 会让你有强烈的既视感，因为浏览器 JS 和 Node JS 共享 90% 的语言核心。这三篇的任务是把差异点（模块、进程、流）讲清楚。
- **04-08** 是"从写脚本到写服务"的分水岭。NestJS 的 IoC 你第一次可能觉得啰嗦，但它是大型服务的骨架，第 04 篇我会带你手写一个迷你 IoC 容器，你就懂了。
- **09-12** 按需读，但第 12 篇强烈建议通读——不了解部署的前端，写代码时不知道生产环境长什么样。

## 4. 路线使用方法

我的建议是**项目驱动**，不要刷完 14 篇再动手。具体操作：

1. **先立项目**：从第 03 篇开始，同步开一个"个人博客 API"项目（文章 CRUD → 用户认证 → 评论队列 → 上传封面 → 上线部署）。01–12 正好对应它的 12 个迭代；**13 篇是毕业项目**，把这个项目按「契约先行 → 鉴权/日志 → 测试/部署」重做一遍并上线。
2. **每篇 1-2 小时 + 1 次提交**：读完全文，把"练习"部分做完，`git commit` 一次。练习都是我自己踩过坑的变体，不是抄书。
3. **卡住超过 30 分钟就跳过**：有些概念（比如第 02 篇的事件循环六个阶段）第一遍理解 70% 就够了，实战中会反复回来。
4. **环境准备**（第 01 篇会详细讲）：nvm 管理 Node 版本、VS Code 装 ESLint、装好 Docker Desktop（第 05 篇起要用）。

时间预期：全职约 2 周，业余每天 2 小时约 6-8 周。别信"三天学会 Node"——三天学的是 API 调用，不是工程能力。

## 5. 这条路线为什么选 NestJS 而不是 Express 直接上

这是被问最多的问题，我直接给结论：

| 方案 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- |
| 原生 http / Express | 极简、自由、心智负担小 | 没有约束，项目大了变泥球 | 学习原理、小工具 |
| Koa | 中间件模型优雅 | 生态碎片化，要自己拼积木 | 理解洋葱模型 |
| NestJS | 开箱即用的 DI/校验/文档，结构强约束 | 概念多，前期有学习成本 | 团队协作、长期维护 |

Express 和 Koa 我在生产里都写过两年以上，最终的体感是：**单人小项目 Express 爽，三个人以上必须 NestJS**。它用 Angular 式的强约定，换来了"任何人接手任何模块都不迷路"。第 03 篇会先讲 Express/Koa 打好原理基础，第 04 篇再进 NestJS——不跳步。

另外为什么不选 Go/Java：不是它们不好，而是"前端延伸"的场景里，**复用已有 TS 技能 + 前后端同构（连类型都能共享）** 的收益太大了。写够一年 Node 想转 Go，那时你对服务端的理解会让迁移快得多。

## 小结

- 学 Node 的核心收益不是多一门语言，而是补齐"服务端思维"：长生命周期进程、数据责任、信任边界。
- 路线分三段：地基（01-03）→ 工程（04-08）→ 实战（09-12），用一个博客 API 项目串起来。
- 每篇控制 1-2 小时 + 动手练习，卡住 30 分钟先跳过。
- 选 NestJS 是为了工程约束和团队协作，但第 03 篇的 Express/Koa 原理必须先懂。

## 练习

1. 写下你当前项目里三个"如果我会后端就能自己解决"的问题，作为学习动机存档。
2. 检查本机 Node 版本（`node -v`），确认你能否说出"LTS 版本和 Current 版本该用哪个、为什么"。
3. 注册一个 GitHub 仓库叫 `my-blog-api`，后续 12 篇的练习代码都提交在这里。
4. 通读一遍本文的"前端思维 vs 服务端思维"表格，圈出你最没把握的一行——那是你在这条路线里最该留意的盲区。

## 毕业前自检（整条路线的验收）

读完 13 篇、做完毕业项目之后，对着这张表勾一遍。全勾上，说明你能独立交付一个服务：

- [ ] 能画出你的服务从收到请求到返回响应的完整链路，并指出中间件、校验、业务、数据层各在哪
- [ ] 能在不看代码的情况下，说出某个接口大概会发几条 SQL
- [ ] 内存跑 24 小时不涨（用 heap snapshot 对比过两次）
- [ ] 压测过一次，知道你的 QPS 与 P95，知道瓶颈在哪一层
- [ ] 所有写接口都有：鉴权、输入校验、限流、幂等
- [ ] 日志是结构化的，带 `requestId`，能从一次报错串到具体请求
- [ ] 密钥全在环境变量里，仓库和镜像里搜不到
- [ ] 部署脚本能一键发布，且做过一次回滚演练
- [ ] 有一条 E2E 覆盖"登录 → 写入 → 查询"这条主链路
