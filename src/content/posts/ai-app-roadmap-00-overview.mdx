团队成员登录工作台，上传一份发布手册，就能询问「发布前要做什么」，点击引用打开原文。也可以发起多轮对话、用截图或录音补充问题、让助手拟一条待办，再手动确认。维护者能用固定问题评测回答，按请求 ID 排查异常，查看用量和反馈。

整个系列只做这一个项目。第一天启动可打开的网页，后面的阶段继续用同一份代码和数据库。推荐先做一章的实战，遇到概念问题再看章末链接的专题。

## 开工前准备

会写基本 JavaScript、能读 HTTP 请求和 JSON，即可开始。需要 Node.js 24、浏览器和 MySQL 8.4。第 1 章提供 Docker Compose 配置，也可以连接已有的 MySQL 8.0 或 8.4 实例。服务端用 `mysql2` 连接池、参数化 SQL 和 InnoDB 事务保存会话与文档，网页用 HTML 与浏览器模块。 [mysql2 Promise 接口](https://sidorares.github.io/node-mysql2/docs/documentation/promise-wrapper)

参考源码位于本仓库的 `lab/ai-app-workshop/`。每章说明新增文件写在哪里，并提供按阶段下载的命令。默认 mock 可以练联调、中断、权限、引用、工具确认和评测。接入实际支持相应能力的模型后，再验收真实回答、语义检索、工具选择、视觉与转写。真实模型会产生供应商费用。

## 页面、接口与数据归属

| 页面能力 | 后端入口 | 数据归属 |
| --- | --- | --- |
| 多轮聊天 | `/api/conversations`、`/api/messages`、`/api/chat` | MySQL 会话及消息，服务端从访问密钥确定用户 |
| 知识库 | `/api/documents`、`/api/document`、`/api/ask` | MySQL 文档、分块及 JSON 向量，检索和引用都查归属 |
| 待办助手 | `/api/agent`、`/api/tasks`、`/api/tasks/confirm` | 草案有有效期，用户确认后事务写入待办 |
| 图片与语音 | `/api/media` | 校验后的媒体由服务端传给对应模型，结果由用户选择是否发进对话 |
| 运营与质量 | `/api/usage`、`/api/feedback`、评测脚本 | 用量和反馈属于请求人，评测使用独立测试库 |

浏览器始终通过同源 HTTP 调工作台。模型 API Key 留在服务端，模型用量和协议差异在适配层处理。服务端按单实例、少量文档设计。MySQL 持久化业务数据，每轮检索先按用户查候选，再在 Node.js 里打分。生产应用的企业登录、大规模向量索引、远程 MCP、多供应商容灾和模型训练属于后续专题方向。

## 从第一步开始

按顺序做完每章的「联调与验收」，保留每次验证的命令和结果。阶段编号就是运行命令里的参数。例如 `node --env-file=.env server.mjs 2` 打开前两章能力，`node --env-file=.env smoke.mjs 2` 在独立的 MySQL 测试库回归前两章。
