## 先定"做到什么算过"

一个新手跟完这个项目，应该能独立做到下面 8 件事。做不到的，就是没毕业：

1. 给你一张需求（列表 + 筛选 + 分页 + CRUD），你能**独立拆出路由、页面、数据层**，不再是一把梭写在一个文件里。
2. 请求层有统一的错误类型，`4xx/5xx/断网` 三种情况 UI 表现不同、都有出路（重试 / 回列表 / 提示）。
3. **URL 就是筛选与分页状态**：刷新、分享、后退都不丢。
4. 增删改之后列表**自动一致**（不手动 `refetch` 拍脑袋）。
5. 乐观更新失败能**回滚**，不会出现"界面成功了但服务器没有"。
6. 表单校验有字段级错误 + 焦点自动落到第一个错误字段。
7. 全程可以只用键盘操作完（Tab 能走到每个控件，焦点环可见）。
8. 能说出这个项目里**哪些地方故意没加** `memo/useMemo`，以及为什么。

> 这 8 条对应的是"能独立干活"，不是"能背 API"。第 3、5、7 条是绝大多数教程会跳过、但真实工作每天都要用的部分。

## 技术选型（以及为什么只选这几个）

| 选择 | 理由 | 不选什么 |
|---|---|---|
| Vite + React 18 + TS | 启动快、类型能兜住一半低级错误 | 不上 CRA（已停更） |
| React Router 6（data router） | 路由即页面骨架，`errorElement` 兜渲染错误 | 不上手写 switch |
| TanStack Query v5 | 服务端状态（缓存、失效、重试、乐观更新）不用自己写 | 不自己造 `useFetch` |
| json-server 0.17 | 10 秒得到一个真 REST 后端，能增删改查、分页、模糊搜索 | 不先写 Node 后端（会跑偏） |
| 手写 CSS | 不引入 UI 库，注意力留在数据流 | 不上 AntD（会变成学组件库） |

**刻意不引入**：Redux/Zustand（这个规模的页面不需要，见 [状态管理那篇](/blog/posts/react-roadmap-08-state-management/)）、表单库（手写一遍才知道受控组件难在哪）。

## 阶段 1：列表页（路由 + 请求 + 三态）

**目标**：打开 `/tasks` 能看到列表；筛选、分页、搜索都写进 URL；加载/错误/空三种状态各有出路。

### 1. `api/client.ts`：统一出口 + 统一错误

```ts
const BASE = import.meta.env.VITE_API_BASE ?? "http://localhost:4000";

export class ApiError extends Error {
	constructor(
		readonly status: number,
		message: string,
		readonly detail?: unknown,
	) {
		super(message);
		this.name = "ApiError";
	}
}

export async function request<T>(path: string, init?: RequestInit): Promise<T> {
	let res: Response;
	try {
		res = await fetch(`${BASE}${path}`, {
			...init,
			headers: { "Content-Type": "application/json", ...init?.headers },
		});
	} catch {
		// fetch 只在网络层失败时 reject —— 这是"断网/后端没起"
		throw new ApiError(0, "网络异常，请检查后端是否在运行");
	}

	if (!res.ok) {
		let detail: unknown = null;
		try {
			detail = await res.json();
		} catch {
			detail = await res.text();
		}
		throw new ApiError(res.status, statusText(res.status), detail);
	}

	if (res.status === 204) return undefined as T;
	return (await res.json()) as T;
}

function statusText(status: number): string {
	if (status === 404) return "资源不存在（可能已被别人删除）";
	if (status === 422) return "提交的数据不合法";
	if (status >= 500) return "服务端出错了，稍后重试";
	return `请求失败（${status}）`;
}
```

**要点**：把"网络失败"和"业务失败"分开。前者是 `fetch` reject（`status: 0`），后者是 `res.ok === false`。分开之后 UI 才能给出不同出路。

### 2. `api/tasks.ts`：领域接口

```ts
import { request } from "./client";

export type TaskStatus = "todo" | "doing" | "done";
export type TaskPriority = "low" | "mid" | "high";

export interface Task {
	id: string;
	title: string;
	status: TaskStatus;
	priority: TaskPriority;
	assignee: string;
	desc: string;
	createdAt: string;
}

export interface TaskQuery {
	page: number;
	limit: number;
	status: TaskStatus | "all";
	keyword: string;
}

export interface TaskPage {
	items: Task[];
	hasNext: boolean;
}

export async function listTasks(q: TaskQuery): Promise<TaskPage> {
	const params = new URLSearchParams({
		_page: String(q.page),
		_limit: String(q.limit),
	});
	if (q.status !== "all") params.set("status", q.status);
	if (q.keyword.trim()) params.set("q", q.keyword.trim());

	const items = await request<Task[]>(`/tasks?${params.toString()}`);
	// json-server 0.17 的 total 在响应头里，浏览器读不到（CORS 未暴露），
	// 这里用"本页是否取满"判断有没有下一页。真实后端请返回 total。
	return { items, hasNext: items.length === q.limit };
}

export const getTask = (id: string) => request<Task>(`/tasks/${id}`);

export type TaskInput = Pick<Task, "title" | "status" | "priority" | "assignee" | "desc">;

export const createTask = (input: TaskInput) =>
	request<Task>("/tasks", {
		method: "POST",
		body: JSON.stringify({ ...input, createdAt: new Date().toISOString() }),
	});

export const updateTask = (id: string, patch: Partial<TaskInput>) =>
	request<Task>(`/tasks/${id}`, { method: "PATCH", body: JSON.stringify(patch) });

export const removeTask = (id: string) =>
	request<void>(`/tasks/${id}`, { method: "DELETE" });
```

### 3. `features/tasks/useTasks.ts`：queryKey 工厂 + 四个 hook

```ts
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import * as api from "../../api/tasks";

/** queryKey 统一在这里生成：手写字符串数组早晚会拼错，导致缓存命中不了 */
export const taskKeys = {
	all: ["tasks"] as const,
	list: (q: api.TaskQuery) => ["tasks", "list", q] as const,
	detail: (id: string) => ["tasks", "detail", id] as const,
};

export function useTaskList(q: api.TaskQuery) {
	return useQuery({
		queryKey: taskKeys.list(q),
		queryFn: () => api.listTasks(q),
		placeholderData: (prev) => prev, // 翻页时保留上一页，不闪白
		staleTime: 15_000,
	});
}

export function useTask(id: string | undefined) {
	return useQuery({
		queryKey: taskKeys.detail(id ?? ""),
		queryFn: () => api.getTask(id as string),
		enabled: Boolean(id),
	});
}

export function useCreateTask() {
	const qc = useQueryClient();
	return useMutation({
		mutationFn: api.createTask,
		onSuccess: () => {
			// 注意：不要精确匹配 ["tasks","list",某个查询对象]，
			// 用前缀 ["tasks"] 让所有列表查询一起失效
			void qc.invalidateQueries({ queryKey: taskKeys.all });
		},
	});
}

export function useUpdateTask(id: string) {
	const qc = useQueryClient();
	return useMutation({
		mutationFn: (patch: Partial<api.TaskInput>) => api.updateTask(id, patch),
		// 乐观更新：先改缓存，失败再回滚
		onMutate: async (patch) => {
			await qc.cancelQueries({ queryKey: taskKeys.detail(id) });
			const previous = qc.getQueryData<api.Task>(taskKeys.detail(id));
			if (previous) {
				qc.setQueryData<api.Task>(taskKeys.detail(id), { ...previous, ...patch });
			}
			return { previous };
		},
		onError: (_err, _patch, ctx) => {
			if (ctx?.previous) qc.setQueryData(taskKeys.detail(id), ctx.previous);
		},
		onSettled: () => {
			void qc.invalidateQueries({ queryKey: taskKeys.all });
		},
	});
}

export function useDeleteTask() {
	const qc = useQueryClient();
	return useMutation({
		mutationFn: api.removeTask,
		onSuccess: () => {
			void qc.invalidateQueries({ queryKey: taskKeys.all });
		},
	});
}
```

### 7. `features/tasks/TaskListPage.tsx`：URL 即状态

```tsx
import { Link, useSearchParams } from "react-router-dom";
import type { TaskStatus } from "../../api/tasks";
import { StatusBadge } from "../../components/StatusBadge";
import { useTaskList } from "./useTasks";

const PAGE_SIZE = 5;

export default function TaskListPage() {
	const [searchParams, setSearchParams] = useSearchParams();

	// URL 是唯一真相：刷新、分享链接、浏览器后退都不会丢筛选
	const page = Math.max(1, Number(searchParams.get("page") ?? "1") || 1);
	const status = (searchParams.get("status") ?? "all") as TaskStatus | "all";
	const keyword = searchParams.get("q") ?? "";

	const { data, isPending, isError, error, refetch, isFetching } = useTaskList({
		page,
		limit: PAGE_SIZE,
		status,
		keyword,
	});

	const patchParams = (patch: Record<string, string | undefined>) => {
		const next = new URLSearchParams(searchParams);
		for (const [key, value] of Object.entries(patch)) {
			if (!value) next.delete(key);
			else next.set(key, value);
		}
		// replace: true —— 连续的输入/翻页不该塞满历史记录
		setSearchParams(next, { replace: true });
	};

	return (
		<section>
			<div className="toolbar">
				<input
					className="search"
					placeholder="搜索标题…"
					defaultValue={keyword}
					onChange={(e) => patchParams({ q: e.target.value, page: undefined })}
				/>
				<select
					value={status}
					onChange={(e) => patchParams({ status: e.target.value, page: undefined })}
				>
					<option value="all">全部状态</option>
					<option value="todo">待办</option>
					<option value="doing">进行中</option>
					<option value="done">已完成</option>
				</select>
				<Link className="btn primary" to="/tasks/new">
					新建任务
				</Link>
			</div>

			{isPending ? (
				<p className="hint">加载中…</p>
			) : isError ? (
				<div className="error" role="alert">
					<p>{error.message}</p>
					<button type="button" onClick={() => refetch()}>
						重试
					</button>
				</div>
			) : data.items.length === 0 ? (
				<p className="hint">没有符合条件的任务。换个关键词，或清空筛选。</p>
			) : (
				<ul className="list">
					{data.items.map((task) => (
						<li key={task.id}>
							<Link to={`/tasks/${task.id}`} className="row">
								<span className="title">{task.title}</span>
								<StatusBadge status={task.status} />
								<span className="assignee">{task.assignee}</span>
							</Link>
						</li>
					))}
				</ul>
			)}

			<div className="pager">
				<button type="button" disabled={page <= 1} onClick={() => patchParams({ page: String(page - 1) })}>
					上一页
				</button>
				<span>
					第 {page} 页{isFetching ? "（刷新中…）" : ""}
				</span>
				<button
					type="button"
					disabled={!data?.hasNext}
					onClick={() => patchParams({ page: String(page + 1) })}
				>
					下一页
				</button>
			</div>
		</section>
	);
}
```

### ✅ 阶段 1 验收清单

- [ ] 打开 `/tasks` 显示 5 条；点「下一页」URL 变成 `?page=2`，**刷新后仍停在第 2 页**。
- [ ] 选「进行中」→ URL 出现 `status=doing`，列表只剩 2 条；**浏览器后退**能回到"全部"。
- [ ] 搜索框输入"删" → URL 出现 `q=删`；清空后回到全量。
- [ ] 复制当前 URL 到新标签页 → 筛选与页码完全一致（这就是"URL 即状态"）。
- [ ] 关掉 json-server 再刷新 → 出现"网络异常…"和**重试**按钮；重启后端后点重试能恢复。
- [ ] 搜索一个不存在的词 → 出现引导式空态，而不是空白页。
- [ ] DevTools Network：翻页时**不会整页闪白**（`placeholderData` 生效），只有"（刷新中…）"提示。
- [ ] 双击"下一页"快速翻 → 不会出现页码和列表错位（URL 是唯一来源）。

## 阶段 2：CRUD + 表单 + 乐观更新

**目标**：能新建、编辑、删除；表单有字段级校验和焦点管理；状态切换是乐观更新且能回滚。

### 1. `useTaskForm.ts`：受控表单 + 校验 + 焦点

```ts
import { useState } from "react";
import type { TaskInput, TaskPriority, TaskStatus } from "../../api/tasks";

export interface TaskFormValues {
	title: string;
	status: TaskStatus;
	priority: TaskPriority;
	assignee: string;
	desc: string;
}

export type FieldErrors = Partial<Record<keyof TaskFormValues, string>>;

export const EMPTY_FORM: TaskFormValues = {
	title: "",
	status: "todo",
	priority: "mid",
	assignee: "",
	desc: "",
};

/** 纯函数：方便单测，也方便复用（提交前和失焦时都可以调） */
export function validate(values: TaskFormValues): FieldErrors {
	const errors: FieldErrors = {};
	const title = values.title.trim();
	if (!title) errors.title = "标题不能为空";
	else if (title.length < 4) errors.title = "标题至少 4 个字";
	else if (title.length > 60) errors.title = "标题不要超过 60 个字";
	if (!values.assignee.trim()) errors.assignee = "请填写负责人";
	if (values.desc.length > 500) errors.desc = "描述不要超过 500 字";
	return errors;
}

export function useTaskForm(
	initial: TaskFormValues,
	onSubmit: (values: TaskFormValues) => Promise<void>,
) {
	const [values, setValues] = useState<TaskFormValues>(initial);
	const [errors, setErrors] = useState<FieldErrors>({});
	const [submitting, setSubmitting] = useState(false);
	const [formError, setFormError] = useState<string | null>(null);

	const setField = <K extends keyof TaskFormValues>(key: K, value: TaskFormValues[K]) => {
		setValues((prev) => ({ ...prev, [key]: value }));
		// 边输边清掉这个字段的旧错误，避免"改好了红字还在"
		setErrors((prev) => ({ ...prev, [key]: undefined }));
		setFormError(null);
	};

	const handleSubmit = async (event: React.FormEvent<HTMLFormElement>) => {
		event.preventDefault();
		const found = validate(values);
		setErrors(found);

		const firstInvalid = (Object.keys(found) as (keyof TaskFormValues)[])[0];
		if (firstInvalid) {
			// 把焦点送到第一个出错的字段：键盘/读屏用户不用自己找
			document.getElementById(`field-${firstInvalid}`)?.focus();
			return;
		}

		setSubmitting(true);
		try {
			await onSubmit(values);
		} catch (err) {
			setFormError(err instanceof Error ? err.message : "提交失败，请重试");
		} finally {
			setSubmitting(false);
		}
	};

	return { values, errors, submitting, formError, setField, handleSubmit };
}

export function toFormValues(task: TaskInput): TaskFormValues {
	return {
		title: task.title,
		status: task.status,
		priority: task.priority,
		assignee: task.assignee,
		desc: task.desc,
	};
}
```

### 2. `TaskForm.tsx`：新建 / 编辑共用一个表单

### 3. `TaskFormPage.tsx`：新建 / 编辑复用

```tsx
import { useNavigate, useParams } from "react-router-dom";
import { ErrorBox } from "../../components/ErrorBox";
import { useToast } from "../../components/Toast";
import { useCreateTask, useTask, useUpdateTask } from "./useTasks";
import { TaskForm } from "./TaskForm";
import { EMPTY_FORM, toFormValues, type TaskFormValues } from "./useTaskForm";

export default function TaskFormPage() {
	const { id } = useParams();
	const isEdit = Boolean(id);
	const navigate = useNavigate();
	const toast = useToast();

	const { data: task, isPending, isError, error, refetch } = useTask(id);
	const createTask = useCreateTask();
	const updateTask = useUpdateTask(id ?? "");

	if (isEdit) {
		if (isPending) return <p className="hint">加载中…</p>;
		if (isError) return <ErrorBox message={error.message} onRetry={() => refetch()} />;
		if (!task) return <p className="hint">任务不存在</p>;
	}

	const initial: TaskFormValues = task ? toFormValues(task) : EMPTY_FORM;
	const submitting = createTask.isPending || updateTask.isPending;

	const handleSubmit = async (values: TaskFormValues) => {
		if (isEdit && id) {
			await updateTask.mutateAsync(values);
			toast("已保存");
			navigate(`/tasks/${id}`);
			return;
		}
		const created = await createTask.mutateAsync(values);
		toast("已创建");
		navigate(`/tasks/${created.id}`, { replace: true });
	};

	return (
		<section>
			<h2>{isEdit ? "编辑任务" : "新建任务"}</h2>
			<TaskForm
				key={task?.id ?? "new"}
				initial={initial}
				submitting={submitting}
				submitText={isEdit ? "保存修改" : "创建"}
				onSubmit={handleSubmit}
				onCancel={() => navigate(-1)}
			/>
		</section>
	);
}
```

					<span className="confirm">

							取消
						</button>
					</span>

### 5. `components/Toast.tsx`：Context 的正当用途

```tsx
import { createContext, useCallback, useContext, useEffect, useState } from "react";

const ToastContext = createContext<(message: string) => void>(() => {});

export function ToastProvider({ children }: { children: React.ReactNode }) {
	const [message, setMessage] = useState<string | null>(null);

	const show = useCallback((text: string) => setMessage(text), []);

	useEffect(() => {
		if (!message) return;
		const timer = setTimeout(() => setMessage(null), 2200);
		return () => clearTimeout(timer);
	}, [message]);

	return (
		<ToastContext.Provider value={show}>
			{children}
			{message && (
				<div className="toast" role="status" aria-live="polite">
					{message}
				</div>
			)}
		</ToastContext.Provider>
	);
}

export function useToast() {
	return useContext(ToastContext);
}
```

> 这就是 Context 的合适场景：**低频、全局、只有一个值**（一个函数）。别把列表数据塞 Context——那会让所有消费者一起重渲染（见[状态管理那篇](/blog/posts/react-roadmap-08-state-management/)）。
>
> 用之前记得在 `main.tsx` 里包一层 `ToastProvider`。

## 阶段 3：体验与工程化（把它变成"能给别人用"）

**目标**：出错不白屏、首屏不背全量代码、键盘可用、搜索不抖。

### 1. 路由级兜底：`components/RouteError.tsx`

```tsx
import { Link, useRouteError } from "react-router-dom";

export function RouteError() {
	const error = useRouteError();
	const message = error instanceof Error ? error.message : "页面出错了";

	return (
		<section className="error" role="alert">
			<h2>这个页面崩了</h2>
			<p>{message}</p>
			<Link className="btn" to="/tasks">
				回到任务列表
			</Link>
		</section>
	);
}
```

> `errorElement` 接住的是**渲染期/loader 期**抛出的错误（包括 `undefined.map` 这种低级错）。它接不住事件回调里的错误——那类错误要自己 try/catch 或上 Sentry。

### 2. 路由级代码分割（只给编辑页分包）

```tsx
import { lazy, Suspense } from "react";

const TaskFormPage = lazy(() => import("./features/tasks/TaskFormPage"));

// 路由表里：
{ path: "tasks/new", element: <Suspense fallback={<p className="hint">加载中…</p>}><TaskFormPage /></Suspense> }
```

**为什么只拆表单页**：它包含最多的表单/校验代码，但用户 80% 的时间在列表页。把最大、最少用的那块先拆出去，收益最高。**别一上来全站 lazy**——过度分割会让每次跳转都多一次请求。

### 3. 搜索防抖：`useDebouncedValue`

```ts
import { useEffect, useState } from "react";

export function useDebouncedValue<T>(value: T, delay = 300): T {
	const [debounced, setDebounced] = useState(value);
	useEffect(() => {
		const timer = setTimeout(() => setDebounced(value), delay);
		return () => clearTimeout(timer); // 每次输入都会取消上一个 timer
	}, [value, delay]);
	return debounced;
}
```

在列表页把 `keyword` 换成"输入先落本地 state，防抖后再写 URL"：每敲一个字不发请求，`?q=` 也不会被中间态污染。

### 4. 键盘可用性三件事

1. 所有可点元素用 `button` / `a`，不要给 `div` 加 `onClick`。
2. 焦点环别用 `outline: none` 干掉；若要自定义，用 `:focus-visible` 只给键盘用户画。
3. 操作后焦点要有落点：删除后回列表，把焦点移到列表标题或第一条。

```css
:focus-visible {
	outline: 2px solid #2563eb;
	outline-offset: 2px;
	border-radius: 6px;
}
```

### 5. 性能：哪些地方故意不加 memo

- 列表行 `TaskRow` 没加 `React.memo`：父组件每次翻页都**整体换数据**，memo 只会增加比较成本。
- `useTaskList` 的 `queryFn` 是箭头函数、每次渲染都新建：TanStack Query 只依赖 `queryKey`，不需要 `useCallback`。
- **什么时候才加**：DevTools Profiler 里看到某个子组件在父组件无关更新时反复重渲染，且它渲染成本高（长列表、图表）。先度量，再优化——见[性能那篇](/blog/posts/react-roadmap-09-performance/)。

## 常见坑（这个项目里我踩过的）

1. **queryKey 手写字符串**：`["tasks", {page,status}]` 和 `["tasks", {status,page}]` 是两个缓存。用 `taskKeys` 工厂函数统一生成。
2. **`invalidateQueries` 只传精确 key**：想失效所有列表查询，用前缀 `["tasks"]`，不要传整个查询对象。
3. **乐观更新忘了回滚**：`onMutate` 里存了 `previous`，`onError` 一定要 `setQueryData` 回去，否则界面在骗人。
4. **`useEffect` 里请求数据**：这是最容易把代码写乱的起点。服务端状态交给 TanStack Query，`useEffect` 只留给"同步外部系统"。
5. **编辑页先渲染空表单再填值**：会出现"用户刚输入就被覆盖"。用 `key={task.id}` 挂载，或加载完再渲染表单。
6. **受控组件 `value={undefined}`**：从 `undefined` 变成字符串会把组件从非受控切成受控，React 直接警告。初始值一律给空字符串。
7. **json-server 的 `id` 是字符串**：别用 `Number(id)` 比较，`t-01` 转数字是 `NaN`。
8. **`disabled` 当"防止重复提交"**：点了之后到状态更新之间仍有间隙，真正稳的是 `mutation.isPending` 判断 + 后端幂等。

1. 用这套结构重写一遍**你自己的真实小需求**（比再做一遍 demo 有用十倍）。
2. 加测试：`api/tasks.ts` 是纯函数层，最适合先写；组件层用 Testing Library 测"提交空表单→出现红字"。
3. 换后端：把 json-server 换成 [Node + NestJS 那一套](/blog/posts/node-roadmap-03-http-server-express-koa/)，体会"前端只依赖契约"。
4. 迁到 Next.js：同样的页面用 Server Components + Server Actions 写一遍，对照 [Next.js 全栈路线](/blog/posts/nextjs-roadmap-05-server-actions-forms/)。

> 如果你把 3 个阶段的清单都勾完了，恭喜——你已经在"能独立编程"这一档了。剩下的不是学更多 API，而是**多做几个真实需求**。
