## 先定「做到什么算过」

不是"看完 16 篇"，而是能做出这五个动作。都做到，就是能独立用 Next.js 交付一个产品：

1. 拿到一个页面，**能说出它是静态、动态还是流式**，以及为什么——而不是构建完看日志才发现全是 `ƒ`。
2. 能把一个功能拆成"服务端取数 / 客户端交互 / 写操作"三段，并**说清每一段在哪跑**。
3. 改了数据之后，能指出**哪几个缓存需要失效**，而不是等它自己过期或者重启服务。
4. 线上出问题（500、白屏、数据不更新）时，能**从日志/trace 定位到具体一层**，而不是靠猜。
5. 能部署一个 standalone 产物，**反代、流式、静态资源、健康检查**都齐，且能回滚。

第 3 条是 Next.js 与普通 React 应用最大的分水岭：**框架不替你决定缓存，你决定。**

## 三条贯穿全系列的主线

**一、边界比 API 重要。** `'use client'` 是一条**模块边界**：从这一行开始，导入图里的所有东西都会进入客户端 bundle。放错位置，要么把数据库客户端打进浏览器，要么让整棵树失去服务端渲染能力（03 专讲）。

**二、缓存是显式的，失效是设计出来的。** Next.js 15 起 `fetch` 默认不缓存，Route Handler 默认不缓存；新版本推 `use cache`、`cacheLife`、`cacheTag` 这套显式模型。框架不再替你做"聪明的决定"，你必须自己回答：这份数据能旧多久？谁负责让它失效？（04）

**三、服务端不是"另一个前端"。** 在 Server Component 里查数据库很爽，但连接池、事务、超时、鉴权、审计一个都跑不掉（07、08）——这些才是全栈与前端的真正分水岭。

## 每篇怎么用（这次的重点变化）

这一版之前，16 篇只有正文没有练习。现在**每篇都补了两块**：

- **「练习（带自检）」5 道**：前 2 道是"读懂"（解释现象 + 改错），后 3 道是"做出"（写代码、量数据、故意搞坏）。**每题末尾给了自检标准**——做到什么算对，不用猜。
- **「验收清单」**：6–8 条可勾选项，全部是**能在浏览器/终端里当场验的**（构建日志里出现什么、`curl` 返回什么、DevTools 里看到什么）。

用法建议：**先把正文读完，合上文章做练习，卡住再翻回去。** 直接看答案的收益接近于零——这套路线里所有"坑"都是动手才会长记性的。

## 我带团队时最常见的五个翻车点

- **根布局写了 `'use client'`**：整站退化成客户端应用，SSR 只剩个空壳。
- **在深层组件里读 `cookies()`**：整条路由从静态变动态，构建日志里全是 `ƒ`，CDN 缓存全失效。
- **只做了写入、没做失效**：后台改了数据，前台半小时后还是旧的，最后靠重启服务"解决"。
- **把 Server Action 当内部函数**：它是可被直接调用的 HTTP 端点，没做鉴权就等于把写接口裸奔在公网。
- **本地 `next start` 正常，上线 502**：standalone 产物没带 `public/`、`.next/static`，或者反代没配流式响应。
