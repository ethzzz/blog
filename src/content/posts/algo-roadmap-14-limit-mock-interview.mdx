前 13 篇解决"知道怎么做"，这一篇解决"**在压力下做得出来**"。这两件事的差距，比大多数人想的大得多。

我自己面试别人的经验：候选人私下刷了 300 题，现场 25 分钟写不出一道中等题的情况非常常见。不是不会，是**没有在"有人看着、有时间限制、要边说边写"的条件下练过**。

## 为什么平时刷题不算练过

| 条件 | 平时刷题 | 真实面试 |
|---|---|---|
| 时间 | 想多久都行 | 25–30 分钟硬上限 |
| 提示 | 可以瞄题解 | 只有面试官的口头提示 |
| 表达 | 心里想就行 | 要边写边讲，讲不清等于不会 |
| 环境 | 自己的编辑器、自动补全 | 共享屏幕、纯文本、可能没高亮 |
| 状态 | 心情平静 | 紧张、被打断、被追问 |

所以模拟的目的不是"再做题",而是**练习这五个条件下的稳定输出**。

## 60 分钟标准流程

一套三题，严格计时。建议用手机计时器，**不暂停**。

| 阶段 | 时长 | 要做的事 |
|---|---|---|
| 读题澄清 | 每题 2 分钟 | 复述输入输出、问边界（空？负数？重复？规模多大？） |
| 口述思路 | 每题 2 分钟 | 一句话说套路 + 为什么 + 复杂度预估，再动手 |
| 编码 | 每题 12–15 分钟 | 先写骨架再补细节，不留 TODO |
| 自测 | 每题 3 分钟 | 手动跑 3 个用例：正常 / 最小 / 特殊 |
| 收尾 | 最后 3 分钟 | 说出复杂度 + 一句"如果要优化我会怎么做" |

**关键纪律：25 分钟没 AC 就停，记下来进错题卡。** 模拟时死磕一道题，等于放弃了另外两道的练习价值。

## 三套题单

### A 组 · 算法基础（最常考的组合）

| 题 | 套路 | 目标复杂度 |
|---|---|---|
| 1. 两数之和 | 哈希 | O(n) 时间 / O(n) 空间 |
| 46. 全排列 | 回溯 | O(n·n!) |
| 200. 岛屿数量 | DFS/BFS 网格遍历 | O(m·n) |

这一组考的是"三个不同范式各来一道"——面试最常见的排布方式。

### B 组 · 手写题（前端专属）

| 题 | 要求 |
|---|---|
| 1. `debounce(fn, wait)` | 带 `cancel` 与 `flush`，`this` 与参数透传正确 |
| 2. `Promise.all` | 保序、任一 reject 立即 reject、空数组立即 resolve |
| 3. `deepClone` | 处理循环引用、Date/RegExp/Map/Set，函数按引用拷贝 |

**判分标准是"脱稿、从空文件开始、15 分钟三题"。** 一边看提示一边写不算。

### C 组 · 综合（区分度最高）

| 题 | 考点 |
|---|---|
| 300. 最长递增子序列 | DP 状态定义；能说出 O(n log n) 的贪心+二分版本 |
| 146. LRU 缓存 | 设计题：哈希 + 双向链表，`get`/`put` 都要 O(1) |
| 手写并发池 `asyncPool(limit, tasks)` | 控制并发、保序返回、异常传播 |

C 组的共同点是"代码量大、边界多"。它测的不是套路记忆，是**工程化的编码习惯**：会不会先定接口、会不会写辅助函数、会不会边写边说。

## 六维评分表

每题打完分（0–3 分），三题共 54 分；按 18 分制折算更直观（取平均）：

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 读题澄清 | 直接写 | 复述了但没问边界 | 问了 1–2 个关键边界 | 主动确认规模/边界/返回约定 |
| 思路口述 | 沉默开写 | 只说"我用双指针" | 说了套路 + 为什么 | 说了套路 + 反例 + 复杂度预估 |
| 编码正确 | 跑不通 | 主用例过、边界挂 | 全过，有小瑕疵 | 一次写对，命名清晰 |
| 自测习惯 | 不测 | 只跑给的样例 | 自己补了 2 个用例 | 主动构造最小/极端用例 |
| 复杂度 | 说不出 | 说错 | 说对时间 | 时间空间都对，且能说优化方向 |
| 沟通救场 | 卡住沉默 | 卡很久才求助 | 主动要提示 | 主动降级 + 说明取舍 |

**判定**：平均 ≥ 2.3（约 14/18）算"能过"；≥ 2.7 算"稳"；< 1.8 说明还没到面试水平，回去补该篇。

注意：**沟通救场是独立维度**——很多人技术上 2.5 分，这一项 1 分，整体就被拖下来了。

### 一个能算分的脚本

填完表别凭感觉，用 20 行脚本算出均分和短板：

```js
const DIMS = ['读题澄清', '思路口述', '编码正确', '自测习惯', '复杂度', '沟通救场'];

/**
 * rows：3 道题 × 6 个维度，每格 0–3
 */
function score(rows) {
  const total = rows.flat().reduce((a, b) => a + b, 0);
  const avg = total / rows.length / DIMS.length;
  const verdict =
    avg >= 2.7 ? '稳' :
    avg >= 2.3 ? '能过' :
    avg >= 1.8 ? '边缘' : '回炉';

  // 找出最低的两个维度
  const weak = DIMS
    .map((dim, i) => ({ dim, s: rows.reduce((a, r) => a + r[i], 0) / rows.length }))
    .sort((a, b) => a.s - b.s)
    .slice(0, 2)
    .map((x) => `${x.dim}(${x.s.toFixed(1)})`);

  return { 总分: `${total}/54`, 均分: +avg.toFixed(2), 判定: verdict, 短板: weak.join('、') };
}

// 例：三题、六维
console.table(
  score([
    [3, 2, 3, 2, 3, 2],
    [2, 2, 2, 2, 2, 1],
    [2, 1, 2, 1, 2, 1],
  ]),
);
```

输出里的「短板」就是下一周的训练重点——**别平均用力，补最低那两项涨分最快**。

## 卡住时的四个救场动作

按顺序用，别硬撑：

1. **复述问题**："我理解是……对吗？"——八成是你理解错了，而不是不会。
2. **降级到暴力解**："我先写 O(n²) 的，再优化。"——先有分，再谈优。
3. **要方向性提示**："我可以往双指针方向想吗？"——要"方向"不算扣分，要"答案"才扣。
4. **写出骨架 + 注释**：即使写不完，结构清晰也能拿到部分评价。

**最糟的动作是沉默。** 面试官无法区分"在想"和"卡死"，通常按后者打分。

## 复盘模板（24 小时内做完）

模拟结束后立刻填，超过 24 小时记忆就失真了。

**第一步：错误归因（只能选一个主因）**

| 类型 | 典型表现 | 对应补法 |
|---|---|---|
| 读题错 | 看漏"不能重复使用" | 练"复述 + 问边界"，不急着写 |
| 套路错 | 该用哈希却去排序 | 回该篇重记模板 |
| 边界错 | 空数组/单元素挂 | 每道题固定测三类用例 |
| 语法/API 错 | `Map` 和对象混用、`splice` 参数错 | 补语言细节，不是算法问题 |
| 表达错 | 代码对但讲不清 | 练"三句话口述"，录音回听 |

**第二步：三条行动**（具体到题号和动作，不写"多练习"）：

```text
1. 重写 200（今天 22:00 前，不看题解）
2. 46.全排列：把"选择-递归-撤销"模板默写两遍
3. 明天做 3 道网格 DFS，限时 15 分钟/题
```

**第三步：24 小时后重写错题**。同一天重写是"短期记忆"，隔一天才是真掌握。

## 三个月怎么排

| 时间 | 频率 | 重点 |
|---|---|---|
| 第 1 个月 | 每周 1 次 A 组 | 把"限时"变习惯，先不追分 |
| 第 2 个月 | 每周 1 次 A + 1 次 B | 手写题脱稿；开始看评分表找短板 |
| 第 3 个月 | 每周 2 次（A/B/C 轮换）+ 一次全真（找人当面试官） | 稳定在 2.3 分以上 |

**最后两周一定要找真人模拟一次**（朋友、前同事、付费mock 都行）。有真人在场和没人在场，紧张程度完全不是一个量级。

## 常见坑

| 现象 | 根因 | 解法 |
|---|---|---|
| 平时会做，模拟就崩 | 没在压力下练过 | 每周固定一次限时，逐步加"被看着" |
| 三题只做完一题 | 时间分配失控 | 严格 25 分钟切题，超时就停 |
| 代码对但评价低 | 全程不说话 | 边写边讲"我要做什么、为什么" |
| 复杂度答不上 | 平时不标 | 每题写完强制标注，形成条件反射 |
| 边界总挂 | 没有固定用例清单 | 固定测：空、单元素、全相同、极值 |
| 复盘写完就忘 | 没做 24h 重写 | 日历上排一个提醒 |

## 练习

1. **现在做一次 A 组**，严格 60 分钟，用评分表给自己打分。把分数记下来——这是你的基线。
2. **手写组（B 组）**：关掉所有参考，从空文件默写三题，限时 15 分钟。做不到就说明 10–12 篇需要重练。
3. **给自己做一份"边界用例清单"**（空、单元素、全相同、负数、极大值、重复），以后每道题固定过一遍。
4. **录一次口述**：选一道做过的题，用手机录音讲 90 秒思路。回听时你会发现"讲不清"的地方，正是没真懂的地方。
5. **找一个人当面试官**，做一次 C 组。让对方只在你卡住 3 分钟后才给提示。

**自检标准**：第 1 题能给出一个具体分数（比如 12/18）；第 4 题的录音里，你能不重复、不"嗯…"地讲完 90 秒。

## 验收清单

- [ ] 做过至少一次完整 60 分钟模拟，且有分数记录（不是"感觉还行"）
- [ ] 有一套自己的边界用例清单，每题都过一遍
- [ ] 能在 25 分钟内 AC 一道中等题（限时，含自测）
- [ ] 写完能立刻说出时间与空间复杂度，并给一句优化方向
- [ ] 90 秒口述一道题，不卡壳、不重复
- [ ] 手写组三题（debounce / Promise.all / deepClone）脱稿默写正确
- [ ] 有一张错题卡（题号 + 卡点 + 提醒），每周复盘一次
- [ ] 做过至少一次真人模拟，知道自己在有观众时的真实水平
- [ ] 卡住时会用四种救场动作，而不是沉默

## 小结

限时模拟是这条路线的"考试"。前 13 篇给你套路，这一篇检验套路能不能在压力下取出来。**没有模拟的刷题，只是"见过"，不是"会"**。

把它排进日历：每周一次，60 分钟，写分数，24 小时内复盘。三个月后你会明显感觉到——面试时手不抖了。
