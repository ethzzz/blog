## 2. 分档与动作

### A 档：重写正文（browser / js / react，39 篇）

按三层重组，每篇 3,000+ 字，统一骨架：

1. 机制/原理（不是"是什么"，而是"为什么这样"）
2. 可运行代码或可抄的配置
3. 常见坑表（**现象 / 根因 / 解法** 三列）
4. 勾选式验收清单（6–7 条，都可当场验）
5. 练习（每题带"自检"标准）

### B 档：补结构（algo / nextjs / node）

正文不动，做三件事：

- 总览加三层地图 + 四类起点读法 + 每层验收标准；
- 补**练习与解答**（algo：限时模拟 + solutions；nextjs：每篇 2–3 题）；
- 补"能力清单 + 自测 10 题"作为毕业标准。

### C 档：只补阶段层（docker / python / higress / java / ruoyi）

正文已厚，只需：

- 总览加三层地图（现有篇目归类）；
- 每层给验收标准；
- java 补 1 篇独立毕业项目篇；ruoyi 补阶段划分说明。

## 6. 深度标准 v2（2026-10-29 起）

第一轮把「结构」补齐了，但多数篇目仍停在「结论 + 一句解释 + 片段代码」。第二轮目标改成**每个知识点能照着跑一遍**，判据从"字数"改为"可运行示例数"。

### 6.1 硬指标

| 指标 | v1（2026-10-26） | v2（本轮） |
| :-- | :-- | :-- |
| 正文（去空白） | ≥ 3,000 字 | **≥ 7,000 字** |
| 代码块 | 不限 | **≥ 12 个**，代码型篇目 ≥ 15 个 |
| 完整可跑 demo | 无要求 | **每篇至少 1 个**（HTML 能直接打开跑，或带 import 的完整 ts 文件） |
| 练习 | 有题 | **每题带"自检"标准**（可判定的现象或数字） |

### 6.2 单个知识点的写法（四段式）

1. **结论**：一句话说清"是什么/该怎么做"。
2. **机制**：为什么这样——内部过程、线程归属、触发条件、代价来源。这一节必须能回答"追问两个为什么"。
3. **示例**：可直接粘贴运行的代码，带输入输出；关键行有注释解释"为什么这么写"。
4. **坑与边界**：至少一条"换个场景就失效"的说明，或进篇末坑表。
